AWS X-Ray

En una frase: Traza cada petición entre servicios y dibuja un mapa con latencias y errores
Categoría: Herramientas para desarrolladores (Developer Tools)
Certificaciones: CLF-C02 SAA-C03 DVA-C02 SAP-C02
Documentación oficial: Documentación de AWS X-Ray ↗
Aviso: Los SDK (Software Development Kit: bibliotecas para programar contra AWS) y el demonio de X-Ray están en modo de mantenimiento desde el 25/02/2026 (solo reciben correcciones de seguridad). El servicio X-Ray sigue plenamente soportado, pero la instrumentación recomendada es OpenTelemetry (por ejemplo con AWS Distro for OpenTelemetry), y las novedades llegan a CloudWatch Application Signals y Transaction Search. Los exámenes siguen preguntando por X-Ray, su demonio y sus conceptos.

Qué es

AWS X-Ray es un servicio de trazado distribuido. Registra el recorrido de cada petición a través de tu aplicación (API Gateway, Lambda, contenedores, bases de datos, llamadas HTTP (HyperText Transfer Protocol: protocolo de la web)…) y construye un mapa de servicios con latencias, errores y fallos de cada tramo. Sirve para encontrar dónde se pierde el tiempo o falla una petición en una arquitectura de microservicios.

Conceptos clave

  • Traza: el recorrido completo de una petición, identificado por un ID que se propaga en una cabecera.
  • Segmentos y subsegmentos: el trabajo de cada servicio y, dentro de él, de cada llamada (por ejemplo, a DynamoDB).
  • Anotaciones: pares clave-valor indexados, para filtrar trazas (por ejemplo, por cliente). Metadatos: información adicional no indexada.
  • Muestreo: reglas que deciden qué fracción de peticiones se trazan, para controlar el coste.
  • Demonio de X-Ray: recibe los segmentos por UDP (puerto 2000) y los envía al servicio; en Lambda y Elastic Beanstalk ya está integrado, en ECS (Elastic Container Service) se ejecuta como contenedor auxiliar.
  • Trazado activo en Lambda y trazado en etapas de API Gateway, con un solo ajuste.
  • Grupos e Insights: filtros guardados y detección automática de anomalías.
  • OpenTelemetry: la vía recomendada para instrumentar; X-Ray acepta trazas en ese formato.

Casos de uso típicos

  • Encontrar qué microservicio añade latencia a una petición.
  • Ver qué llamadas a servicios externos fallan y con qué frecuencia.
  • Analizar el rendimiento de aplicaciones sin servidor con Lambda y API Gateway.

Cuándo NO usarlo

  • Para métricas y alarmas de infraestructura: CloudWatch.
  • Para guardar y consultar registros de la aplicación: CloudWatch Logs.
  • Para auditar quién llamó a la API (Application Programming Interface: interfaz para que los programas se comuniquen) de AWS: CloudTrail.

Modelo de precios

Se paga por trazas registradas y por trazas recuperadas o analizadas, con una capa gratuita mensual. El muestreo reduce el coste. Con Transaction Search de CloudWatch, los tramos se cobran como ingesta de registros.

Seguridad y alta disponibilidad

  • Permisos de IAM (Identity and Access Management) para enviar trazas (por ejemplo, en el rol de ejecución de Lambda o el rol de la tarea).
  • Cifrado de los datos de trazas con KMS (Key Management Service).
  • No incluyas datos personales en anotaciones ni metadatos.
  • Las trazas se conservan 30 días.

Trampas de examen

  • "Encontrar el cuello de botella entre microservicios": X-Ray.
  • "Filtrar trazas por un valor propio": anotaciones (los metadatos no se indexan).
  • "Las trazas no llegan desde EC2 (Elastic Compute Cloud) o ECS": falta el demonio (o el colector) o el permiso de IAM.
  • "Trazar Lambda": activar el trazado activo.
  • "Reducir el coste del trazado": reglas de muestreo.
  • "Instrumentar hoy una aplicación nueva": OpenTelemetry (ADOT), enviando a X-Ray.
