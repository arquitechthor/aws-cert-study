AWS AppConfig

En una frase: Publica cambios de configuración y feature flags de forma gradual y con marcha atrás
Categoría: Administración y gobernanza (Management and Governance)
Certificaciones: DVA-C02
Documentación oficial: Documentación de AWS AppConfig ↗

Qué es

AWS AppConfig separa la configuración de una aplicación de su código. Permite cambiar en caliente parámetros de funcionamiento y feature flags (interruptores de funcionalidades) sin compilar ni desplegar de nuevo. Trata cada cambio de configuración como un despliegue: lo valida, lo reparte poco a poco y lo revierte solo si salta una alarma. Es una capacidad de AWS Systems Manager con consola y API (Application Programming Interface: interfaz para que los programas se comuniquen) propias.

Conceptos clave

  • Aplicación: el contenedor lógico (un microservicio, una app móvil).
  • Entorno: un grupo de destinos, como beta o producción. Cada entorno puede tener asociadas alarmas de CloudWatch que se vigilan durante los despliegues.
  • Perfil de configuración: indica dónde está el dato y de qué tipo es:
    • Feature flags: interruptores con atributos y variantes, en un formato propio pensado para la consola.
    • Configuración libre: JSON (JavaScript Object Notation: formato de datos en texto), YAML (YAML Ain't Markup Language: formato de configuración legible) o texto. Puede guardarse en el almacén alojado de AppConfig (lo recomendado), en S3 (Simple Storage Service), en Parameter Store, en Secrets Manager o en un documento de Systems Manager.
  • Validadores: antes de desplegar comprueban la configuración, con un esquema JSON (sintaxis) o con una función Lambda (lógica propia). Si fallan, el despliegue no empieza.
  • Estrategia de despliegue: define a qué ritmo llega el cambio a los destinos (todo a la vez, lineal o exponencial), la duración del despliegue y el tiempo de observación (bake time) durante el que se siguen vigilando las alarmas.
  • Marcha atrás automática: si una alarma de CloudWatch del entorno salta durante el despliegue o el tiempo de observación, AppConfig vuelve a la versión anterior.
  • Cómo la lee la aplicación: con el agente de AppConfig, que consulta el servicio cada cierto intervalo, guarda la configuración en una caché local y la sirve por HTTP (HyperText Transfer Protocol: protocolo de la web) en localhost. En Lambda se añade como extensión (una capa); en ECS (Elastic Container Service) y EKS (Elastic Kubernetes Service), como contenedor auxiliar; en EC2 (Elastic Compute Cloud), como proceso. También se puede llamar a la API directamente (StartConfigurationSession y GetLatestConfiguration).

Casos de uso típicos

  • Lanzar una funcionalidad poco a poco: el código ya está desplegado y se activa con un flag, primero para una parte del tráfico.
  • Interruptor de emergencia: desactivar una función que da problemas sin desplegar.
  • Ajuste operativo: cambiar límites, tiempos de espera o niveles de log en caliente.
  • Listas de permitidos o bloqueados que cambian a menudo.

Cuándo NO usarlo

  • Para secretos (contraseñas, claves): Secrets Manager, que además los rota.
  • Para valores sueltos que casi no cambian: Parameter Store o variables de entorno.
  • Para desplegar código de forma gradual: CodeDeploy.
  • Para experimentos A/B con análisis estadístico de resultados, AppConfig solo aporta el interruptor.

Modelo de precios

Se paga por petición de configuración que hacen los destinos y por configuración recibida (cuando hay datos nuevos). El almacén alojado no tiene coste aparte; si el dato vive en S3, Parameter Store o Secrets Manager, se suma el precio de ese servicio. El agente, con su caché, reduce el número de llamadas.

Seguridad y alta disponibilidad

  • El acceso se controla con IAM (Identity and Access Management): lo normal es que la aplicación solo pueda leer su configuración y que desplegar cambios quede para otro rol.
  • Los datos del almacén alojado se cifran, también con una clave de KMS (Key Management Service) gestionada por el cliente.
  • Para la marcha atrás, AppConfig necesita un rol con permiso para consultar las alarmas de CloudWatch.
  • Si el agente no llega al servicio, sigue sirviendo la última configuración válida de su caché: un fallo de red no tumba la aplicación.

Trampas de examen

  • "Feature flags" o "activar una funcionalidad sin desplegar código": AppConfig.
  • "Cambiar la configuración de forma gradual y revertir si hay errores": estrategia de despliegue de AppConfig con alarma de CloudWatch.
  • "Evitar que una configuración mal formada llegue a producción": validadores (esquema JSON o Lambda).
  • "Reducir las llamadas y la latencia al leer la configuración desde Lambda": la extensión del agente de AppConfig, que usa caché local.
  • Secretos: Secrets Manager. Parámetros sin despliegue controlado: Parameter Store.
