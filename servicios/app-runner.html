AWS App Runner

En una frase: Lanza una web desde código o imagen de contenedor con HTTPS (HTTP Secure: HTTP cifrado con TLS) y escalado incluidos
Categoría: Computación (Compute)
Certificaciones: SAP-C02
Documentación oficial: Documentación de AWS App Runner ↗
Aviso: App Runner no admite clientes nuevos desde el 30/04/2026. Quienes ya lo usaban pueden seguir, incluso creando servicios nuevos, y AWS mantiene la seguridad y la disponibilidad, pero no añadirá funciones. Para aplicaciones nuevas AWS recomienda Amazon ECS (Elastic Container Service) Express Mode: a partir de una imagen de contenedor crea de una vez un servicio de ECS en Fargate con su balanceador, escalado y red, sin coste adicional sobre los recursos. Sigue en la guía de SAP-C02, que se puede presentar hasta el 17/11/2026.

Qué es

AWS App Runner es un servicio totalmente gestionado para poner en marcha aplicaciones web y API (Application Programming Interface: interfaz para que los programas se comuniquen) en contenedores sin conocer la infraestructura de contenedores. Le das el código fuente o una imagen, y él construye, despliega, pone un balanceador con HTTPS, escala según el tráfico y vigila la salud del servicio. No hay clústeres, instancias ni balanceadores que configurar.

Conceptos clave

  • Dos orígenes: un repositorio de código (App Runner construye la imagen con un entorno de ejecución gestionado, como Python o Node.js) o una imagen de contenedor en ECR (Elastic Container Registry).
  • Despliegue automático: opcionalmente, cada cambio en la rama del repositorio o cada imagen nueva en ECR lanza un despliegue.
  • Servicio: la unidad que se despliega. Recibe una URL (Uniform Resource Locator: dirección web) con HTTPS y admite dominios propios con certificado gestionado.
  • Escalado automático por concurrencia: se define cuántas peticiones simultáneas atiende cada instancia y un mínimo y un máximo de instancias. App Runner añade instancias al superarse la concurrencia.
  • Instancias aprovisionadas y activas: el mínimo de instancias queda siempre aprovisionado (se paga solo su memoria); cuando hay tráfico pasan a activas (se paga también la CPU (Central Processing Unit: procesador)). Así no hay arranque en frío desde cero.
  • Red: el servicio es público por defecto. Con un conector de VPC (Virtual Private Cloud) llega a recursos privados (una base de datos de RDS (Relational Database Service)), y también puede exponerse solo de forma privada dentro de una VPC.
  • Pausa: un servicio se puede pausar para dejar de pagar el cómputo.

Casos de uso típicos

  • API y aplicaciones web con peticiones HTTP (HyperText Transfer Protocol: protocolo de la web), cuando el equipo no quiere gestionar ECS ni Kubernetes.
  • Prototipos y entornos de pruebas que deben estar en línea en minutos.
  • Microservicios sencillos con despliegue continuo desde el repositorio.

Cuándo NO usarlo

  • En cuentas nuevas ya no está disponible: ECS Express Mode.
  • Si necesitas control fino de red, de tareas o de despliegues: ECS o EKS (Elastic Kubernetes Service) con Fargate.
  • Para código que responde a eventos y puede escalar a cero: Lambda.
  • Para trabajos por lotes o procesos largos sin peticiones HTTP: AWS Batch o tareas de ECS.
  • Para aplicaciones en instancias de EC2 (Elastic Compute Cloud) con acceso al sistema operativo: Elastic Beanstalk.

Modelo de precios

Se paga la memoria de las instancias aprovisionadas y, mientras atienden peticiones, también la CPU de las instancias activas. Aparte se cobran la construcción desde código (por minuto) y los despliegues automáticos (cuota mensual por aplicación).

Seguridad y alta disponibilidad

  • HTTPS con certificado gestionado en la URL del servicio y en los dominios propios.
  • El servicio usa un rol de instancia de IAM (Identity and Access Management) para llamar a otros servicios, y un rol de acceso para leer la imagen de ECR.
  • Las instancias se reparten entre varias AZ (Availability Zone: zona de disponibilidad); un mínimo de instancias más alto mejora ese reparto.
  • Los secretos y parámetros se inyectan desde Secrets Manager y Parameter Store.

Trampas de examen

  • "Desplegar una web en contenedor desde el código fuente o una imagen, con el menor esfuerzo operativo": App Runner.
  • "Sin gestionar clústeres, balanceadores ni escalado" y con tráfico HTTP: App Runner; si piden más control, ECS con Fargate.
  • "Acceder a una base de datos privada desde App Runner": conector de VPC.
  • No escala a cero por completo: mantiene instancias aprovisionadas; para escala a cero, Lambda.
