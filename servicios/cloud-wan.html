AWS Cloud WAN

En una frase: Red global gestionada que une regiones y oficinas con una política central declarativa
Categoría: Redes y entrega de contenido (Networking and Content Delivery)
Certificaciones: SAP-C03
Documentación oficial: Documentación de AWS Cloud WAN ↗

Qué es

AWS Cloud WAN (Wide Area Network: red de área extensa) es un servicio de red de área extensa (WAN) gestionada para construir una red global única que une VPC (Virtual Private Cloud) de varias regiones, oficinas y centros de datos sobre la red troncal de AWS. En lugar de configurar y enlazar a mano un Transit Gateway por región, describes la red en una política declarativa (qué regiones, qué segmentos, qué se conecta con qué) y Cloud WAN la despliega y la mantiene coherente en todas partes.

Conceptos clave

  • Red global: el contenedor de todos los objetos de red, que puede incluir redes troncales de Cloud WAN y también Transit Gateway existentes.
  • Red troncal (core network): la parte gestionada por AWS, que opera en las regiones que indica la política.
  • Política de la red troncal: un documento JSON (JavaScript Object Notation: formato de datos en texto) con versiones que define regiones, segmentos, cómo se asignan los anexos y cómo se comparten rutas. Solo una versión está activa y se puede volver a una anterior.
  • Borde de la red troncal (core network edge): el punto de conexión regional gestionado por AWS (funciona como un Transit Gateway). Los bordes de todas las regiones se unen entre sí en malla completa de forma automática.
  • Segmentos: dominios de enrutamiento aislados y globales (producción, desarrollo, servicios compartidos…). Por defecto solo se comunican los anexos del mismo segmento; las acciones de segmento comparten rutas entre segmentos de forma explícita. Pueden exigir aprobación para unirse.
  • Anexos y políticas de anexo: VPC, VPN (Virtual Private Network: red privada virtual), Connect (para equipos SD-WAN (Software-Defined Wide Area Network: red extensa entre sedes gestionada por software)) o tablas de rutas de Transit Gateway. Las políticas de anexo asignan cada anexo a su segmento según sus etiquetas.
  • Grupos de funciones de red: anexos con cortafuegos o sistemas de inspección; la política desvía por ellos el tráfico entre segmentos o regiones sin rutas estáticas.
  • Propietario de la red y de los anexos: el equipo de red comparte la red troncal con RAM (Resource Access Manager) y las cuentas de aplicación solo pueden crear sus anexos y etiquetas.

Casos de uso típicos

  • Red global de una empresa con VPC en muchas regiones y oficinas en varios continentes.
  • Separar producción y desarrollo (o unidades de negocio) en segmentos aislados en todo el mundo.
  • Inspeccionar con cortafuegos centralizados el tráfico entre segmentos y entre regiones.
  • Sustituir la red privada de un operador o una malla de VPN entre sedes por la red troncal de AWS.
  • Convivir con Transit Gateway existentes mediante emparejamiento, durante una migración.

Cuándo NO usarlo

  • Para pocas VPC en una o dos regiones: Transit Gateway es más sencillo y suele salir más barato.
  • Para conectar dos VPC concretas: emparejamiento de VPC (peering).
  • Para comunicación entre servicios de aplicación (no redes enteras): VPC Lattice o PrivateLink.
  • Para el enlace físico privado con el centro de datos: Direct Connect (que se puede unir a Cloud WAN).

Modelo de precios

Se paga por hora de cada borde de la red troncal (uno por región), por hora de cada anexo y por GB procesado. Algunas funciones, como la NAT (Network Address Translation: traducción de direcciones de red) 1:1, añaden su propio coste, y la transferencia entre regiones se factura aparte.

Seguridad y alta disponibilidad

  • Segmentos aislados por defecto y aprobación opcional para unir anexos a un segmento.
  • Inspección centralizada con grupos de funciones de red (por ejemplo, Network Firewall).
  • Bordes en malla completa con caminos redundantes por la red global de AWS.
  • Cambios controlados: versiones de la política, conjunto de cambios previo y vuelta atrás.
  • Visibilidad central (mapas de topología, eventos y rutas) en Network Manager, con región base en us-west-2.

Trampas de examen

  • "Red global, muchas regiones y sedes, configuración central con una política": Cloud WAN.
  • "Aislar producción y desarrollo en todo el mundo": segmentos de Cloud WAN.
  • "Que cada VPC nueva quede en su segmento sin intervención del equipo de red": políticas de anexo por etiquetas.
  • "Pocas VPC en una región": Transit Gateway.
  • "Pasar por un cortafuegos el tráfico entre segmentos": grupo de funciones de red.
