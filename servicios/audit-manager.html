AWS Audit Manager

En una frase: Recoge evidencias automáticas para preparar auditorías frente a marcos como PCI DSS (Payment Card Industry Data Security Standard: norma de seguridad para datos de tarjetas)
Categoría: Seguridad, identidad y cumplimiento (Security, Identity, and Compliance)
Certificaciones: SAP-C02
Documentación oficial: Documentación de AWS Audit Manager ↗
Aviso: Audit Manager está en modo de mantenimiento: desde el 30/04/2026 no se puede activar en cuentas nuevas ni extender a más regiones. Quien ya lo usaba puede seguir, incluso creando evaluaciones, pero AWS no añadirá marcos ni funciones. La alternativa que propone AWS son los paquetes de conformidad de AWS Config, que tienen plantillas para marcos como HIPAA (Health Insurance Portability and Accountability Act: ley de EE. UU. que protege los datos de salud), NIST (National Institute of Standards and Technology: organismo de normas de EE. UU.) o PCI DSS (no para todos: faltan, por ejemplo, SOC (System and Organization Controls: informes de auditoría sobre los controles de un proveedor) 2 y el RGPD) y no generan un informe de auditoría equivalente. Sigue en la guía de SAP-C02, que se puede presentar hasta el 17/11/2026.

Qué es

AWS Audit Manager automatiza la parte más tediosa de una auditoría: reunir las evidencias. Recoge de forma continua datos de tu uso de AWS, los asocia a los controles de un marco de cumplimiento y los deja ordenados para que el auditor los revise. Audita tu entorno, a diferencia de AWS Artifact, que entrega los informes sobre el cumplimiento de AWS.

Conceptos clave

  • Marco (framework): un conjunto de controles agrupados. Hay marcos estándar ya preparados (PCI DSS, HIPAA, SOC 2, RGPD, CIS (Center for Internet Security: organización que publica referencias de configuración segura), buenas prácticas de AWS) y personalizados.
  • Control: un requisito concreto, con las fuentes de datos de las que se obtiene su evidencia.
  • Evaluación (assessment): la aplicación de un marco a un alcance: unas cuentas y unos servicios. Desde que se crea, empieza a acumular evidencias.
  • Evidencias automáticas: salen de AWS Config (resultados de reglas), Security Hub (controles), CloudTrail (actividad de los usuarios) y llamadas a las API (Application Programming Interface: interfaz para que los programas se comuniquen) de los servicios (instantáneas de configuración).
  • Evidencias manuales: documentos que subes tú, para los controles que no se pueden comprobar de forma automática (políticas, actas, formación).
  • Delegación: un conjunto de controles se asigna a un experto para que lo revise.
  • Informe de evaluación: el resumen final con las evidencias seleccionadas, que se guarda en S3 (Simple Storage Service) con una suma de comprobación para verificar su integridad.
  • Varias cuentas: con AWS Organizations, una evaluación abarca cuentas de toda la organización, gestionada desde un administrador delegado.

Casos de uso típicos

  • Preparar una auditoría de PCI DSS, SOC 2 o HIPAA sin recopilar capturas de pantalla a mano.
  • Mantener el cumplimiento de forma continua, en lugar de reunirlo todo antes de cada auditoría.
  • Auditorías internas con controles propios de la empresa.

Cuándo NO usarlo

  • En cuentas nuevas ya no se puede activar: paquetes de conformidad de AWS Config.
  • Para descargar los informes de cumplimiento de AWS: AWS Artifact.
  • Para detectar y corregir configuraciones incorrectas: AWS Config y Security Hub. Audit Manager reúne pruebas; no corrige.
  • Para saber quién hizo una acción: CloudTrail.

Modelo de precios

Se paga por evaluación de recursos: cada vez que el servicio recoge una evidencia de un recurso para una evaluación activa. Aparte, el almacenamiento en S3 de los informes y el coste de las fuentes (reglas de AWS Config, Security Hub).

Seguridad y alta disponibilidad

  • Las evidencias se cifran con una clave de KMS (Key Management Service), de AWS o propia.
  • Las evidencias son de solo lectura y los informes llevan una suma de comprobación, lo que respalda su integridad ante el auditor.
  • El acceso se controla con IAM (Identity and Access Management), con permisos distintos para el responsable de la auditoría y para los delegados.
  • Es regional: cada evaluación recoge evidencias de la región donde se crea.

Trampas de examen

  • "Automatizar la recopilación de evidencias para una auditoría" o "preparar informes listos para el auditor": Audit Manager.
  • "Descargar el informe SOC de AWS": AWS Artifact. Audit Manager audita lo tuyo; AWS Artifact documenta lo de AWS.
  • "Comprobar si los recursos cumplen una regla y corregirlos": AWS Config.
  • Audit Manager no garantiza el cumplimiento: reúne pruebas; valorar si se cumple es cosa del auditor.
