AWS Transit Gateway

En una frase: Hub central que interconecta cientos de VPC (Virtual Private Cloud) y redes locales en estrella
Categoría: Redes y entrega de contenido (Networking and Content Delivery)
Certificaciones: CLF-C02 SAA-C03 SAP-C02
Documentación oficial: Documentación de AWS Transit Gateway ↗

Qué es

AWS Transit Gateway es un router regional gestionado que actúa como centro de una topología en estrella (hub-and-spoke). En lugar de conectar cada VPC con todas las demás, cada red se conecta una sola vez al Transit Gateway y este enruta el tráfico entre ellas: VPC, conexiones VPN (Virtual Private Network: red privada virtual), Direct Connect y otros Transit Gateway. AWS gestiona la disponibilidad y el escalado.

Conceptos clave

  • Adjuntos (attachments): cada red conectada. Tipos: VPC, Site-to-Site VPN, puerta de enlace de Direct Connect, emparejamiento con otro Transit Gateway (de la misma u otra región) y Connect (túneles GRE (Generic Routing Encapsulation: túnel que encapsula paquetes entre routers) con BGP (Border Gateway Protocol: protocolo con el que los routers se anuncian las redes) para dispositivos SD-WAN (Software-Defined Wide Area Network: red extensa entre sedes gestionada por software)).
  • Tablas de rutas: un Transit Gateway puede tener varias. Cada adjunto se asocia a una tabla (la que se consulta para su tráfico) y propaga sus rutas a las tablas que quieras. Así se segmenta: por ejemplo, producción y desarrollo no se ven, pero ambos llegan a los servicios compartidos.
  • Rutas de agujero negro (blackhole): descartan el tráfico hacia un destino.
  • Enrutamiento transitivo: a diferencia del emparejamiento de VPC, una VPC puede llegar a otra (o al centro de datos) pasando por el Transit Gateway.
  • Compartir entre cuentas: se comparte con otras cuentas u OU (Organizational Unit: unidad organizativa de AWS Organizations) de la organización mediante RAM (Resource Access Manager), de modo que un equipo de red central lo gestiona y las cuentas solo adjuntan sus VPC.
  • ECMP (Equal-Cost Multi-Path: reparte el tráfico entre varias rutas iguales): reparte el tráfico entre varios túneles VPN con enrutamiento dinámico (BGP) para sumar ancho de banda.
  • Modo dispositivo (appliance mode): mantiene la ida y la vuelta de una conexión en la misma AZ (Availability Zone: zona de disponibilidad), necesario cuando hay un cortafuegos con estado en una VPC de inspección.
  • Capacidad: miles de adjuntos por Transit Gateway y, por defecto, hasta 100 Gbps por adjunto de VPC y por AZ en cada sentido.

Casos de uso típicos

  • Conectar decenas o cientos de VPC de muchas cuentas sin una malla de emparejamientos.
  • Centralizar la conexión con el centro de datos: una sola conexión Direct Connect o VPN para todas las VPC.
  • VPC de salida centralizada (NAT (Network Address Translation: traducción de direcciones de red) compartido) o VPC de inspección con Network Firewall.
  • Conectar regiones entre sí con emparejamiento entre Transit Gateway.
  • Integrar redes SD-WAN con adjuntos Connect.

Cuándo NO usarlo

  • Solo dos o tres VPC que deben hablar entre sí: el emparejamiento de VPC es más simple y no tiene cargo por hora ni por procesamiento.
  • Exponer un único servicio a otras VPC o cuentas sin abrir toda la red, incluso con rangos de IP (Internet Protocol: dirección de red) solapados: PrivateLink.
  • Una red global con muchas regiones y sedes gestionada por políticas: AWS Cloud WAN (Wide Area Network: red de área extensa).
  • VPC con CIDR (Classless Inter-Domain Routing: notación de rangos de IP como 10.0.0.0/16) solapados: Transit Gateway no enruta entre ellos.

Modelo de precios

Se paga por hora de cada adjunto y por gigabyte procesado por el Transit Gateway, además de la transferencia de datos entre regiones cuando hay emparejamiento.

Seguridad y alta disponibilidad

  • Es un servicio regional de alta disponibilidad. Para cada adjunto de VPC eliges una subred por AZ; adjunta una en cada AZ que uses.
  • La segmentación se hace con tablas de rutas; los grupos de seguridad y las ACL (Access Control List: lista de control de acceso) de red de cada VPC siguen aplicando.
  • El tráfico entre regiones por emparejamiento va cifrado por la red troncal de AWS.
  • Los registros de flujo de Transit Gateway muestran el tráfico que pasa por él.

Trampas de examen

  • "Cientos de VPC" o "evitar una malla de emparejamientos": Transit Gateway.
  • "Enrutamiento transitivo": el emparejamiento de VPC no lo admite; Transit Gateway sí.
  • "Aislar entornos pero compartir servicios comunes": varias tablas de rutas con asociaciones y propagaciones distintas.
  • "Sumar ancho de banda de varias VPN": ECMP sobre Transit Gateway, con BGP (no funciona con rutas estáticas).
  • "Compartir el Transit Gateway con otras cuentas": RAM.
  • "Cortafuegos con estado en una VPC de inspección y tráfico asimétrico": activa el modo dispositivo.
  • "Solo dos VPC y el menor coste": emparejamiento de VPC, no Transit Gateway.
