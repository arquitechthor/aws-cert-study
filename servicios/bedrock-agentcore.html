Amazon Bedrock AgentCore

En una frase: Ejecuta y protege agentes de IA (inteligencia artificial) en producción con memoria, identidad y observabilidad
Categoría: Machine learning (Machine Learning)
Certificaciones: AIF-C01
Documentación oficial: Documentación de Amazon Bedrock AgentCore ↗

Qué es

Amazon Bedrock AgentCore es un conjunto de servicios para llevar agentes de IA a producción. Un agente es un programa que usa un modelo de lenguaje para decidir qué pasos dar y qué herramientas llamar. AgentCore resuelve lo que no es el modelo: dónde se ejecuta el agente, cómo recuerda, cómo se conecta a herramientas y API (Application Programming Interface: interfaz para que los programas se comuniquen), quién puede usarlo y qué hace. Funciona con cualquier marco (Strands Agents, LangGraph, CrewAI…) y cualquier modelo, dentro o fuera de Bedrock.

Conceptos clave

  • Runtime: ejecuta el agente sin servidores, con cada sesión aislada y sesiones largas.
  • Memory: memoria a corto plazo (la conversación) y a largo plazo (preferencias, hechos, episodios aprendidos).
  • Gateway: convierte API, funciones Lambda y servicios en herramientas que el agente puede usar mediante MCP (Model Context Protocol: protocolo abierto para dar herramientas y datos a agentes de IA).
  • Identity: gestiona con qué identidad actúa el agente y sus credenciales hacia terceros (OAuth (estándar para delegar acceso a una aplicación sin compartir la contraseña), claves de API).
  • Policy: reglas (escritas en lenguaje natural y convertidas a Cedar) que interceptan las llamadas a herramientas para que el agente no se salga de sus límites.
  • Evaluations: mide la calidad del agente con evaluadores ya definidos o propios.
  • Observability: trazas y métricas de cada paso del agente en CloudWatch.
  • Herramientas integradas: navegador (Browser) e intérprete de código (Code Interpreter) en entornos aislados.

Casos de uso típicos

  • Desplegar en producción un agente de atención al cliente creado con Strands o LangGraph.
  • Dar a un agente acceso controlado a las API internas de la empresa.
  • Agentes que recuerdan las preferencias de cada usuario entre sesiones.

Cuándo NO usarlo

  • Para una sola llamada a un modelo (resumir, clasificar): la API de Bedrock basta.
  • Para un asistente empresarial listo para usar sin programar: soluciones gestionadas como Amazon Quick.
  • Para escribir la lógica del agente: eso lo hace un marco como Strands Agents; AgentCore lo ejecuta y lo protege.

Modelo de precios

Pago por uso de cada componente: tiempo de CPU (Central Processing Unit: procesador) y memoria consumido en Runtime, eventos y registros de memoria, invocaciones de Gateway, etc., sin costes iniciales. Los modelos se pagan aparte.

Seguridad y alta disponibilidad

  • Aislamiento de cada sesión de usuario en Runtime.
  • Identidades y credenciales del agente gestionadas, sin guardarlas en el código.
  • Policy limita qué herramientas y con qué parámetros puede usar el agente.
  • Trazas completas para auditar las decisiones del agente.

Trampas de examen

  • "Ejecutar agentes en producción de forma segura y escalable con cualquier marco": AgentCore.
  • "Que el agente recuerde entre sesiones": AgentCore Memory.
  • "Convertir API internas en herramientas para el agente": AgentCore Gateway.
  • "Impedir que el agente haga ciertas acciones": AgentCore Policy.
