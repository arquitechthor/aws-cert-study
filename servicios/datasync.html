AWS DataSync

En una frase: Tareas de copia en línea de grandes volúmenes desde NAS o servidores a S3, EFS o FSx
Categoría: Migración y transferencia (Migration and Transfer)
Certificaciones: SAA-C03 SAP-C02
Documentación oficial: Documentación de AWS DataSync ↗

Qué es

AWS DataSync es un servicio de transferencia de datos en línea. Copia ficheros y objetos entre tu almacenamiento local (NAS con NFS (Network File System: protocolo para compartir ficheros en red) o SMB (Server Message Block: protocolo de ficheros compartidos de Windows), HDFS (Hadoop Distributed File System: sistema de ficheros distribuido de Hadoop), almacenamiento de objetos), otras nubes y los servicios de almacenamiento de AWS: S3, EFS y todos los tipos de FSx. Se encarga del paralelismo, el cifrado, los reintentos y la verificación de integridad, y puede ejecutarse de forma programada copiando solo lo que ha cambiado.

Conceptos clave

  • Agente: máquina virtual (VMware, Hyper-V, KVM (Kernel-based Virtual Machine: hipervisor de Linux)) o instancia EC2 (Elastic Compute Cloud) que se despliega cerca del almacenamiento de origen para leerlo. Entre servicios de AWS no hace falta agente.
  • Ubicaciones: el origen y el destino de la copia.
  • Tarea: la configuración de una transferencia: ubicaciones, filtros de inclusión y exclusión, límite de ancho de banda, verificación y programación.
  • Transferencias incrementales: tras la primera copia completa, solo se copian los cambios.
  • Conserva metadatos: permisos, marcas de tiempo y propietarios de los ficheros.
  • Rendimiento: una sola tarea puede aprovechar un enlace de 10 Gbps; para más, se reparten los datos entre varias tareas y agentes.
  • Red: puede ir por internet, VPN (Virtual Private Network: red privada virtual) o Direct Connect, y usar puntos de enlace de VPC (Virtual Private Cloud) para no salir a internet.

Casos de uso típicos

  • Migrar un NAS local a EFS o a FSx.
  • Mover datos a S3 para analizarlos o archivarlos (incluidas clases Glacier).
  • Replicar periódicamente datos entre centros de datos y AWS, o entre servicios de AWS de distintas regiones.
  • Traer datos desde otra nube.

Cuándo NO usarlo

  • Si la red no da para mover el volumen en un plazo razonable: transferencia física (Snow Family para clientes existentes, Data Transfer Terminal para nuevos).
  • Para que las aplicaciones locales sigan accediendo a los datos en AWS de forma continua, con caché local: Storage Gateway.
  • Para que socios externos suban ficheros por SFTP (SSH File Transfer Protocol: transferencia de ficheros sobre SSH): Transfer Family.
  • Para migrar bases de datos: DMS (Database Migration Service).

Modelo de precios

Se paga por gigabyte copiado (con tarifas distintas según el modo de la tarea), más las peticiones y el almacenamiento de los servicios de destino y la transferencia de datos que corresponda.

Seguridad y alta disponibilidad

  • Cifrado en tránsito con TLS (Transport Layer Security: cifrado de las conexiones); los datos en destino se cifran según el servicio (por ejemplo SSE (Server-Side Encryption: cifrado en el servidor) en S3).
  • Verificación de integridad durante y después de la copia.
  • Acceso a los destinos con roles de IAM (Identity and Access Management).
  • Puntos de enlace de VPC (PrivateLink) para que la transferencia no pase por internet.

Trampas de examen

  • "Copiar un NAS (NFS o SMB) a EFS, FSx o S3": DataSync.
  • "Copia programada e incremental con verificación": DataSync.
  • "Que la copia no sature la red en horario laboral": límite de ancho de banda y programación.
  • "Seguir usando los ficheros desde local con caché": Storage Gateway, no DataSync.
  • "Petabytes con poca red": transferencia física, no DataSync.
  • "Sin pasar por internet": agente con punto de enlace de VPC sobre Direct Connect o VPN.
