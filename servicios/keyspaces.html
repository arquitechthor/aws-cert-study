Amazon Keyspaces

Amazon Keyspaces (for Apache Cassandra)

En una frase: Base de columnas anchas sin servidor compatible con CQL (Cassandra Query Language: lenguaje de consultas de Apache Cassandra) y sus drivers de código abierto
Categoría: Base de datos (Database)
Certificaciones: SAA-C03 SAP-C02
Documentación oficial: Documentación de Amazon Keyspaces ↗

Qué es

Amazon Keyspaces (for Apache Cassandra) es una base de datos de columnas anchas, sin servidor y compatible con Apache Cassandra. Las aplicaciones usan el mismo lenguaje CQL y los mismos controladores, pero no hay nodos, clústeres ni reparaciones que gestionar: las tablas escalan solas y AWS guarda tres copias de los datos en varias AZ (Availability Zone: zona de disponibilidad).

Conceptos clave

  • Espacio de claves (keyspace) y tablas: como en Cassandra, con clave de partición y columnas de agrupación.
  • Modos de capacidad: bajo demanda (pago por petición) o aprovisionada, con escalado automático.
  • Replicación multirregión: tablas replicadas en varias regiones con escritura en todas.
  • Recuperación a un momento dado (PITR) de los últimos 35 días y TTL (Time To Live: tiempo de vida antes de caducar) para que las filas caduquen solas.
  • Límites: filas de hasta 1 MB; algunas funciones de Cassandra no están disponibles o se comportan distinto, así que conviene comprobar la compatibilidad.
  • Captura de cambios (CDC): flujo de cambios de las filas para otras aplicaciones.

Casos de uso típicos

  • Migrar un clúster de Cassandra sin seguir operando nodos.
  • Aplicaciones de gran volumen de escritura: telemetría, IoT (Internet of Things: internet de las cosas: dispositivos conectados), historiales de eventos.
  • Datos de perfiles o catálogos con acceso por clave a escala.

Cuándo NO usarlo

  • Si no hay código Cassandra que conservar: DynamoDB suele ser la opción nativa.
  • Para consultas relacionales con uniones: RDS (Relational Database Service) o Aurora.
  • Si necesitas funciones de Cassandra no compatibles: Cassandra propio en EC2 (Elastic Compute Cloud).

Modelo de precios

Se paga por petición de lectura y escritura (bajo demanda) o por capacidad aprovisionada, más el almacenamiento, las copias PITR, el TTL y la replicación multirregión.

Seguridad y alta disponibilidad

  • Tres réplicas en varias AZ de la región.
  • Cifrado en reposo siempre activo (clave de AWS o de KMS (Key Management Service)) y TLS (Transport Layer Security: cifrado de las conexiones) obligatorio en tránsito.
  • Autenticación con IAM (Identity and Access Management) (complemento de firma para los controladores) o credenciales específicas del servicio.
  • Puntos de enlace de VPC (Virtual Private Cloud) para no salir a internet.

Trampas de examen

  • "Cassandra" o "CQL" sin gestionar servidores: Keyspaces.
  • "Clave-valor nativo de AWS" sin Cassandra: DynamoDB.
  • "Escrituras en varias regiones": replicación multirregión de Keyspaces.
  • "Volver a un estado de hace unos días": PITR.
  • "Filas que caduquen solas": TTL.
