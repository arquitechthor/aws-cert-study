AWS Cost Categories

En una frase: Agrupa el gasto con reglas propias, como equipos o proyectos, para repartir la factura
Categoría: Administración financiera en la nube (Cloud Financial Management)
Certificaciones: SAP-C03
Documentación oficial: Documentación de AWS Cost Categories ↗

Qué es

AWS Cost Categories permite clasificar los costes de AWS según la estructura de tu empresa: equipos, unidades de negocio, proyectos o centros de coste. Defines reglas (por cuenta, etiqueta, servicio, tipo de cargo u otra categoría) y cada línea de la factura recibe un valor de la categoría. Esos valores aparecen después en Cost Explorer, Budgets, el informe de costes y uso (CUR) y la detección de anomalías de costes, sin tocar los recursos.

Conceptos clave

  • Categoría y valores: por ejemplo, la categoría "Equipo" con los valores "Pagos", "Catálogo" y "Plataforma".
  • Reglas: asignan un valor según dimensiones como la cuenta, una etiqueta de asignación de costes, el servicio o el tipo de cargo. Se evalúan en orden y gana la primera que coincide.
  • Valor heredado: el valor se toma directamente de una etiqueta o del nombre de la cuenta, sin escribir una regla por cada caso.
  • Valor por defecto: nombre para lo que no encaja en ninguna regla (si no, queda sin categorizar).
  • Reglas de reparto de cargos (split charges): reparten costes compartidos (soporte Enterprise, transferencia de datos, la cuenta de red común) entre varios valores, a partes iguales, en proporción al gasto o con porcentajes fijos.
  • Jerarquías: una categoría puede usar otra como dimensión (centro de coste → departamento → equipo).
  • Aplicación: las reglas organizan el coste desde el principio del mes y se pueden aplicar a meses anteriores.

Casos de uso típicos

  • Showback y chargeback: mostrar o cobrar a cada equipo lo que gasta.
  • Presupuestos de Budgets por unidad de negocio aunque cada una use varias cuentas y etiquetas.
  • Repartir de forma justa los costes de la plataforma compartida entre los equipos que la usan.
  • Informes de FinOps con la misma clasificación en Cost Explorer y en el CUR.

Cuándo NO usarlo

  • Para obligar a etiquetar los recursos: políticas de etiquetas de Organizations y SCP (las categorías solo clasifican lo que ya hay).
  • Para limitar o avisar de un gasto: Budgets (que sí puede usar las categorías como filtro).
  • Para analizar gasto con SQL (Structured Query Language: lenguaje de consultas de bases de datos relacionales) a nivel de recurso: el informe de costes y uso con Athena.

Modelo de precios

Crear y usar categorías de costes no tiene coste adicional. Se pagan, en su caso, las herramientas que las consumen, como las llamadas a la API (Application Programming Interface: interfaz para que los programas se comuniquen) de Cost Explorer o los presupuestos de Budgets.

Seguridad y alta disponibilidad

  • Se gestionan desde la cuenta de administración de la organización (o con permisos de facturación de IAM (Identity and Access Management)).
  • No cambian los recursos ni la factura real: solo cómo se agrupa para analizarla.
  • Se pueden definir con CloudFormation para versionarlas como código.

Trampas de examen

  • "Agrupar el gasto por unidad de negocio que usa varias cuentas y etiquetas": Cost Categories.
  • "Repartir el coste del soporte o de la red compartida entre equipos": reglas de reparto de cargos.
  • "Presupuesto por centro de coste": Budgets filtrado por una categoría de costes.
  • "Exigir etiquetas en todos los recursos": políticas de etiquetas o SCP, no Cost Categories.
