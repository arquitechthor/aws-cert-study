AWS CDK

En una frase: Define infraestructura con TypeScript, Python o Java y la convierte en plantillas
Categoría: Administración y gobernanza (Management and Governance)
Certificaciones: DVA-C02
Documentación oficial: Documentación de AWS CDK ↗

Qué es

AWS CDK (Cloud Development Kit) es un marco de código abierto para definir infraestructura con un lenguaje de programación de propósito general en lugar de escribir plantillas a mano. Tu programa describe los recursos con clases y objetos; el CDK lo sintetiza en plantillas de CloudFormation y las despliega. Así aprovechas bucles, condiciones, funciones, tipos, pruebas unitarias y el autocompletado del editor, y por debajo sigues teniendo las garantías de CloudFormation (pilas, reversión, detección de desviaciones).

Conceptos clave

  • Lenguajes: TypeScript, JavaScript, Python, Java, C# y Go.
  • App, pila y construct: una app contiene una o varias pilas (cada una es una pila de CloudFormation), y cada pila está hecha de constructs, las piezas reutilizables.
  • Tres niveles de construct:
    • L1 (clases Cfn…): equivalencia uno a uno con un recurso de CloudFormation; hay que indicar todas las propiedades.
    • L2: recursos con valores por defecto sensatos y métodos de ayuda. Por ejemplo, bucket.grantRead(funcion) genera la política de IAM (Identity and Access Management) de mínimo privilegio.
    • L3 (patrones): varios recursos ya combinados para una tarea, como un servicio de Fargate con su balanceador.
  • Síntesis: cdk synth ejecuta el programa y genera el cloud assembly: una plantilla por pila más los recursos adjuntos (assets), como el código de las funciones Lambda o las imágenes de contenedor.
  • Bootstrap: cdk bootstrap se ejecuta una vez por cuenta y región. Crea la pila CDKToolkit con el bucket de S3 (Simple Storage Service), el repositorio de ECR (Elastic Container Registry) y los roles de IAM que el CDK necesita para subir los recursos adjuntos y desplegar.
  • Comandos habituales: cdk init (proyecto nuevo), cdk synth, cdk diff (qué cambiaría respecto a lo desplegado), cdk deploy y cdk destroy.
  • Entorno: la pareja cuenta y región a la que apunta cada pila.
  • Pruebas: el módulo de aserciones permite comprobar en pruebas unitarias la plantilla que se va a generar.

Casos de uso típicos

  • Equipos de desarrollo que quieren definir la infraestructura en el mismo lenguaje y repositorio que la aplicación.
  • Crear componentes internos reutilizables (un construct con los estándares de la empresa) y compartirlos como una biblioteca.
  • Infraestructura con mucha repetición o lógica: diez entornos casi iguales, recursos generados en un bucle.
  • Pipelines de despliegue definidos también en código (CDK Pipelines).

Cuándo NO usarlo

  • Si el equipo prefiere plantillas declarativas y no quiere mantener código: CloudFormation directamente.
  • Para aplicaciones sin servidor sencillas con una sintaxis abreviada: SAM (Serverless Application Model: extensión de CloudFormation para aplicaciones sin servidores), que además permite probar las funciones en local.
  • Si necesitas la misma herramienta para varias nubes: Terraform.
  • Para desplegar una aplicación web sin diseñar la infraestructura: Elastic Beanstalk.

Modelo de precios

El CDK es gratuito y de código abierto. Se pagan los recursos que despliega y los que crea el bootstrap (el almacenamiento del bucket de S3 y del repositorio de ECR).

Seguridad y alta disponibilidad

  • El despliegue lo hace CloudFormation con los roles creados en el bootstrap, no con los permisos directos de quien ejecuta el comando: conviene acotar esos roles.
  • Los métodos grant… generan políticas de mínimo privilegio y evitan escribir IAM a mano.
  • cdk diff avisa de los cambios en permisos de IAM y en grupos de seguridad antes de desplegar.
  • La alta disponibilidad depende de lo que definas (varias AZ (Availability Zone: zona de disponibilidad), escalado); el CDK solo genera la plantilla.

Trampas de examen

  • "Definir infraestructura con Python, TypeScript o Java": CDK.
  • El CDK no sustituye a CloudFormation: lo usa por debajo. Las cuotas y el comportamiento de las pilas son los de CloudFormation.
  • Error al desplegar por falta del bucket de recursos adjuntos o en una cuenta o región nueva: falta ejecutar cdk bootstrap.
  • "Ver los cambios antes de desplegar": cdk diff. "Obtener la plantilla": cdk synth.
  • "Componentes de alto nivel con valores por defecto": L2. "Control total sobre cada propiedad": L1.
