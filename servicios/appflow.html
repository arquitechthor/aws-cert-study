Amazon AppFlow

Categoría: Integración de aplicaciones (Application Integration)
Certificaciones: SAA-C03 SAP-C02
Documentación oficial: Documentación de Amazon AppFlow ↗

Qué es

Amazon AppFlow mueve datos entre aplicaciones SaaS (software como servicio, como Salesforce, SAP, Zendesk, Slack, ServiceNow o Google Analytics) y servicios de AWS como S3 (Simple Storage Service) o Redshift, en ambos sentidos. Se configura con clics: eliges origen, destino, qué campos copiar y cuándo, y AppFlow hace la extracción, la transformación básica y la carga sin que tengas que programar ni mantener integraciones con las API (Application Programming Interface: interfaz para que los programas se comuniquen) de cada proveedor.

Conceptos clave

  • Flujo (flow): la definición de una transferencia: conexión de origen, destino, mapeo de campos, filtros y disparador.
  • Conectores: decenas de aplicaciones SaaS y servicios de AWS integrados; con el SDK (Software Development Kit) de conectores personalizados se pueden añadir otros.
  • Disparadores: bajo demanda, programado (cada cierto tiempo, con transferencias incrementales solo de lo nuevo o modificado) o por evento (por ejemplo, cuando cambia un registro en Salesforce).
  • Transformaciones: mapear y renombrar campos, filtrar registros, validar, enmascarar campos sensibles y combinar campos, sin código.
  • Destinos habituales: S3 (para un lago de datos), Redshift, Snowflake, EventBridge y de vuelta a otras aplicaciones SaaS como Salesforce.
  • Conectividad privada: con proveedores que lo admiten (como Salesforce), los datos viajan por AWS PrivateLink sin pasar por internet.

Casos de uso típicos

  • Copiar cada día las oportunidades de Salesforce a S3 para analizarlas con Athena o Redshift.
  • Enviar a Salesforce datos de clientes calculados en AWS.
  • Reaccionar a cambios en un SaaS enviando los eventos a EventBridge.
  • Alimentar un lago de datos con información de marketing y soporte sin desarrollar integraciones.

Cuándo NO usarlo

  • Transformaciones complejas o grandes volúmenes entre bases de datos: AWS Glue.
  • Migrar bases de datos relacionales: AWS DMS (Database Migration Service).
  • Transferir ficheros desde servidores propios: DataSync o Transfer Family.
  • Datos en streaming en tiempo real de alto volumen: Kinesis o Amazon Data Firehose.

Comparativa con servicios parecidos

NecesidadServicio adecuado
Datos de aplicaciones SaaS, sin códigoAppFlow
ETL (extraer, transformar y cargar) complejo y catálogo de datosGlue
Migrar o replicar bases de datosDMS
Ficheros desde el centro de datosDataSync
Streaming hacia S3 o RedshiftAmazon Data Firehose

Modelo de precios

Se paga por cada ejecución de flujo y por el volumen de datos procesados (por GB), más los servicios de destino (almacenamiento en S3, Redshift…) y, si se usa, PrivateLink. No hay infraestructura que aprovisionar.

Seguridad y alta disponibilidad

  • Datos cifrados en tránsito y en reposo, con claves de KMS (Key Management Service) gestionadas por AWS o por el cliente.
  • Credenciales de las aplicaciones SaaS guardadas de forma segura (en Secrets Manager).
  • Tráfico privado por PrivateLink con los proveedores que lo admiten.
  • Servicio gestionado y regional, sin servidores que mantener.

Trampas de examen

  • "Datos de Salesforce (u otro SaaS) a S3 o Redshift sin programar": AppFlow.
  • "Sin pasar por internet" con Salesforce: AppFlow con PrivateLink.
  • "ETL complejo entre bases de datos": Glue, no AppFlow.
  • "Solo los registros nuevos o cambiados": flujo programado con transferencia incremental.
