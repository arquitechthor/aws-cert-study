AWS Service Catalog

En una frase: Portafolio de productos aprobados por TI (tecnologías de la información: el departamento de sistemas) que los equipos lanzan en autoservicio
Categoría: Administración y gobernanza (Management and Governance)
Certificaciones: SAA-C03 SAP-C02 CLF-C02
Documentación oficial: Documentación de AWS Service Catalog ↗
Aviso: AppRegistry, la parte de Service Catalog para agrupar recursos por aplicación, no admite clientes nuevos desde el 30/07/2026 (quienes ya lo usaban pueden seguir). AWS propone como alternativas las etiquetas, AWS Resource Groups y Resource Explorer. El catálogo de productos, que es lo que entra en los exámenes, no cambia.

Qué es

AWS Service Catalog permite a una organización publicar un catálogo de productos de TI aprobados: desde una instancia o una base de datos hasta una arquitectura completa. Los administradores definen cada producto como una plantilla de infraestructura como código y deciden quién puede usarlo. Los usuarios lo lanzan en autoservicio, eligiendo unos pocos parámetros, sin necesitar permisos sobre los servicios que hay debajo. El resultado es rapidez para los equipos y gobierno para la empresa.

Conceptos clave

  • Producto: un servicio de TI que se quiere ofrecer, definido con una plantilla de CloudFormation o una configuración de Terraform. Tiene versiones.
  • Cartera (portfolio): un conjunto de productos junto con su configuración: quién tiene acceso y con qué restricciones. El acceso se concede a usuarios, grupos o roles de IAM (Identity and Access Management).
  • Producto aprovisionado: una instancia lanzada de un producto (por debajo, una pila de CloudFormation). El usuario puede actualizarla a otra versión o terminarla.
  • Restricciones (constraints):
    • De lanzamiento: indica el rol de IAM que Service Catalog asume para crear los recursos. Por eso el usuario no necesita permisos sobre ellos.
    • De plantilla: limita los valores que el usuario puede elegir en los parámetros (por ejemplo, solo ciertos tipos de instancia).
    • De notificación: envía los eventos de la pila a un tema de SNS (Simple Notification Service).
    • De actualización de etiquetas y de conjunto de pilas (despliegue en varias cuentas y regiones con StackSets).
  • TagOptions: etiquetas predefinidas que se aplican obligatoriamente a lo que se lanza.
  • Compartir carteras: con otras cuentas o con toda una organización o una OU (Organizational Unit: unidad organizativa de AWS Organizations) mediante AWS Organizations, desde la cuenta de administración o un administrador delegado. El modelo habitual es una cuenta central (hub) que publica y cuentas consumidoras (spoke).
  • Acciones de servicio: operaciones predefinidas (reiniciar, hacer una copia) que el usuario puede ejecutar sobre lo lanzado, mediante documentos de Systems Manager.

Casos de uso típicos

  • Autoservicio con gobierno: los equipos lanzan entornos estándar sin abrir una petición ni tener permisos amplios.
  • Imponer arquitecturas que cumplen las normas de seguridad y de costes (cifrado, etiquetas, tamaños).
  • Es la base de Account Factory de Control Tower, que crea cuentas como productos.
  • Ofrecer entornos de ciencia de datos o de desarrollo ya configurados.

Cuándo NO usarlo

  • Si quien despliega es el propio equipo de infraestructura: basta CloudFormation o CDK.
  • Para comprar software de terceros: AWS Marketplace (aunque sus productos se pueden añadir a una cartera).
  • Para impedir acciones en toda la organización: SCP (Service Control Policy: límite de permisos para las cuentas de una organización) de AWS Organizations.
  • Para desplegar la misma pila en muchas cuentas sin autoservicio: CloudFormation StackSets.

Modelo de precios

Se cobra por llamadas a la API (Application Programming Interface: interfaz para que los programas se comuniquen) de Service Catalog por encima de un cupo gratuito mensual por cuenta y región. Aparte se pagan los recursos que crean los productos.

Seguridad y alta disponibilidad

  • La restricción de lanzamiento aplica el mínimo privilegio: el usuario solo necesita permiso para usar Service Catalog, y el rol de lanzamiento es el que crea los recursos.
  • En los productos de Terraform la restricción de lanzamiento es obligatoria.
  • Al compartir una cartera entre cuentas, el rol de lanzamiento se puede indicar por nombre para que se use el rol local de cada cuenta.
  • Service Catalog es regional: una cartera hay que crearla o compartirla en cada región donde se use.

Trampas de examen

  • "Los usuarios deben poder desplegar solo configuraciones aprobadas" o "autoservicio con gobierno": Service Catalog.
  • "Sin dar a los usuarios permisos sobre los servicios subyacentes": restricción de lanzamiento con un rol de IAM.
  • "Limitar los tipos de instancia que se pueden elegir": restricción de plantilla.
  • "Distribuir productos estándar a todas las cuentas": compartir la cartera con la organización.
  • No confundir con Marketplace (software de terceros) ni con Systems Manager (operación de recursos).
