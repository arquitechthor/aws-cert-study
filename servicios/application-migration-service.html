AWS Transform MGN

En una frase: Replica servidores físicos o virtuales a la nube tal cual, para migrarlos sin rehacer
Categoría: Migración y transferencia (Migration and Transfer)
Certificaciones: CLF-C02 SAA-C03 SAP-C02
Documentación oficial: Documentación de AWS Transform MGN ↗
Aviso: AWS Transform MGN es el nombre actual de AWS Application Migration Service (MGN), renombrado en junio de 2026 al convertirse en el motor de replicación de AWS Transform. El servicio y su funcionamiento no cambian, y en los exámenes verás "Application Migration Service": es esto mismo.

Qué es

AWS Transform MGN, antes llamado AWS Application Migration Service, es el servicio recomendado para rehospedar (lift and shift) servidores en AWS. Un agente instalado en cada servidor de origen replica sus discos bloque a bloque y de forma continua a AWS. Cuando quieras, lanzas instancias EC2 (Elastic Compute Cloud) de prueba y, al final, haces el corte con una parada de minutos. Sirve para servidores físicos, máquinas virtuales (VMware, Hyper-V) y servidores en otras nubes, con Windows o Linux.

Conceptos clave

  • Agente de replicación: se instala en cada servidor de origen y envía los cambios de sus discos de forma continua.
  • Área de preparación (staging area): subred de tu cuenta con servidores de replicación ligeros y volúmenes EBS (Elastic Block Store) de bajo coste que reciben los datos.
  • Plantillas de lanzamiento: definen el tipo de instancia, la subred y los grupos de seguridad de las instancias de prueba y de corte; MGN convierte el arranque y los controladores para EC2.
  • Prueba y corte: primero se lanzan instancias de prueba sin afectar a la replicación; en el corte se detiene el origen, se lanza la instancia definitiva y se finaliza.
  • Acciones posteriores al lanzamiento: scripts y tareas de Systems Manager que se ejecutan en la instancia nueva (instalar agentes, cambiar configuración…).
  • Olas y aplicaciones: agrupar servidores para migrarlos juntos.
  • AWS Transform: flujo con agentes de IA (inteligencia artificial) que planifica olas, prepara la red y usa MGN para rehospedar.

Casos de uso típicos

  • Mover un centro de datos a AWS sin cambiar las aplicaciones.
  • Migrar desde otra nube a EC2.
  • Mover instancias EC2 entre regiones o cuentas.
  • Primer paso de una modernización: rehospedar ahora y optimizar después.

Cuándo NO usarlo

  • Para migrar solo una base de datos o cambiar de motor: DMS (Database Migration Service) (y SCT (Schema Conversion Tool)).
  • Para recuperación ante desastres continua (no una migración): Elastic Disaster Recovery, que usa una tecnología parecida.
  • Para mover ficheros o recursos compartidos: DataSync.
  • Si vas a reescribir la aplicación (por ejemplo, a contenedores o sin servidor), rehospedar el servidor tal cual no aporta.

Modelo de precios

Cada servidor de origen tiene 2160 horas gratis (90 días de replicación continua); después se paga por hora de replicación. Siempre se pagan los recursos que crea en tu cuenta: servidores de replicación, volúmenes EBS, instantáneas e instancias de prueba y de corte.

Seguridad y alta disponibilidad

  • Datos cifrados en tránsito (TLS) y en los volúmenes EBS con KMS (Key Management Service).
  • La replicación puede ir por internet, VPN (Virtual Private Network: red privada virtual) o Direct Connect, y usar IP (Internet Protocol: dirección de red) privadas.
  • Las pruebas no interrumpen la replicación ni el origen.

Trampas de examen

  • "Lift and shift", "rehospedar", "sin cambios en la aplicación": Application Migration Service (hoy Transform MGN).
  • "Cientos de servidores VMware a EC2 con poca parada": MGN.
  • "Probar antes del corte sin afectar al origen": instancias de prueba de MGN.
  • Si aparecen Server Migration Service o CloudEndure Migration: son sus predecesores; la respuesta actual es MGN.
  • "Recuperación ante desastres": Elastic Disaster Recovery, no MGN.
