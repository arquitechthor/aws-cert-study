AWS Transfer Family

En una frase: Servidores SFTP (SSH File Transfer Protocol: transferencia de ficheros sobre SSH), FTPS (FTP Secure: FTP cifrado con TLS) y FTP (File Transfer Protocol: protocolo clásico de transferencia de ficheros) gestionados que guardan los ficheros en S3 (Simple Storage Service) o EFS (Elastic File System)
Categoría: Migración y transferencia (Migration and Transfer)
Certificaciones: SAA-C03 SAP-C02
Documentación oficial: Documentación de AWS Transfer Family ↗

Qué es

AWS Transfer Family ofrece servidores de transferencia de ficheros gestionados con los protocolos SFTP, FTPS, FTP y AS2 (Applicability Statement 2: protocolo para intercambiar documentos de negocio entre empresas). Los socios y clientes siguen usando sus herramientas de siempre, pero los ficheros se guardan directamente en S3 o EFS, sin servidores que mantener. Escala solo y se integra con tu sistema de identidades.

Conceptos clave

  • Protocolos: SFTP (sobre SSH (Secure Shell: acceso remoto cifrado por terminal)), FTPS (FTP con TLS (Transport Layer Security: cifrado de las conexiones)), FTP (sin cifrar, solo dentro de una VPC (Virtual Private Cloud)) y AS2 (intercambio entre empresas, típico en EDI (Electronic Data Interchange: intercambio electrónico de documentos comerciales)).
  • Almacenamiento: S3 (con permisos por rol de IAM (Identity and Access Management)) o EFS (con permisos POSIX (Portable Operating System Interface: estándar de ficheros y permisos tipo Unix)).
  • Proveedores de identidad: gestionado por el servicio (usuarios con claves SSH, solo SFTP), AWS Managed Microsoft AD (Active Directory: directorio de usuarios y equipos de Microsoft), o uno propio mediante Lambda o API Gateway (contraseñas, MFA (Multi-Factor Authentication: inicio de sesión con un segundo factor), otros directorios).
  • Directorios de inicio lógicos: cada usuario ve solo su carpeta, sin conocer el bucket.
  • Tipos de punto de enlace: público, o dentro de una VPC (con IP (Internet Protocol: dirección de red) elásticas para acceso desde internet, útil si el socio debe permitir IP fijas en su cortafuegos, o solo interno).
  • Flujos gestionados: pasos automáticos tras cada subida (copiar, etiquetar, descifrar, o una función Lambda).
  • Conectores SFTP: para enviar o recoger ficheros de servidores SFTP externos.
  • Aplicaciones web: acceso a S3 desde el navegador para usuarios no técnicos.

Casos de uso típicos

  • Recibir ficheros de socios y proveedores que solo trabajan con SFTP.
  • Migrar un servidor SFTP propio sin cambiar nada para los usuarios.
  • Intercambio EDI con AS2.
  • Iniciar procesos de datos en cuanto llega un fichero (flujos gestionados, eventos de S3).

Cuándo NO usarlo

  • Para migrar un volumen grande de datos propios: DataSync.
  • Para dar a las aplicaciones locales acceso NFS (Network File System: protocolo para compartir ficheros en red) o SMB (Server Message Block: protocolo de ficheros compartidos de Windows) a S3: Storage Gateway.
  • Si los clientes pueden usar la API (Application Programming Interface: interfaz para que los programas se comuniquen) de S3 o URL (Uniform Resource Locator: dirección web) prefirmadas, quizá no necesitas un servidor de protocolo.

Modelo de precios

Se paga por hora de cada protocolo activado en un servidor (aunque no se use) y por gigabyte subido o descargado. Los conectores, AS2 y las aplicaciones web tienen sus propios cargos.

Seguridad y alta disponibilidad

  • SFTP y FTPS cifran en tránsito; FTP no, por eso solo se permite dentro de una VPC.
  • Permisos mínimos por usuario con roles de IAM y políticas de alcance reducido.
  • Grupos de seguridad en los puntos de enlace de VPC; WAF (Web Application Firewall) si el proveedor de identidad usa API Gateway.
  • Servicio de alta disponibilidad repartido en varias AZ (Availability Zone: zona de disponibilidad).
  • Registros en CloudWatch y CloudTrail.

Trampas de examen

  • "Los socios solo pueden usar SFTP" y "guardar en S3 sin servidores": Transfer Family.
  • "IP fijas para el cortafuegos del socio": punto de enlace de VPC con IP elásticas.
  • "Autenticar contra el directorio corporativo": Managed Microsoft AD o proveedor de identidad propio con Lambda.
  • "Procesar cada fichero al llegar": flujos gestionados o eventos de S3.
  • "EDI": AS2.
  • "FTP sin cifrar desde internet": no se permite; usa SFTP o FTPS.
