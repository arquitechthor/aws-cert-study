Amazon Inspector

En una frase: Escanea instancias, imágenes de contenedor y funciones en busca de CVE (Common Vulnerabilities and Exposures: catálogo público de vulnerabilidades conocidas) y exposición
Categoría: Seguridad, identidad y cumplimiento (Security, Identity, and Compliance)
Certificaciones: SAA-C03 SAP-C02 AIF-C01 CLF-C02
Documentación oficial: Documentación de Amazon Inspector ↗

Qué es

Amazon Inspector es el servicio de gestión de vulnerabilidades de AWS. Descubre automáticamente tus cargas de trabajo y las analiza de forma continua en busca de vulnerabilidades de software conocidas (CVE) y de exposición de red no intencionada. No hay que programar análisis: vuelve a revisar cuando cambia el recurso o cuando se publica una vulnerabilidad nueva.

Conceptos clave

  • Qué analiza:
    • Instancias de EC2 (Elastic Compute Cloud): paquetes del sistema operativo y de lenguajes de programación, y accesibilidad desde la red.
    • Imágenes de contenedor en ECR (Elastic Container Registry): al subirlas y de forma continua después (el análisis mejorado de ECR).
    • Funciones Lambda: las dependencias del paquete y, con el análisis de código, el código propio.
    • Repositorios de código (Code Security): código propio, dependencias de terceros e infraestructura como código.
  • Con o sin agente en EC2: usa el agente de Systems Manager si la instancia está gestionada; si no, el análisis sin agente examina instantáneas de sus volúmenes de EBS (Elastic Block Store). Por defecto combina los dos.
  • Hallazgos (findings): cada vulnerabilidad detectada, con su gravedad, el recurso afectado y cómo corregirla.
  • Puntuación de riesgo de Inspector: ajusta la gravedad genérica de la CVE al contexto del recurso, por ejemplo si es accesible desde internet, para priorizar.
  • Reglas de supresión: ocultan los hallazgos que has decidido aceptar.
  • Varias cuentas: con AWS Organizations, un administrador delegado activa y gestiona Inspector en todas las cuentas.
  • Integraciones: los hallazgos van a Security Hub y a EventBridge, para avisar o corregir automáticamente.
  • Inventario de software (SBOM): exporta la lista de componentes de los recursos analizados.
  • Análisis CIS (Center for Internet Security: organización que publica referencias de configuración segura): evalúa la configuración del sistema operativo de las instancias frente a las referencias del CIS.

Casos de uso típicos

  • Saber qué instancias, imágenes y funciones están afectadas cuando se publica una vulnerabilidad grave.
  • Impedir que lleguen a producción imágenes de contenedor con vulnerabilidades críticas, en el pipeline.
  • Priorizar los parches por riesgo real y lanzar el parcheo con Systems Manager.
  • Cumplir requisitos de gestión de vulnerabilidades (PCI DSS (Payment Card Industry Data Security Standard: norma de seguridad para datos de tarjetas) y otros).

Cuándo NO usarlo

  • Para detectar amenazas activas y comportamiento malicioso: GuardDuty.
  • Para encontrar datos sensibles en S3 (Simple Storage Service): Macie.
  • Para evaluar la configuración de los recursos de AWS frente a reglas: AWS Config.
  • Para aplicar los parches: Patch Manager de Systems Manager. Inspector detecta, no corrige.
  • Para proteger frente a ataques web: WAF (Web Application Firewall) y Shield.

Modelo de precios

Se paga según lo que se analiza: por instancia de EC2 analizada al mes, por imagen de contenedor analizada (al subirla y en cada nuevo análisis), por función Lambda al mes y por el análisis de código. Hay un periodo de prueba gratuito al activarlo.

Seguridad y alta disponibilidad

  • Usa roles vinculados al servicio; no necesita credenciales dentro de las instancias.
  • Es un servicio regional: hay que activarlo en cada región que se use.
  • El análisis es continuo y automático; no hay ventanas de análisis que gestionar.
  • Los hallazgos se cierran solos cuando se corrige la vulnerabilidad.

Trampas de examen

  • "Vulnerabilidades de software", "CVE" o "exposición de red" en EC2, contenedores o Lambda: Inspector.
  • "Analizar las imágenes de contenedor al subirlas al registro": Inspector con ECR.
  • "Amenazas", "comportamiento anómalo", "minería de criptomonedas": GuardDuty, no Inspector.
  • "Datos personales en S3": Macie.
  • Inspector detecta; Patch Manager parchea.
  • "Sin instalar agentes": análisis sin agente, a partir de instantáneas de EBS.
