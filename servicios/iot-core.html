AWS IoT Core

En una frase: Conecta millones de dispositivos por MQTT (Message Queuing Telemetry Transport: protocolo ligero de mensajería para dispositivos) y enruta sus mensajes con reglas
Categoría: Internet de las cosas (IoT) (Internet of Things (IoT))
Certificaciones: CLF-C02 SAP-C02
Documentación oficial: Documentación de AWS IoT Core ↗

Qué es

AWS IoT Core es el servicio central de IoT (Internet of Things: internet de las cosas: dispositivos conectados) de AWS. Permite que miles de millones de dispositivos se conecten de forma segura y publiquen o reciban mensajes mediante un agente de mensajes (MQTT, MQTT sobre WebSocket o HTTPS (HTTP Secure: HTTP cifrado con TLS)). Con el motor de reglas, los mensajes se filtran, transforman y envían a otros servicios de AWS sin escribir servidores.

Conceptos clave

  • Agente de mensajes: modelo publicación-suscripción por temas MQTT.
  • Identidad de los dispositivos: certificados X.509 por dispositivo y políticas de IoT que indican qué temas puede usar cada uno.
  • Registro: inventario de "cosas" (dispositivos) con sus atributos.
  • Sombra del dispositivo (device shadow): documento JSON (JavaScript Object Notation: formato de datos en texto) con el estado notificado y el deseado; las aplicaciones lo leen y lo cambian aunque el dispositivo esté desconectado.
  • Motor de reglas: consultas tipo SQL (Structured Query Language: lenguaje de consultas de bases de datos relacionales) sobre los mensajes con acciones hacia Lambda, DynamoDB, S3 (Simple Storage Service), Kinesis, Data Firehose, SNS (Simple Notification Service), SQS (Simple Queue Service), Timestream o IoT SiteWise.
  • Aprovisionamiento de flotas: los dispositivos obtienen su certificado la primera vez que se conectan.
  • IoT Core for LoRaWAN (Long Range Wide Area Network: red inalámbrica de largo alcance y bajo consumo para sensores) para dispositivos inalámbricos de largo alcance y bajo consumo.

Casos de uso típicos

  • Telemetría de sensores enviada a un lago de datos o a paneles.
  • Control remoto de dispositivos (por ejemplo, encender o apagar un equipo) con la sombra.
  • Productos de consumo conectados (electrodomésticos, wearables).

Cuándo NO usarlo

  • Para procesar datos en el propio dispositivo o en el borde sin conexión: IoT Greengrass.
  • Para datos industriales con modelos de equipos y plantas: IoT SiteWise.
  • Para mensajería entre aplicaciones (no dispositivos): SQS, SNS o EventBridge.

Modelo de precios

Se paga por minutos de conexión, mensajes, operaciones de sombra y registro, y reglas ejecutadas y acciones. No hay cuota mínima.

Seguridad y alta disponibilidad

  • TLS (Transport Layer Security: cifrado de las conexiones) en todas las conexiones y autenticación mutua con certificados X.509.
  • Políticas de IoT por dispositivo con mínimo privilegio (por ejemplo, cada uno solo en su tema).
  • Servicio regional gestionado y escalable; la sombra guarda el estado durante las desconexiones.

Trampas de examen

  • "Miles de sensores con MQTT": IoT Core.
  • "Enviar los datos de los dispositivos a DynamoDB o Kinesis sin servidores": motor de reglas.
  • "Cambiar el estado de un dispositivo desconectado": sombra del dispositivo.
  • "Autenticar cada dispositivo": certificados X.509 y políticas de IoT.
  • "Procesar sin conexión en el borde": Greengrass.
