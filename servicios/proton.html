AWS Proton

En una frase: El equipo de plataforma define entornos y servicios con su pipeline y los demás los usan
Categoría: Administración y gobernanza (Management and Governance)
Certificaciones: SAP-C02
Documentación oficial: Documentación de AWS Proton ↗
Aviso: AWS retira Proton. No admite clientes nuevos desde el 07/10/2025 y el 07/10/2026 termina el soporte: a partir de ese día ya no se puede entrar en la consola ni en los recursos de Proton, y sus datos se borran. La infraestructura ya desplegada (las pilas de CloudFormation y sus recursos) sigue funcionando; lo que desaparece son las plantillas, los pipelines y el propio servicio. AWS propone como alternativas la sincronización con Git de CloudFormation (Git sync), CodePipeline con CodeBuild, GitHub Actions o el portal de desarrolladores Harmonix on AWS (basado en Backstage). Sigue en la guía de SAP-C02, que se puede presentar hasta el 17/11/2026, así que conviene saber qué problema resolvía.

Qué es

AWS Proton es un servicio de ingeniería de plataforma: el equipo de plataforma define, como infraestructura como código, plantillas aprobadas de entornos y de servicios, y los equipos de desarrollo las usan en autoservicio para desplegar sus aplicaciones (contenedores o sin servidor) sin escribir la infraestructura ni el pipeline. El desarrollador solo rellena unos parámetros; Proton aprovisiona los recursos, crea el pipeline de CI/CD (Continuous Integration / Continuous Delivery: integración y entrega continuas) y avisa cuando una plantilla tiene una versión nueva.

Conceptos clave

  • Dos papeles: el equipo de plataforma (administradores) crea y versiona las plantillas; los desarrolladores eligen una plantilla y despliegan.
  • Plantilla de entorno: la infraestructura compartida por varias aplicaciones: red (VPC (Virtual Private Cloud)), clúster, roles… Un entorno es una plantilla de entorno desplegada con unos parámetros concretos (por ejemplo desarrollo, preproducción y producción).
  • Plantilla de servicio: la infraestructura de una aplicación o microservicio (por ejemplo un servicio de Fargate detrás de un balanceador, o una función Lambda con su API (Application Programming Interface: interfaz para que los programas se comuniquen)) y, opcionalmente, su pipeline. Cada plantilla de servicio declara con qué plantillas de entorno es compatible.
  • Servicio e instancias de servicio: un servicio es una plantilla de servicio instanciada; cada instancia de servicio es ese servicio desplegado en un entorno concreto. Las instancias se despliegan dentro de los entornos.
  • Paquete de plantilla (template bundle): los ficheros de IaC (Infrastructure as Code: infraestructura como código) y el esquema de sus parámetros. Se sube desde un bucket de S3 (Simple Storage Service) o se sincroniza desde un repositorio Git.
  • Versiones: las plantillas tienen versión mayor y menor. Cuando el equipo de plataforma publica una versión, Proton muestra qué entornos e instancias se han quedado atrás para actualizarlos.
  • Proveedores de IaC: CloudFormation (lo aprovisiona Proton) o Terraform (Proton abre una pull request en tu repositorio y el despliegue lo ejecuta tu propia automatización).
  • Componentes: recursos adicionales que un desarrollador puede añadir a una instancia de servicio (una cola, un bucket) si la plantilla lo permite, sin cambiar la plantilla.
  • Conexiones de cuenta de entorno: permiten gestionar desde una cuenta los entornos que viven en otras cuentas.

Casos de uso típicos

  • Dar a muchos equipos de desarrollo un autoservicio con barreras: despliegan solos, pero solo arquitecturas aprobadas.
  • Estandarizar microservicios en contenedores (ECS (Elastic Container Service), Fargate) o sin servidor (Lambda) con su pipeline incluido.
  • Propagar una mejora (un parche de seguridad en la plantilla) a todos los servicios que la usan.

Cuándo NO usarlo

  • En proyectos nuevos: el servicio está en retirada; usa las alternativas del aviso.
  • Para ofrecer un catálogo de productos aprobados de cualquier tipo (no solo aplicaciones con pipeline): Service Catalog.
  • Para desplegar la misma plantilla en muchas cuentas y regiones: CloudFormation StackSets.
  • Para una sola aplicación web sin equipo de plataforma: Elastic Beanstalk o App Runner.

Modelo de precios

Proton no tiene coste propio: se pagan los recursos que aprovisionan las plantillas (cómputo, redes, bases de datos, ejecuciones de pipeline) al precio de cada servicio.

Seguridad y alta disponibilidad

  • Proton aprovisiona con un rol de servicio de IAM (Identity and Access Management) por entorno, así que los desarrolladores no necesitan permisos directos sobre la infraestructura: basta con permiso para usar Proton.
  • Las plantillas son el punto de control: lo que no esté en una plantilla aprobada no se puede desplegar.
  • La disponibilidad de las aplicaciones depende de lo que definan las plantillas (varias AZ (Availability Zone: zona de disponibilidad), escalado), no de Proton, que solo interviene al desplegar.

Trampas de examen

  • "Equipo de plataforma" + "plantillas estandarizadas" + "autoservicio para desarrolladores" + "contenedores o sin servidor": Proton.
  • Entorno frente a servicio: el entorno es lo compartido (red, clúster); el servicio es la aplicación, que se despliega dentro de un entorno.
  • Si el enunciado habla de un catálogo de productos con restricciones de lanzamiento y sin pipeline, es Service Catalog.
  • Fuera del examen, recuerda que el servicio se retira el 07/10/2026: no lo propongas en diseños reales.
