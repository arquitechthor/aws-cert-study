AWS DMS

AWS Database Migration Service (AWS DMS)

En una frase: Migra bases de datos con la de origen en marcha y replica los cambios hasta el corte
Categoría: Migración y transferencia (Migration and Transfer)
Certificaciones: CLF-C02 SAA-C03 SAP-C02
Documentación oficial: Documentación de AWS DMS ↗

Qué es

AWS Database Migration Service (DMS) copia datos de una base de datos de origen a un destino mientras el origen sigue funcionando. Hace una carga completa inicial y después replica los cambios que se producen, lo que se conoce como CDC (Change Data Capture: captura de los cambios de una base de datos para replicarlos), de modo que el corte final dura minutos. Sirve entre motores iguales (homogénea, por ejemplo de Oracle a Oracle) o distintos (heterogénea, por ejemplo de Oracle a PostgreSQL); en este último caso, el esquema y el código se convierten antes con DMS Schema Conversion o con SCT (Schema Conversion Tool).

Conceptos clave

  • Instancia de replicación: instancia gestionada que ejecuta las tareas; se elige su tamaño y puede ser Multi-AZ. Alternativa: DMS Serverless, que ajusta la capacidad sola.
  • Puntos de enlace: la conexión al origen y al destino. Además de bases de datos, el destino puede ser S3 (Simple Storage Service), DynamoDB, Redshift, OpenSearch Service o Kinesis Data Streams.
  • Tareas: tres tipos de migración: solo carga completa, carga completa más CDC, o solo CDC.
  • CDC: lee los registros de transacciones del origen (por ejemplo, el binlog de MySQL), por lo que suele requerir configurarlos. No es replicación en tiempo real ni tiene SLA (Service Level Agreement: compromiso de disponibilidad) de latencia.
  • Reglas de selección y transformación: qué tablas migrar y cambios sencillos de nombres o columnas.
  • Validación de datos: compara filas de origen y destino.
  • Migraciones homogéneas: para algunos motores, DMS usa las herramientas nativas del motor.
  • DMS Schema Conversion: conversión de esquemas y código dentro de la consola de DMS, con ayuda de IA (inteligencia artificial) generativa para el código difícil.

Casos de uso típicos

  • Migrar una base de datos local a RDS (Relational Database Service) o Aurora con una parada mínima.
  • Cambiar de motor comercial a uno de código abierto (con conversión de esquema).
  • Replicación continua hacia un lago de datos en S3 o un almacén en Redshift.
  • Consolidar varias bases de datos en una.

Cuándo NO usarlo

  • Para convertir el esquema, procedimientos y funciones entre motores: DMS no lo hace en sus tareas de datos; hace falta DMS Schema Conversion o SCT.
  • Para migrar servidores completos (sistema operativo y aplicación): Application Migration Service.
  • Para replicación continua de baja latencia y bidireccional en producción, valora la replicación nativa del motor.
  • Si la base de datos ya está en Aurora y solo necesitas otra región: base de datos global de Aurora.

Modelo de precios

Con instancias de replicación se paga por hora de instancia (según tamaño y si es Multi-AZ) y por su almacenamiento. Con DMS Serverless se paga por la capacidad usada por hora. La transferencia de datos de entrada a AWS no se cobra.

Seguridad y alta disponibilidad

  • Cifrado en reposo con KMS (Key Management Service) y TLS (Transport Layer Security: cifrado de las conexiones) en las conexiones a los puntos de enlace.
  • Credenciales de las bases de datos en Secrets Manager.
  • Instancia de replicación Multi-AZ para que la tarea siga si cae una AZ (Availability Zone: zona de disponibilidad).
  • La instancia de replicación vive en tu VPC (Virtual Private Cloud); el origen local se alcanza por VPN (Virtual Private Network: red privada virtual) o Direct Connect.

Trampas de examen

  • "Migrar con el mínimo tiempo de parada": DMS con carga completa más CDC.
  • "Oracle a Aurora PostgreSQL": primero SCT o DMS Schema Conversion (esquema), después DMS (datos).
  • "Mismo motor": no hace falta convertir el esquema.
  • "Base de datos de muchos terabytes y poca red": carga inicial por otro medio y CDC con DMS.
  • "Replicar cambios hacia S3 o Kinesis": DMS admite esos destinos.
  • "Sin gestionar la capacidad de la instancia de replicación": DMS Serverless.
