AWS CloudHSM

En una frase: Módulos de hardware dedicados de un solo cliente para guardar tus claves criptográficas
Categoría: Seguridad, identidad y cumplimiento (Security, Identity, and Compliance)
Certificaciones: SAA-C03 SAP-C02 CLF-C02
Documentación oficial: Documentación de AWS CloudHSM ↗

Qué es

AWS CloudHSM proporciona módulos de seguridad de hardware (HSM) en la nube dedicados a un solo cliente. Un HSM es un dispositivo físico que genera y guarda claves criptográficas y hace operaciones con ellas sin que las claves salgan de él. Con CloudHSM, solo tú tienes acceso a las claves: AWS gestiona el hardware, pero no puede verlas ni usarlas. Es la opción cuando una norma o un contrato exige HSM de uso exclusivo.

Conceptos clave

  • Un solo inquilino (single-tenant): el HSM no se comparte con otros clientes, a diferencia de KMS (Key Management Service), que usa HSM compartidos.
  • FIPS (Federal Information Processing Standards: normas de seguridad del gobierno de EE. UU.) 140 nivel 3: los HSM están validados en ese nivel (140-2 o 140-3) cuando el clúster funciona en modo FIPS. También hay un modo no FIPS con más algoritmos.
  • Clúster: un conjunto de HSM sincronizados. Para alta disponibilidad se colocan al menos dos HSM en distintas AZ (Availability Zone: zona de disponibilidad); CloudHSM replica las claves entre ellos.
  • Dentro de tu VPC (Virtual Private Cloud): cada HSM tiene una interfaz de red en una subred tuya.
  • Usuarios del HSM: los gestionas tú dentro del propio HSM, fuera de IAM (Identity and Access Management). IAM solo controla quién puede crear o borrar clústeres. Si pierdes las credenciales de los usuarios del HSM, AWS no puede recuperarlas.
  • Interfaces estándar: PKCS (Public-Key Cryptography Standards: estándares de criptografía de clave pública) #11, JCE (Java Cryptography Extension: interfaz criptográfica de Java), CNG y KSP, y OpenSSL, lo que facilita migrar aplicaciones que ya usaban un HSM.
  • Copias de seguridad: automáticas y cifradas; se pueden copiar a otra región.
  • Almacén de claves personalizado de KMS: KMS puede usar un clúster de CloudHSM para guardar el material de sus claves. Así usas las integraciones de KMS con los servicios de AWS, pero las claves viven en tus HSM.
  • Claves simétricas y asimétricas, y posibilidad de exportarlas si lo decides.

Casos de uso típicos

  • Requisitos normativos o contractuales de HSM dedicado y validación FIPS 140 nivel 3.
  • Descarga de TLS (Transport Layer Security: cifrado de las conexiones): la clave privada del servidor web se queda en el HSM.
  • Clave privada de una autoridad de certificación propia.
  • Cifrado transparente de datos de bases de datos Oracle.
  • Firma de código o de documentos, y migración de aplicaciones que usaban un HSM local.

Cuándo NO usarlo

  • Para cifrar datos en los servicios de AWS sin requisitos especiales: KMS, más sencillo, más barato e integrado.
  • Para certificados TLS públicos gestionados: ACM (AWS Certificate Manager).
  • Para guardar contraseñas o secretos de aplicaciones: Secrets Manager.
  • Si no hay equipo para operar HSM (usuarios, copias, capacidad): la responsabilidad es mayor que en KMS.

Modelo de precios

Se paga por hora de cada HSM en ejecución, sin compromiso. Un clúster con alta disponibilidad necesita al menos dos, así que el coste fijo es notablemente mayor que el de KMS.

Seguridad y alta disponibilidad

  • AWS vigila la salud del hardware y la red, pero no tiene acceso a tus claves.
  • La comunicación entre la aplicación y el HSM va cifrada de extremo a extremo.
  • Con dos o más HSM en distintas AZ, el cliente reparte la carga y sigue funcionando si cae uno.
  • Con un solo HSM, si falla, las claves creadas desde la última copia se pierden.
  • Las llamadas de gestión quedan en CloudTrail; las operaciones dentro del HSM, en los registros de auditoría del HSM (CloudWatch Logs).

Trampas de examen

  • "HSM dedicado", "de un solo inquilino" o "control exclusivo de las claves": CloudHSM.
  • "FIPS 140 nivel 3": CloudHSM.
  • "Usar esas claves con los servicios de AWS": almacén de claves personalizado de KMS respaldado por CloudHSM.
  • "Menor esfuerzo operativo para cifrar", sin requisitos de HSM dedicado: KMS.
  • "Alta disponibilidad": HSM en al menos dos AZ.
  • "Descargar el TLS manteniendo la clave privada en hardware": CloudHSM.
