AWS Client VPN

En una frase: Da a empleados en remoto un túnel cifrado desde su portátil hasta tus redes privadas
Categoría: Redes y entrega de contenido (Networking and Content Delivery)
Certificaciones: CLF-C02 SAA-C03 SAP-C02
Documentación oficial: Documentación de AWS Client VPN ↗

Qué es

AWS Client VPN (Virtual Private Network: red privada virtual) es una VPN de acceso remoto gestionada: los empleados instalan un cliente compatible con OpenVPN en su portátil y abren un túnel cifrado (TLS) hasta un punto de enlace de Client VPN en AWS. Desde ahí acceden a las VPC (Virtual Private Cloud), a otras VPC conectadas, a la red local o a internet, según las reglas que definas. AWS escala el servicio según el número de usuarios.

Conceptos clave

  • Punto de enlace de Client VPN: el recurso al que se conectan los clientes. Necesita un certificado de servidor en ACM (AWS Certificate Manager) y un rango CIDR (Classless Inter-Domain Routing: notación de rangos de IP como 10.0.0.0/16) para los clientes que no se solape con la VPC.
  • Redes de destino: subredes de una VPC asociadas al punto de enlace; cada asociación crea interfaces de red y tiene coste. Asocia subredes de varias AZ (Availability Zone: zona de disponibilidad) para alta disponibilidad.
  • Autenticación: mutua con certificados, Active Directory (con Directory Service) o federada con SAML (inicio de sesión único, por ejemplo con IAM Identity Center u otro proveedor). Se puede combinar la mutua con una de usuario.
  • Reglas de autorización: qué redes puede alcanzar cada usuario o grupo (del directorio o del proveedor SAML).
  • Tabla de rutas del punto de enlace: hacia dónde se envía el tráfico (VPC, red local por VPN o Direct Connect, internet).
  • Túnel dividido (split tunnel): solo el tráfico hacia AWS va por la VPN; el resto sale por la conexión local del usuario.
  • Registros y controlador de conexión: registros de conexión en CloudWatch Logs y una función Lambda opcional que valida cada conexión (por ejemplo, el estado del dispositivo).

Casos de uso típicos

  • Teletrabajo: acceso seguro a aplicaciones internas en VPC.
  • Acceso a la red local a través de AWS cuando la VPC ya está conectada al centro de datos.
  • Acceso temporal de terceros o proveedores con reglas de autorización limitadas.

Cuándo NO usarlo

  • Para conectar una sede o un centro de datos entero: Site-to-Site VPN.
  • Para dar acceso a aplicaciones web internas sin VPN, con políticas de confianza cero por usuario y dispositivo: AWS Verified Access.
  • Para administrar instancias sin abrir puertos ni usar VPN: Session Manager de Systems Manager.
  • Para dar un escritorio completo en la nube: WorkSpaces.

Modelo de precios

Se paga por hora de cada asociación de subred al punto de enlace y por hora de cada conexión de cliente activa, además de la transferencia de datos.

Seguridad y alta disponibilidad

  • Cifrado TLS de extremo a extremo entre el dispositivo y el punto de enlace.
  • MFA (Multi-Factor Authentication: inicio de sesión con un segundo factor) a través de Active Directory o del proveedor SAML.
  • Grupos de seguridad aplicados a las asociaciones, además de las reglas de autorización.
  • Alta disponibilidad: asocia subredes en al menos dos AZ.

Trampas de examen

  • "Empleados en remoto" o "desde su portátil": Client VPN.
  • "Conectar la oficina" o "el centro de datos": Site-to-Site VPN, no Client VPN.
  • "Que solo el tráfico hacia AWS vaya por la VPN": túnel dividido.
  • "Cada grupo de usuarios solo ve ciertas redes": reglas de autorización por grupo.
  • "Inicio de sesión único con el proveedor de identidad corporativo": autenticación federada con SAML.
  • "Sin VPN, acceso de confianza cero a aplicaciones web": Verified Access.
