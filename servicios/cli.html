AWS CLI

En una frase: Herramienta que instalas en tu equipo para controlar los servicios con comandos y scripts
Categoría: Administración y gobernanza (Management and Governance)
Certificaciones: SAA-C03 SAP-C02 CLF-C02 DVA-C02
Documentación oficial: Documentación de AWS CLI ↗

Qué es

La AWS CLI (Command Line Interface) es una herramienta de código abierto para manejar los servicios de AWS desde la terminal. Cada comando equivale a una llamada a la API (Application Programming Interface: interfaz para que los programas se comuniquen) de un servicio, firmada con tus credenciales. Sirve para trabajar más rápido que en la consola y, sobre todo, para automatizar con scripts. Es una de las tres formas de acceder a AWS, junto con la consola (en el navegador) y los SDK (desde el código).

Conceptos clave

  • Estructura de un comando: aws <servicio> <operación> [opciones], por ejemplo aws s3 ls o aws ec2 describe-instances.
  • Versión 2: la actual. Añade, entre otras cosas, el inicio de sesión con IAM (Identity and Access Management) Identity Center y el autocompletado interactivo.
  • Ficheros de configuración: ~/.aws/credentials (claves) y ~/.aws/config (región, formato de salida, roles). aws configure los rellena.
  • Perfiles con nombre: varios juegos de configuración; se elige con --profile o con la variable AWS_PROFILE. Un perfil puede asumir un rol (role_arn y source_profile) para trabajar en otra cuenta.
  • Orden de precedencia de credenciales y ajustes, de mayor a menor: opciones del comando, variables de entorno, rol asumido, IAM Identity Center, fichero de credenciales, fichero de configuración, credenciales del contenedor (rol de la tarea de ECS (Elastic Container Service)) y, por último, el perfil de instancia de EC2 (Elastic Compute Cloud).
  • Credenciales: lo recomendado son las temporales: aws sso login con IAM Identity Center en tu equipo, y roles en EC2, ECS o Lambda. Las claves de acceso de larga duración de un usuario de IAM son el último recurso.
  • Salida: --output json (por defecto), yaml, text o table.
  • Filtrado: --query filtra en tu equipo la respuesta con expresiones JMESPath; --filters (en los servicios que lo tienen) filtra en el servidor y reduce lo que se transfiere.
  • Paginación: la CLI pide automáticamente todas las páginas. --page-size reduce el tamaño de cada llamada (útil ante tiempos de espera agotados) y --max-items limita cuántos elementos se devuelven.
  • Comandos de alto nivel de S3 (Simple Storage Service): aws s3 cp, sync, mv… que usan la carga multiparte de forma automática.
  • Otras opciones útiles: --dry-run (en EC2, comprueba permisos sin ejecutar), --debug y --region.

Casos de uso típicos

  • Scripts de operación y tareas repetitivas (copias, limpieza de recursos, informes).
  • Pasos de un pipeline de CI/CD (Continuous Integration / Continuous Delivery: integración y entrega continuas).
  • Consultas rápidas y diagnóstico: ver qué devuelve exactamente una API.
  • Sincronizar carpetas con S3.

Cuándo NO usarlo

  • Para definir infraestructura repetible: CloudFormation o CDK. Un script de CLI no guarda estado ni revierte.
  • Dentro del código de una aplicación: el SDK del lenguaje.
  • Si no quieres instalar ni configurar nada en tu equipo: CloudShell, una terminal en el navegador con la CLI ya instalada y tus credenciales de la consola.
  • Para explorar un servicio por primera vez suele ser más cómoda la AWS Management Console.

Modelo de precios

La CLI es gratuita. Se pagan los recursos y las llamadas que generen sus comandos, al precio de cada servicio.

Seguridad y alta disponibilidad

  • Nunca guardes claves de acceso en una instancia de EC2: asocia un rol (perfil de instancia) y la CLI obtendrá credenciales temporales sola.
  • No subas el fichero de credenciales a un repositorio ni uses las claves del usuario raíz.
  • Si una política exige MFA, hay que pedir credenciales temporales con aws sts get-session-token (o asumir un rol con MFA) y usarlas en la CLI.
  • Cada comando queda registrado en CloudTrail como cualquier otra llamada a la API.
  • Un mensaje de error de autorización codificado se descifra con aws sts decode-authorization-message.

Trampas de examen

  • "Acceso programático" o "automatizar con scripts": CLI (o SDK). La consola es acceso interactivo.
  • La CLI en EC2 sin claves: rol de IAM en el perfil de instancia.
  • La CLI usa unas credenciales inesperadas: revisa la precedencia; las variables de entorno ganan a los ficheros.
  • Un listado enorme agota el tiempo de espera: --page-size más pequeño.
  • "Reducir los datos devueltos por la API": filtro en el servidor (--filters). --query solo recorta lo que se muestra.
  • "Comprobar si tengo permiso sin ejecutar la acción": --dry-run.
