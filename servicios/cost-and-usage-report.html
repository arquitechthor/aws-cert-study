AWS Cost and Usage Report

En una frase: Exporta el detalle más fino de facturación, línea a línea, a S3 (Simple Storage Service) para analizarlo
Categoría: Administración financiera en la nube (Cloud Financial Management)
Certificaciones: CLF-C02 SAA-C03 SAP-C02
Documentación oficial: Documentación de AWS Cost and Usage Report ↗

Qué es

AWS Cost and Usage Report (CUR) es el conjunto de datos de facturación más completo de AWS. Contiene cada línea de uso y coste, con granularidad horaria, diaria o mensual, por recurso, con etiquetas de asignación de costes, descuentos, Savings Plans y reservas. Se entrega en un bucket de S3 varias veces al día para analizarlo con Athena, Redshift o Quick Sight. Hoy se crea como CUR 2.0 desde AWS Data Exports.

Conceptos clave

  • CUR 2.0 (Data Exports): esquema fijo, columnas anidadas (etiquetas, categorías de coste), selección de columnas y filtros con SQL (Structured Query Language: lenguaje de consultas de bases de datos relacionales) básico, y columnas extra como el nombre de la cuenta. Sustituye al CUR heredado, que tiene un esquema que cambia según el uso.
  • Granularidad e IDs de recurso: se puede pedir por hora e incluir el ID de cada recurso.
  • Formatos: Parquet (recomendado para consultas) o CSV (Comma-Separated Values: texto con valores separados por comas) comprimido.
  • Integración con Athena y Redshift: la exportación incluye lo necesario para crear las tablas y mantenerlas al día.
  • Organizaciones: desde la cuenta de administración se obtienen los costes de todas las cuentas.
  • Etiquetas de asignación de costes: hay que activarlas en Billing para que aparezcan.
  • Otras exportaciones: Data Exports también ofrece el formato abierto FOCUS (FinOps Open Cost and Usage Specification: formato abierto para datos de facturación en la nube) y datos de recomendaciones de optimización.

Casos de uso típicos

  • Repercutir costes a departamentos o clientes (chargeback) por etiquetas o cuentas.
  • Análisis detallado del uso de Savings Plans y reservas.
  • Paneles de costes propios (por ejemplo, Cloud Intelligence Dashboards).
  • Integrar la facturación con herramientas financieras externas.

Cuándo NO usarlo

  • Para ver gráficos y tendencias rápidamente sin montar nada: Cost Explorer.
  • Para recibir avisos al superar un gasto: Budgets.
  • Para detectar gastos anómalos automáticamente: Cost Anomaly Detection.

Modelo de precios

El informe no tiene coste; se paga el almacenamiento en S3 y las consultas que hagas (Athena, Redshift, Quick).

Seguridad y alta disponibilidad

  • El bucket de destino necesita una política que permita escribir al servicio de facturación.
  • Limita quién lee el bucket: contiene información financiera de toda la organización.
  • Cifrado del bucket con SSE-S3 (Server-Side Encryption with S3 managed keys: cifrado en el servidor con claves que gestiona S3) o SSE-KMS (Server-Side Encryption with KMS keys: cifrado en el servidor con claves de KMS).
  • Se puede pedir que AWS rellene datos de meses anteriores.

Trampas de examen

  • "El nivel de detalle más fino", "por hora y por recurso": Cost and Usage Report.
  • "Consultar los costes con SQL": CUR en S3 y Athena.
  • "Costes por proyecto": etiquetas de asignación de costes activadas, y CUR o Cost Explorer.
  • "Ver tendencias rápidamente": Cost Explorer, no CUR.
  • "Aviso al pasar de un importe": Budgets.
  • "Costes de todas las cuentas": CUR desde la cuenta de administración de la organización.
