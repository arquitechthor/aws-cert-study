AWS Site-to-Site VPN

En una frase: Túnel IPsec (Internet Protocol Security: cifrado de los paquetes IP en una VPN) cifrado sobre Internet entre tu red local y tus redes privadas en AWS
Categoría: Redes y entrega de contenido (Networking and Content Delivery)
Certificaciones: CLF-C02 SAA-C03 SAP-C02
Documentación oficial: Documentación de AWS Site-to-Site VPN ↗

Qué es

AWS Site-to-Site VPN (Virtual Private Network: red privada virtual) crea una conexión cifrada con IPsec entre tu red local (una sede o un centro de datos) y tus redes en AWS, a través de internet. Se configura en minutos y cada conexión trae dos túneles en equipos distintos de AWS para que la caída de uno no corte el servicio.

Conceptos clave

  • Puerta de enlace de cliente (customer gateway): el recurso que representa tu router o cortafuegos local (su IP (Internet Protocol: dirección de red) pública y, si usa BGP (Border Gateway Protocol: protocolo con el que los routers se anuncian las redes), su ASN (Autonomous System Number: número que identifica una red en BGP)).
  • Lado de AWS: la conexión termina en una puerta de enlace privada virtual (una sola VPC (Virtual Private Cloud)), en un Transit Gateway (muchas VPC) o en Cloud WAN (Wide Area Network: red de área extensa).
  • Dos túneles por conexión: conviene configurar ambos en tu equipo; AWS hace mantenimiento en uno mientras el otro sigue activo.
  • Enrutamiento estático o dinámico: rutas estáticas o BGP, que anuncia las redes y conmuta solo entre túneles.
  • Ancho de banda: hasta 1,25 Gbps por túnel estándar. Los túneles de gran ancho de banda llegan a 5 Gbps, solo con Transit Gateway o Cloud WAN. Con Transit Gateway y BGP, ECMP (Equal-Cost Multi-Path: reparte el tráfico entre varias rutas iguales) suma varios túneles.
  • VPN acelerada: el tráfico entra en la red de AWS por la ubicación de borde más cercana gracias a Global Accelerator. Solo con Transit Gateway.
  • VPN sobre Direct Connect: túneles IPsec que viajan por Direct Connect para cifrar ese enlace (también con IP privadas).
  • VPN CloudHub: varias sedes conectadas a la misma puerta de enlace privada virtual pueden comunicarse entre sí a través de AWS.

Casos de uso típicos

  • Conectar rápidamente una sede o un centro de datos con AWS.
  • Respaldo de una conexión Direct Connect.
  • Conexión temporal mientras llega Direct Connect.
  • Cifrar el tráfico que viaja por Direct Connect.

Cuándo NO usarlo

  • Si se necesita rendimiento constante o mucho ancho de banda de forma continua: Direct Connect.
  • Para que empleados individuales se conecten desde su portátil: Client VPN.
  • Para conectar dos VPC de AWS entre sí: emparejamiento de VPC o Transit Gateway.

Modelo de precios

Se paga por hora de cada conexión VPN y por la transferencia de datos de salida. La VPN acelerada añade los cargos de Global Accelerator, y con Transit Gateway se suman sus cargos por adjunto y procesamiento.

Seguridad y alta disponibilidad

  • Cifrado IPsec con IKEv1 (Internet Key Exchange version 1: negociación de claves de IPsec) o IKEv2 (Internet Key Exchange version 2: negociación de claves de IPsec); se pueden elegir algoritmos y usar certificados en lugar de claves precompartidas.
  • Dos túneles por conexión; para evitar que tu equipo sea el punto único de fallo, usa dos puertas de enlace de cliente con una conexión cada una.
  • BGP permite la conmutación automática entre túneles y con Direct Connect.
  • Métricas de estado de los túneles en CloudWatch.

Trampas de examen

  • "Conexión cifrada rápida con el centro de datos": Site-to-Site VPN.
  • "Respaldo de Direct Connect": Site-to-Site VPN.
  • "Más de 1,25 Gbps por VPN": ECMP con Transit Gateway y BGP, o túneles de gran ancho de banda.
  • "Mejorar la VPN desde sedes lejanas": VPN acelerada (con Transit Gateway).
  • "Cifrar Direct Connect": VPN sobre Direct Connect (o MACsec (Media Access Control Security: cifrado del enlace físico, en capa 2)).
  • "Empleados en remoto": Client VPN, no Site-to-Site.
