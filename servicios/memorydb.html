Amazon MemoryDB

En una frase: Base de datos en memoria compatible con Valkey y Redis, duradera con registro multi-AZ
Categoría: Base de datos (Database)
Certificaciones: SAP-C03
Documentación oficial: Documentación de Amazon MemoryDB ↗

Qué es

Amazon MemoryDB es una base de datos en memoria y duradera, compatible con Valkey y Redis OSS (Open Source Software: la versión de código abierto) (las mismas estructuras de datos, APIs y comandos). Guarda todos los datos en memoria, con lecturas en microsegundos y escrituras en pocos milisegundos, y además escribe cada cambio en un registro de transacciones distribuido en varias zonas de disponibilidad. Por eso puede ser la base de datos principal de una aplicación, no solo una caché delante de otra base de datos.

Conceptos clave

  • Clúster, particiones y nodos: los datos se reparten en particiones (shards); cada una tiene un nodo principal que escribe y réplicas de lectura en otras zonas.
  • Registro de transacciones multi-AZ: una escritura se confirma cuando queda guardada de forma duradera en varias zonas. Si cae el principal, una réplica toma el relevo sin perder datos confirmados.
  • Consistencia: lecturas del nodo principal con consistencia fuerte; las réplicas tienen consistencia eventual.
  • Instantáneas: copias del clúster para restaurar o crear clústeres nuevos (también a partir de una instantánea de ElastiCache).
  • Niveles de datos (data tiering): con ciertos tipos de nodo, los datos menos usados bajan a SSD (Solid-State Drive: disco de estado sólido) locales para guardar más datos por menos coste.
  • Búsqueda vectorial: guarda e indexa vectores de inserción (embeddings) para RAG (Retrieval-Augmented Generation: el modelo responde apoyándose en información recuperada de tus documentos), recomendaciones o detección de fraude con latencias de milisegundos, sin coste extra.
  • Control de acceso: usuarios y listas de control de acceso propias de Valkey y Redis OSS (ACL), además de IAM (Identity and Access Management) para administrar el servicio.

Casos de uso típicos

  • Base de datos principal de microservicios que necesitan latencia muy baja y no pueden perder datos: carritos, sesiones, perfiles de usuario, inventario.
  • Clasificaciones y contadores en tiempo real (juegos, votaciones) que deben sobrevivir a un fallo.
  • Sustituir la pareja "caché + base de datos" cuando los datos ya caben en memoria, simplificando la arquitectura.
  • Búsqueda vectorial en tiempo real para aplicaciones de IA (inteligencia artificial) generativa.

Cuándo NO usarlo

  • Para acelerar una base de datos existente (RDS (Relational Database Service), DynamoDB…) con una caché: ElastiCache, más barato para ese papel.
  • Para conjuntos de datos enormes que no caben en memoria de forma rentable o con consultas relacionales complejas: Aurora, RDS o DynamoDB.
  • Para lecturas en microsegundos sobre DynamoDB sin cambiar su API (Application Programming Interface: interfaz para que los programas se comuniquen): el acelerador de DynamoDB.

Modelo de precios

Se paga por hora de nodo según su tipo (con nodos reservados para ahorrar), por los GB escritos en el registro de transacciones, por el almacenamiento de instantáneas por encima del gratuito y por la transferencia de datos.

Seguridad y alta disponibilidad

  • Siempre dentro de una VPC (Virtual Private Cloud), con grupos de seguridad.
  • Cifrado en reposo con KMS (Key Management Service) (clave propia opcional) y en tránsito con TLS (Transport Layer Security: cifrado de las conexiones).
  • Autenticación de clientes con usuarios y ACL de Valkey o Redis OSS.
  • Réplicas en varias zonas y conmutación automática sin pérdida de escrituras confirmadas.

Trampas de examen

  • "Compatible con Redis, microsegundos y durable como base de datos principal": MemoryDB.
  • "Caché para reducir la carga de la base de datos": ElastiCache, no MemoryDB.
  • "Eliminar la caché y la base de datos aparte para simplificar": MemoryDB.
  • "No perder escrituras confirmadas si falla el nodo principal": registro de transacciones multi-AZ de MemoryDB.
  • "Búsqueda vectorial con la máxima velocidad": búsqueda vectorial de MemoryDB.
