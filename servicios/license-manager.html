AWS License Manager

En una frase: Controla cuántas licencias de software usas y evita excederlas o incumplirlas
Categoría: Administración y gobernanza (Management and Governance)
Certificaciones: SAA-C03 SAP-C02 CLF-C02
Documentación oficial: Documentación de AWS License Manager ↗

Qué es

AWS License Manager ayuda a gestionar las licencias de software de terceros (Microsoft, Oracle, SAP, IBM y otros) que usas en AWS y en tus centros de datos. Traduces las condiciones de tus contratos a reglas, y el servicio cuenta el consumo, avisa o impide lanzar recursos cuando se superaría el límite, y da una visión única para las auditorías. Su objetivo es evitar tanto pagar licencias de más como incumplir los contratos.

Conceptos clave

  • Licencias autogestionadas (antes configuraciones de licencia): las reglas de un contrato. Indican en qué se cuenta la licencia (vCPU, núcleos físicos, zócalos o instancias), cuántas tienes y si el límite es estricto.
  • Límite estricto o flexible: con el estricto (hard limit), el lanzamiento de una instancia que superaría el número de licencias se bloquea. Con el flexible, se permite y se avisa.
  • Reglas adicionales: tipo de alojamiento permitido (compartido, instancia dedicada o host dedicado), mínimos y máximos de vCPU o núcleos, y afinidad de la licencia a un host durante un número de días.
  • Asociación: las reglas se asocian a una AMI (Amazon Machine Image: plantilla con el sistema operativo para arrancar instancias), a una plantilla de lanzamiento o a una plantilla de CloudFormation, de modo que todo lo que se lance con ellas consume licencias.
  • Grupos de recursos de host: un conjunto de hosts dedicados de EC2 (Elastic Compute Cloud) que License Manager administra por ti (asigna, libera y recupera hosts), pensado para licencias ligadas al hardware en modelo BYOL (Bring Your Own License: usar tu propia licencia).
  • Descubrimiento: con el inventario de Systems Manager detecta qué software hay instalado, también en servidores locales, y lo cuenta.
  • Derechos gestionados (managed entitlements): licencias emitidas por un vendedor (por ejemplo, compradas en AWS Marketplace) que se distribuyen y se controlan entre las cuentas de la organización.
  • Suscripciones por usuario: software con licencia por usuario y mes en instancias de EC2, como Microsoft Office o Visual Studio.
  • Conversión de tipo de licencia: pasar una instancia de licencia incluida a BYOL, o al revés, sin volver a desplegarla.
  • Varias cuentas: se integra con AWS Organizations para compartir las reglas y ver el consumo de todas las cuentas.

Casos de uso típicos

  • Traer licencias propias al migrar a AWS (Windows Server, SQL Server, Oracle) y demostrar que se cumplen las condiciones.
  • Impedir que los equipos lancen más instancias de las que cubren las licencias.
  • Preparar una auditoría de un proveedor con informes de uso.
  • Gestionar hosts dedicados para software licenciado por núcleo o por zócalo.

Cuándo NO usarlo

  • Si usas instancias con licencia incluida, donde AWS factura la licencia: no hay nada que contar.
  • Para controlar qué productos pueden lanzar los usuarios: Service Catalog.
  • Para inventario general de recursos y cumplimiento de configuración: AWS Config.
  • Para comprar software: AWS Marketplace (License Manager gestiona después esas licencias).

Modelo de precios

License Manager no tiene coste adicional: se pagan los recursos que gestiona (instancias, hosts dedicados). Las suscripciones por usuario se facturan por usuario y mes según el producto.

Seguridad y alta disponibilidad

  • Usa roles vinculados al servicio; el acceso de los administradores se controla con IAM (Identity and Access Management).
  • El límite estricto es un control preventivo: evita el incumplimiento en el momento de lanzar, no después.
  • Los hosts dedicados dan visibilidad de zócalos y núcleos físicos, que es lo que exigen algunas licencias; las instancias dedicadas no.

Trampas de examen

  • "Evitar superar el número de licencias contratadas" o "cumplimiento de licencias de Oracle o Microsoft": License Manager.
  • "Impedir el lanzamiento" al llegar al límite: límite estricto.
  • "Licencias por núcleo físico o por zócalo" en BYOL: hosts dedicados, gestionados con un grupo de recursos de host.
  • "Visión del uso de licencias en varias cuentas y en servidores locales": License Manager con Organizations y el inventario de Systems Manager.
  • No es Service Catalog (catálogo de productos) ni Marketplace (compra).
