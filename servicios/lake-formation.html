AWS Lake Formation

En una frase: Gobierna permisos finos por tabla, columna y fila sobre tu lago de datos en S3 (Simple Storage Service)
Categoría: Análisis (Analytics)
Certificaciones: SAA-C03 SAP-C02 AIF-C01
Documentación oficial: Documentación de AWS Lake Formation ↗

Qué es

AWS Lake Formation sirve para gobernar y compartir un lago de datos guardado en S3. En lugar de repartir el acceso con políticas de bucket y de IAM (Identity and Access Management), objeto a objeto, se conceden permisos al estilo de una base de datos (GRANT y REVOKE) sobre las bases de datos, tablas y columnas del Glue Data Catalog, desde un único sitio. Los motores de análisis integrados aplican esos permisos al consultar.

Conceptos clave

  • Administrador del lago de datos: la identidad que concede permisos y registra ubicaciones.
  • Registro de ubicaciones: se registra la ruta de S3 en Lake Formation, con un rol que tiene acceso a ella. A partir de ahí, Lake Formation gestiona el acceso a esos datos.
  • Catálogo: usa el Glue Data Catalog; las tablas las crean, por ejemplo, los rastreadores de Glue.
  • Permisos finos: a nivel de base de datos, tabla, columna, fila y celda. Los de fila y celda se definen con filtros de datos.
  • Control de acceso basado en etiquetas LF (LF-tags): se clasifican los recursos del catálogo con etiquetas propias de Lake Formation (por ejemplo, Confidencialidad = alta) y se conceden permisos por etiqueta. Escala mucho mejor que conceder tabla a tabla.
  • Entrega de credenciales (credential vending): cuando un usuario autorizado consulta, Lake Formation entrega al motor credenciales temporales para leer de S3. El usuario no necesita permisos directos sobre el bucket.
  • Servicios integrados: Athena, Redshift Spectrum, EMR (Elastic MapReduce) y Glue aplican los permisos.
  • Uso compartido entre cuentas: bases de datos y tablas se comparten con otras cuentas, con OU (Organizational Unit: unidad organizativa de AWS Organizations) o con toda la organización (por debajo usa RAM (Resource Access Manager)), sin copiar los datos.
  • Modo de acceso híbrido: permite convivir con los permisos de IAM y S3 existentes mientras se adopta Lake Formation de forma gradual.
  • Formatos de tabla abiertos: admite tablas de Apache Iceberg, Hudi y Delta Lake.

Casos de uso típicos

  • Que el equipo de marketing vea la tabla de clientes sin las columnas de datos personales.
  • Que cada delegación vea solo las filas de su país.
  • Malla de datos (data mesh): cuentas productoras comparten tablas con cuentas consumidoras bajo un gobierno central.
  • Auditar quién ha accedido a qué datos.
  • Controlar qué datos pueden usar los equipos de ciencia de datos para entrenar modelos.

Cuándo NO usarlo

  • Para transformar o cargar datos: Glue.
  • Para consultar: Athena, Redshift o EMR. Lake Formation gobierna, no consulta.
  • Para descubrir datos sensibles en S3: Macie.
  • Para controlar el acceso a objetos de S3 que no son tablas (ficheros sueltos de una aplicación): políticas de bucket e IAM.
  • Para un catálogo de datos orientado al negocio con flujos de solicitud de acceso: Amazon DataZone.

Modelo de precios

Lake Formation no tiene coste propio por la gestión de permisos. Se pagan los servicios que intervienen: S3, Glue, Athena, y el filtrado de datos que realice el servicio en algunas integraciones.

Seguridad y alta disponibilidad

  • Para que Lake Formation mande de verdad, hay que quitar el acceso directo a los datos: los usuarios no deben tener permisos de S3 sobre las ubicaciones registradas.
  • Los permisos de Lake Formation se suman a los de IAM: hacen falta ambos.
  • Todos los accesos quedan registrados en CloudTrail, con la identidad que consultó.
  • Los datos siguen en S3, con su durabilidad y su cifrado.

Trampas de examen

  • "Control de acceso a nivel de columna o de fila sobre datos en S3": Lake Formation.
  • "Gobierno centralizado del lago de datos" o "compartir tablas entre cuentas sin copiar": Lake Formation.
  • "Gestionar permisos a escala para cientos de tablas": etiquetas LF.
  • Glue cataloga y transforma; Lake Formation autoriza; Athena consulta. Suelen aparecer juntos.
  • Las políticas de bucket no llegan a columnas ni a filas.
