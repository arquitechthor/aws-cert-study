AWS Directory Service

En una frase: Controladores de dominio de Microsoft AD gestionados o un conector hacia tu AD local
Categoría: Seguridad, identidad y cumplimiento (Security, Identity, and Compliance)
Certificaciones: SAA-C03 SAP-C02 CLF-C02
Documentación oficial: Documentación de AWS Directory Service ↗
Aviso: Simple AD ya no admite clientes nuevos (quien lo usaba conserva toda la funcionalidad). AWS recomienda AWS Managed Microsoft AD o AD Connector. Las guías de examen siguen mencionando las tres opciones.

Qué es

AWS Directory Service ofrece varias formas de usar Microsoft Active Directory (AD) con AWS. Un directorio guarda usuarios, grupos y equipos, y permite iniciar sesión con una sola identidad corporativa. El servicio sirve para que las cargas de Windows en la nube tengan su directorio y para que los empleados usen sus credenciales de siempre en los servicios de AWS, sin que tengas que instalar y mantener controladores de dominio.

Conceptos clave

  • AWS Managed Microsoft AD: un Active Directory auténtico, sobre Windows Server, gestionado por AWS. Los controladores de dominio se despliegan en dos AZ (Availability Zone: zona de disponibilidad). Admite relaciones de confianza con tu AD local, políticas de grupo, extensión del esquema y replicación entre regiones. Ediciones Standard (hasta unos 30 000 objetos) y Enterprise (hasta unos 500 000), además de una edición híbrida que extiende tu dominio existente.
  • AD Connector: un proxy que redirige las peticiones a tu AD local. No guarda ni replica datos del directorio en AWS; las políticas de contraseñas siguen siendo las de tu AD. Necesita conectividad con el centro de datos (VPN (Virtual Private Network: red privada virtual) o Direct Connect).
  • Simple AD: directorio básico y económico basado en Samba, compatible con AD para lo esencial. Hasta 5000 usuarios, sin relaciones de confianza.
  • Compartir el directorio: un AWS Managed Microsoft AD se comparte con otras cuentas, para que sus instancias se unan al dominio.
  • Integraciones: unión al dominio de instancias de EC2 (Elastic Compute Cloud), RDS (Relational Database Service) para SQL Server, FSx para Windows File Server, WorkSpaces, Amazon Quick y, como fuente de identidades, IAM Identity Center.
  • Amazon Cognito no es un directorio corporativo: es para los usuarios de tus aplicaciones web y móviles.

Casos de uso típicos

  • Migrar a AWS aplicaciones de Windows que dependen de Active Directory.
  • Que los empleados entren en WorkSpaces o en la consola de AWS con sus credenciales corporativas.
  • Dar autenticación de Windows a SQL Server en RDS o a un sistema de ficheros de FSx.
  • Un bosque de recursos en AWS con confianza hacia el AD local, manteniendo las identidades donde están.

Cuándo NO usarlo

  • Para el acceso de la plantilla a varias cuentas de AWS con inicio de sesión único: IAM Identity Center (que puede usar el directorio como fuente).
  • Para los usuarios finales de una aplicación: Cognito.
  • Para dar permisos sobre recursos de AWS: IAM (Identity and Access Management).
  • Si no hay nada que dependa de AD ni de LDAP (Lightweight Directory Access Protocol: protocolo de directorios de usuarios): no hace falta un directorio.

Modelo de precios

Se paga por hora según el tipo y el tamaño del directorio: en AWS Managed Microsoft AD, por controlador de dominio y edición (con cargos por compartirlo y por regiones adicionales); en AD Connector y Simple AD, por tamaño (pequeño o grande).

Seguridad y alta disponibilidad

  • AWS Managed Microsoft AD: dos controladores en AZ distintas, parches, copias diarias y sustitución automática. Se pueden añadir controladores y regiones.
  • AD Connector depende de la conexión con el centro de datos: si se corta, no hay autenticación. Conviene una conexión redundante.
  • Los directorios viven en tu VPC (Virtual Private Cloud), con sus grupos de seguridad.
  • AWS no te da permisos de administrador del dominio en el directorio gestionado: administras una unidad organizativa delegada.
  • MFA (Multi-Factor Authentication: inicio de sesión con un segundo factor) mediante un servidor RADIUS (Remote Authentication Dial-In User Service: protocolo de autenticación en red) y envío de los registros de seguridad a CloudWatch Logs.

Trampas de examen

  • "Relación de confianza con el Active Directory local": AWS Managed Microsoft AD.
  • "Usar el AD local sin replicar ni sincronizar las identidades en la nube": AD Connector.
  • "Directorio económico para pocos usuarios, sin confianzas": Simple AD.
  • "Unir instancias de EC2 de Windows a un dominio gestionado" o "SQL Server en RDS con autenticación de Windows": AWS Managed Microsoft AD.
  • "Usuarios de una aplicación móvil": Cognito, no Directory Service.
