AWS SCT

AWS Schema Conversion Tool (AWS SCT)

En una frase: Traduce esquemas y código SQL (Structured Query Language: lenguaje de consultas de bases de datos relacionales) de un motor de bases de datos a otro distinto
Categoría: Migración y transferencia (Migration and Transfer)
Certificaciones: CLF-C02 SAP-C02
Documentación oficial: Documentación de AWS SCT ↗

Qué es

AWS Schema Conversion Tool (SCT) es una aplicación de escritorio que traduce el esquema (tablas, índices, vistas) y el código de la base de datos (procedimientos, funciones, disparadores) de un motor a otro distinto, por ejemplo de Oracle o SQL Server a Aurora PostgreSQL, o de Teradata a Redshift. Genera un informe de evaluación que indica qué se convierte solo y qué hay que rehacer a mano. No mueve los datos de las tablas: eso lo hace DMS (Database Migration Service).

Conceptos clave

  • Migración heterogénea: entre motores distintos; es cuando hace falta SCT. Entre motores iguales no hace falta convertir.
  • Informe de evaluación: resume la complejidad, las acciones manuales y el esfuerzo estimado; útil para decidir el motor de destino.
  • Conversión de código de aplicación: también puede convertir sentencias SQL incrustadas en el código de la aplicación.
  • Agentes de extracción de datos: para almacenes de datos grandes (Teradata, Netezza, Oracle, etc.), extraen los datos en paralelo y los cargan en Redshift a través de S3 (Simple Storage Service).
  • Integración con DMS: desde SCT se pueden crear las tareas de DMS que moverán los datos.
  • DMS Schema Conversion: la versión gestionada en la consola de DMS, sin instalar nada y con ayuda de IA (inteligencia artificial) generativa; cubre las conversiones más habituales, mientras SCT admite más orígenes.

Casos de uso típicos

  • Salir de un motor comercial (Oracle, SQL Server) hacia Aurora o RDS (Relational Database Service) con PostgreSQL o MySQL.
  • Migrar un almacén de datos local (Teradata, Netezza, Vertica…) o de otra nube (BigQuery, Snowflake, Azure Synapse) a Redshift.
  • Evaluar el coste de una migración antes de decidirla.

Cuándo NO usarlo

  • Si el origen y el destino usan el mismo motor: basta con DMS o con las herramientas nativas.
  • Para copiar los datos y replicar cambios: DMS.
  • Si prefieres no instalar nada y tu combinación está soportada: DMS Schema Conversion.

Modelo de precios

SCT es gratuito. Se pagan los recursos de AWS que uses con él, como DMS, S3 o Redshift.

Seguridad y alta disponibilidad

  • Se conecta a las bases de datos con sus propias credenciales; usa conexiones cifradas cuando el motor lo admite.
  • Los agentes de extracción se instalan cerca del origen y suben los datos a S3 cifrados.
  • Al ser una herramienta de escritorio, no tiene alta disponibilidad propia: el proyecto se guarda en local.

Trampas de examen

  • "Convertir el esquema" o "motores distintos": SCT (o DMS Schema Conversion), y DMS para los datos.
  • "Mismo motor": SCT no hace falta.
  • "Evaluar cuánto código hay que reescribir": informe de evaluación de SCT.
  • "Almacén de datos local a Redshift": SCT con agentes de extracción de datos.
  • SCT no migra los datos ni replica cambios.
