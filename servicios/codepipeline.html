AWS CodePipeline

En una frase: Encadena fuente, compilación, pruebas y despliegue en un flujo de entrega continua
Categoría: Herramientas para desarrolladores (Developer Tools)
Certificaciones: CLF-C02 DVA-C02 SAP-C02
Documentación oficial: Documentación de AWS CodePipeline ↗

Qué es

AWS CodePipeline es un servicio de entrega continua gestionado. Defines una canalización (pipeline) con etapas (fuente, compilación, pruebas, despliegue) y cada cambio en el código la recorre de forma automática. No compila ni despliega por sí mismo: orquesta otros servicios, como CodeBuild, CodeDeploy, CloudFormation, ECS (Elastic Container Service), Lambda o herramientas de terceros.

Conceptos clave

  • Etapas y acciones: cada etapa contiene acciones (en serie o en paralelo) de tipo fuente, compilación, prueba, despliegue, aprobación o invocación.
  • Artefactos: lo que pasa de una acción a otra (código, paquetes), guardado en un bucket de S3 (Simple Storage Service) cifrado.
  • Fuentes: GitHub, GitLab, Bitbucket (mediante conexiones de CodeConnections), CodeCommit, S3 o imágenes de ECR (Elastic Container Registry).
  • Aprobación manual: pausa la canalización hasta que alguien aprueba, con aviso por SNS (Simple Notification Service).
  • Tipos V1 y V2: V2 añade disparadores por rama, etiqueta de Git o solicitud de incorporación, variables de canalización, modos de ejecución (en cola, reemplazada, paralela) y reversiones y condiciones en las etapas.
  • Despliegues entre cuentas y regiones: acciones en otras cuentas (con roles) y otras regiones.
  • Eventos: los cambios de estado se publican en EventBridge para notificar o automatizar.

Casos de uso típicos

  • CI/CD (Continuous Integration / Continuous Delivery: integración y entrega continuas) de una aplicación: cada commit se compila, se prueba y se despliega.
  • Desplegar infraestructura como código con CloudFormation o CDK en varias cuentas (desarrollo, preproducción, producción).
  • Canalizaciones con aprobación manual antes de producción.

Cuándo NO usarlo

  • Si solo necesitas compilar y probar: CodeBuild por sí solo.
  • Si el equipo ya usa GitHub Actions o GitLab CI y no necesita integrarse con servicios de AWS más allá del despliegue.
  • Para aplicaciones web frontales sencillas con su propio CI/CD: Amplify Hosting.

Comparativa con servicios parecidos

ServicioPapel
CodePipelineOrquesta el flujo completo
CodeBuildCompila y ejecuta pruebas (buildspec)
CodeDeployDespliega en EC2 (Elastic Compute Cloud), servidores locales, Lambda o ECS con estrategias
CodeArtifactRepositorio privado de paquetes

Modelo de precios

Canalizaciones V1: por canalización activa al mes. Canalizaciones V2: por minuto de ejecución de acciones. Aparte se pagan los servicios que ejecutan las acciones (CodeBuild, S3…).

Seguridad y alta disponibilidad

  • Cada canalización usa un rol de servicio de IAM (Identity and Access Management); las acciones entre cuentas asumen roles en las cuentas de destino.
  • Artefactos cifrados con KMS (Key Management Service); para despliegues entre cuentas se necesita una clave gestionada por el cliente compartida.
  • Aprobaciones manuales como control antes de producción.
  • Servicio regional gestionado y de alta disponibilidad.

Trampas de examen

  • "Automatizar todo el flujo desde el commit hasta producción": CodePipeline.
  • "Que alguien apruebe antes de producción": acción de aprobación manual.
  • "Desplegar en otra cuenta": rol entre cuentas y clave de KMS gestionada por el cliente para los artefactos.
  • "Ejecutar solo cuando se crea una etiqueta de Git": disparadores de una canalización V2.
  • "Compilar y ejecutar pruebas unitarias": CodeBuild (dentro de la canalización).
  • "Despliegue canary o azul/verde": lo hace CodeDeploy (u otro servicio de despliegue), no CodePipeline.
