AWS Clean Rooms

En una frase: Analiza datos con socios sin que ninguna parte vea los datos en bruto de la otra
Categoría: Análisis (Analytics)
Certificaciones: SAP-C03
Documentación oficial: Documentación de AWS Clean Rooms ↗

Qué es

AWS Clean Rooms es un espacio de colaboración seguro para que dos o más empresas analicen juntas sus conjuntos de datos sin revelarse los datos en bruto. Cada parte deja sus datos donde están (en S3 (Simple Storage Service), Athena, Snowflake o Databricks), elige con quién colabora y fija qué tipo de consultas se pueden hacer sobre sus tablas y qué resultados pueden salir. Nadie copia los datos del otro.

Conceptos clave

  • Colaboración y miembros: el creador invita a otras cuentas y decide quién puede consultar, quién recibe los resultados y quién paga el cómputo.
  • Tabla configurada: la referencia a los datos de un miembro (por ejemplo, una tabla del catálogo de Glue sobre S3), con las columnas que se permiten usar.
  • Reglas de análisis: de agregación (solo estadísticas, con un mínimo de personas por fila de resultado), de lista (la lista de coincidencias entre conjuntos, con restricciones) o personalizada (consultas SQL (Structured Query Language: lenguaje de consultas de bases de datos relacionales) o trabajos de PySpark revisados y aprobados).
  • Plantillas de análisis: consultas acordadas de antemano, con parámetros, que los demás miembros revisan y aprueban.
  • Privacidad diferencial: añade ruido calculado a los resultados para impedir identificar a una persona concreta mediante consultas repetidas.
  • Computación criptográfica: los datos se mantienen cifrados incluso mientras se procesa la consulta, para políticas de datos muy estrictas.
  • Clean Rooms ML (Machine Learning: aprendizaje automático): modelos de audiencias similares (lookalike) entre dos partes sin compartir los datos.
  • Registros de análisis: cada consulta queda registrada para auditoría.

Casos de uso típicos

  • Un anunciante y un medio miden el alcance de una campaña cruzando impresiones y ventas sin intercambiar clientes.
  • Bancos o aseguradoras detectan fraude cruzando señales sin compartir datos personales.
  • Investigación sanitaria entre instituciones con datos que no pueden salir de cada una.
  • Enriquecer audiencias con un socio para marketing respetando la privacidad.

Cuándo NO usarlo

  • Para vender o distribuir un conjunto de datos a terceros: Data Exchange.
  • Para compartir tablas completas entre cuentas de tu propia organización: Lake Formation o el uso compartido de datos de Redshift.
  • Si los socios pueden ver los datos del otro sin problema: un análisis normal con Athena o Redshift es más simple.

Modelo de precios

Se paga el cómputo de las consultas SQL o los trabajos de PySpark por unidad de procesamiento y hora, y lo paga el miembro que la colaboración designe. Clean Rooms ML y la resolución de entidades se cobran aparte, según los registros o perfiles procesados.

Seguridad y alta disponibilidad

  • Los datos no se mueven ni se copian: Clean Rooms los lee de su origen al ejecutar cada consulta.
  • Reglas de análisis, umbrales mínimos de agregación y privacidad diferencial para evitar reidentificar personas.
  • Cifrado de los datos durante el cálculo con la computación criptográfica.
  • Registros de consultas y llamadas a la API (Application Programming Interface: interfaz para que los programas se comuniquen) en CloudTrail para auditoría.

Trampas de examen

  • "Analizar datos con un socio sin compartir los datos en bruto": Clean Rooms.
  • "Solo resultados agregados de al menos 100 personas": regla de agregación con umbral mínimo.
  • "Evitar que consultas repetidas identifiquen a una persona": privacidad diferencial.
  • "Los datos deben seguir cifrados durante el cálculo": computación criptográfica de Clean Rooms.
  • "Vender un conjunto de datos": Data Exchange, no Clean Rooms.
