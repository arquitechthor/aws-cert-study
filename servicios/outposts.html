AWS Outposts

En una frase: Racks y servidores de AWS instalados en tu centro de datos para baja latencia local
Categoría: Computación (Compute)
Certificaciones: SAA-C03 SAP-C02 CLF-C02
Documentación oficial: Documentación de AWS Outposts ↗
Aviso: AWS ha dejado de vender los servidores Outposts de 1U y 2U y no acepta clientes nuevos para ese formato; se centra en los racks, que ahora tienen también una configuración de un solo rack para sitios con poco espacio. Las guías de examen siguen mencionando los dos formatos.

Qué es

AWS Outposts lleva la infraestructura de AWS a tus instalaciones. AWS entrega e instala en tu centro de datos hardware propio, lo opera, vigila y actualiza a distancia, y tú lo usas con las mismas API (Application Programming Interface: interfaz para que los programas se comuniquen), consola y herramientas que en la nube. Es la respuesta de AWS a la nube híbrida: para las cargas que deben quedarse en local por latencia, por residencia de datos o porque dependen de sistemas que no se pueden mover.

Conceptos clave

  • Racks Outposts: armarios estándar de 42U con cómputo, almacenamiento y red. La segunda generación se ofrece en configuración de un solo rack (todo integrado, sin ampliación con más racks) o de varios racks (un rack de red más los de cómputo que hagan falta).
  • Servicios en local: EC2 (Elastic Compute Cloud), EBS (Elastic Block Store), ECS (Elastic Container Service), EKS (Elastic Kubernetes Service), RDS (Relational Database Service) y balanceadores de aplicación, entre otros, y S3 (Simple Storage Service) en Outposts en las configuraciones que lo admiten. El resto de servicios se usan desde la región.
  • Región de anclaje: cada Outpost depende de una región (y de una AZ (Availability Zone: zona de disponibilidad)) de AWS, que aloja su plano de control.
  • Enlace de servicio (service link): la conexión cifrada entre el Outpost y su región, por internet o por Direct Connect. Por ella van la gestión y el tráfico con el resto de la VPC (Virtual Private Cloud). Outposts está diseñado para funcionar con esa conexión constante.
  • Extensión de la VPC: creas una subred en el Outpost dentro de una VPC de la región; las instancias locales son parte de la misma red.
  • Puerta de enlace local (local gateway): conecta las subredes del Outpost con tu red local, para que tus sistemas hablen con las instancias con latencia mínima.
  • Reparto de tareas: AWS pone, instala y mantiene el hardware. Tú aportas el espacio, la alimentación, la refrigeración, la red y la seguridad física, y decides la capacidad: es finita, no elástica como en la región.

Casos de uso típicos

  • Latencia muy baja hacia equipos locales: fábricas, hospitales, mercados financieros.
  • Residencia de datos: información que por ley o por contrato no puede salir de un país o de un edificio.
  • Procesamiento local de grandes volúmenes de datos antes de enviarlos a la nube.
  • Migración por fases: aplicaciones con dependencias locales que se modernizan con las herramientas de AWS antes de moverse.

Cuándo NO usarlo

  • Si solo necesitas acercar el cómputo a los usuarios de una gran ciudad: una Local Zone, sin hardware en tu casa.
  • Para dispositivos de redes móviles 5G (quinta generación de redes móviles): Wavelength.
  • Para lugares sin conexión estable o para mover datos físicamente: Snow Family.
  • Si lo que quieres es conservar tu entorno VMware: VMware Cloud on AWS o Amazon EVS.
  • Si no hay requisito de latencia ni de residencia: la región es más barata y elástica.

Modelo de precios

Se contrata una configuración de capacidad por un plazo de tres años, con pago total por adelantado, parcial o mensual. El precio incluye la entrega, la instalación, el mantenimiento y las actualizaciones. Los sistemas operativos con licencia, los servicios gestionados que uses y la transferencia de datos se facturan según su tarifa.

Seguridad y alta disponibilidad

  • Responsabilidad compartida ampliada: AWS responde del hardware y del software de la infraestructura; tú, además de lo habitual, de la seguridad física del sitio, la energía y la conectividad.
  • Los datos se cifran en reposo y el enlace de servicio va cifrado.
  • Un Outpost es un único punto físico: para alta disponibilidad se necesitan varios Outposts o respaldo en la región, además de energía y red redundantes.
  • Si se pierde el enlace de servicio, las instancias en marcha siguen funcionando, pero no se pueden hacer cambios mediante las API hasta recuperarlo.

Trampas de examen

  • "Ejecutar servicios de AWS en el centro de datos propio" con las mismas API: Outposts.
  • "Los datos deben permanecer en las instalaciones" y se quiere seguir usando EC2, RDS o S3: Outposts.
  • "Latencia de milisegundos hacia la maquinaria de la fábrica": Outposts con puerta de enlace local.
  • AWS gestiona el hardware; el cliente pone el sitio, la energía y la red.
  • No es una región aislada: necesita conexión con su región de anclaje.
  • No confundir con Local Zones (infraestructura de AWS en una ciudad) ni con Wavelength (en la red 5G).
