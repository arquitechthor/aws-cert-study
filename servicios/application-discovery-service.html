AWS Application Discovery Service

En una frase: Inventaría los servidores de tu centro de datos y sus dependencias antes de migrar
Categoría: Migración y transferencia (Migration and Transfer)
Certificaciones: CLF-C02 SAP-C02
Documentación oficial: Documentación de AWS Application Discovery Service ↗
Aviso: AWS Application Discovery Service no admite clientes nuevos desde el 07/11/2025; los clientes actuales pueden seguir usándolo. Para descubrir y evaluar el entorno local, AWS recomienda AWS Transform. Además, el antiguo Discovery Connector para VMware dejó de funcionar el 17/11/2025 y lo sustituye el recolector sin agente. El servicio sigue apareciendo en las guías de examen.

Qué es

AWS Application Discovery Service recopila información de los servidores de tu centro de datos para planificar una migración: qué servidores hay, su configuración, cuánto los usas y de qué otros servidores dependen. Con esos datos se agrupan servidores en aplicaciones, se dimensionan las instancias EC2 (Elastic Compute Cloud) de destino y se estima el coste. Los datos se ven en Migration Hub y se pueden exportar para analizarlos.

Conceptos clave

  • Agente de descubrimiento: se instala en cada servidor (Windows o Linux, físico o virtual) y recoge configuración, rendimiento, procesos y conexiones de red. Es la opción que permite ver las dependencias entre servidores.
  • Recolector sin agente (Agentless Collector): una máquina virtual que se despliega en vCenter y recoge inventario y rendimiento de las máquinas VMware sin instalar nada en ellas; tiene módulos adicionales para bases de datos y conexiones de red.
  • Importación: se pueden subir datos de otras herramientas con una plantilla.
  • Exploración de datos: exporta lo recogido a S3 (Simple Storage Service) para consultarlo con Athena.
  • Región de inicio de Migration Hub: los datos de descubrimiento se guardan en esa región.

Casos de uso típicos

  • Inventariar un centro de datos antes de migrarlo.
  • Descubrir dependencias para decidir qué servidores migrar juntos en cada ola.
  • Dimensionar las instancias de destino según el uso real, no la capacidad aprovisionada.

Cuándo NO usarlo

  • Si eres cliente nuevo: no está disponible; usa AWS Transform para el descubrimiento y la evaluación.
  • Para migrar los servidores en sí: Application Migration Service (Transform MGN).
  • Para estimar solo el coste de un entorno a partir de un inventario existente: herramientas de evaluación como Migration Evaluator o AWS Transform.

Comparativa con servicios parecidos

NecesidadAgente de descubrimientoRecolector sin agente
InstalaciónEn cada servidorUna máquina virtual en vCenter
EntornosFísicos y virtuales, Windows y LinuxVMware
Procesos y dependenciasSíLimitado (módulo de red)

Modelo de precios

El servicio no tiene coste. Solo se pagan los servicios que uses para analizar los datos, como S3 y Athena.

Seguridad y alta disponibilidad

  • Los datos viajan cifrados (TLS) y se guardan cifrados en AWS.
  • El recolector sin agente permite revisar los datos antes de enviarlos.
  • No recoge el contenido de los ficheros ni de las bases de datos, solo metadatos y métricas.

Trampas de examen

  • "Descubrir dependencias entre servidores": agente de descubrimiento (no el recolector sin agente).
  • "VMware sin instalar nada en las máquinas": recolector sin agente.
  • "Analizar los datos de descubrimiento con SQL (Structured Query Language: lenguaje de consultas de bases de datos relacionales)": exportar y consultar con Athena.
  • "Planificar", "inventariar", "antes de migrar": Application Discovery Service; migrar en sí es otro servicio.
