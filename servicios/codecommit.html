AWS CodeCommit

En una frase: Repositorios Git privados y gestionados, integrados con IAM (Identity and Access Management) y las canalizaciones de AWS
Categoría: Herramientas para desarrolladores (Developer Tools)
Certificaciones: SAP-C03
Documentación oficial: Documentación de AWS CodeCommit ↗

Qué es

AWS CodeCommit es un servicio de repositorios Git privados totalmente gestionado. Guarda el código en AWS, cifrado, con el acceso controlado por IAM y sin servidores de control de versiones que mantener. Se usa con cualquier cliente Git y se integra con CodePipeline, CodeBuild y los demás servicios de CI/CD (Continuous Integration / Continuous Delivery: integración y entrega continuas). Tras dejar de admitir clientes nuevos en julio de 2024, AWS lo devolvió a disponibilidad general el 25/11/2025.

Conceptos clave

  • Repositorio: un repositorio Git normal (ramas, etiquetas, historial) en una región.
  • Conexión: por HTTPS (HTTP Secure: HTTP cifrado con TLS) con credenciales de Git de un usuario de IAM, por SSH (Secure Shell: acceso remoto cifrado por terminal) con una clave pública asociada al usuario, o con el ayudante de credenciales o git-remote-codecommit usando credenciales temporales (roles, federación o la consola de identidades), que evita usuarios de IAM.
  • Permisos de IAM: acciones como codecommit:GitPull y codecommit:GitPush sobre el ARN (Amazon Resource Name: identificador único de un recurso de AWS) del repositorio, y condiciones por rama (por ejemplo, impedir el push directo a main).
  • Solicitudes de extracción y reglas de aprobación: revisión de cambios antes de fusionarlos, con reglas que exigen un número de aprobaciones de un grupo de personas; las plantillas de reglas de aprobación las aplican a varios repositorios.
  • Desencadenadores y notificaciones: hasta 10 desencadenadores por repositorio que publican en SNS (Simple Notification Service) o invocan Lambda al hacer push o crear ramas; además, eventos en EventBridge para arrancar CodePipeline.
  • Acceso entre cuentas: un rol en la cuenta del repositorio que los usuarios de otra cuenta asumen.
  • Cifrado: en reposo con KMS (Key Management Service) (clave gestionada por AWS o propia) y en tránsito con HTTPS o SSH.

Casos de uso típicos

  • Repositorio de origen de canalizaciones de CodePipeline dentro de AWS, sin depender de servicios externos.
  • Código sujeto a normativa que debe quedarse en la cuenta y región de la empresa, con acceso por IAM.
  • Repositorios de infraestructura como código para despliegues multicuenta.
  • Acceso desde instancias o contenedores con roles de IAM, sin claves guardadas.

Cuándo NO usarlo

  • Si el equipo ya trabaja en GitHub, GitLab o Bitbucket: CodePipeline y CodeBuild se conectan a ellos directamente (con conexiones de CodeConnections).
  • Para guardar paquetes y dependencias (npm, Maven, PyPI): CodeArtifact.
  • Para imágenes de contenedor: ECR (Elastic Container Registry).
  • Para ficheros binarios grandes o artefactos de compilación: S3 (Simple Storage Service).

Modelo de precios

Se paga por usuario activo al mes (los primeros, gratis), con almacenamiento y peticiones Git incluidos por usuario; lo que se pase de esas cantidades se cobra aparte.

Seguridad y alta disponibilidad

  • Acceso con IAM, preferiblemente con credenciales temporales en lugar de credenciales de Git de larga duración.
  • Políticas que bloquean el push directo a ramas protegidas y reglas de aprobación obligatorias.
  • Cifrado con KMS y puntos de enlace de VPC (Virtual Private Cloud) de interfaz para usarlo sin salir a internet.
  • Registro de llamadas en CloudTrail y almacenamiento redundante gestionado por AWS.

Trampas de examen

  • "Repositorio Git privado y gestionado, con acceso por IAM": CodeCommit.
  • "Exigir dos aprobaciones antes de fusionar": regla de aprobación de solicitudes de extracción.
  • "Impedir el push directo a main": política de IAM con condición por rama.
  • "Lanzar la canalización al hacer push": evento de EventBridge (o desencadenador) que arranca CodePipeline.
  • "Clonar desde una instancia sin guardar credenciales": rol de IAM con el ayudante de credenciales o git-remote-codecommit.
