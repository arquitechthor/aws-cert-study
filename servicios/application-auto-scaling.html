AWS Application Auto Scaling

En una frase: Ajusta la capacidad de ECS (Elastic Container Service), DynamoDB, Aurora o Lambda según métricas o un horario
Categoría: Computación (Compute)
Certificaciones: SAP-C03
Documentación oficial: Documentación de AWS Application Auto Scaling ↗

Qué es

AWS Application Auto Scaling es el servicio que ajusta de forma automática la capacidad de recursos de otros servicios de AWS que no son grupos de instancias EC2 (Elastic Compute Cloud): el número de tareas de un servicio de ECS, la capacidad de lectura y escritura de una tabla de DynamoDB, las réplicas de Aurora, la concurrencia aprovisionada de Lambda, los nodos de ElastiCache o los puntos de enlace de SageMaker AI, entre otros. Para las instancias EC2 se usa su servicio hermano, EC2 Auto Scaling.

Conceptos clave

  • Objetivo escalable (scalable target): el recurso que se escala, identificado por su espacio de nombres (ecs, dynamodb, lambda…), su ID de recurso y la dimensión escalable (por ejemplo, ecs:service:DesiredCount). Se registra con una capacidad mínima y máxima; ninguna política sale de ese rango.
  • Seguimiento de objetivo (target tracking): mantiene una métrica cerca de un valor (por ejemplo, 70 % de CPU (Central Processing Unit: procesador) media o de uso de la concurrencia aprovisionada). Crea y gestiona él mismo las alarmas de CloudWatch: no hay que editarlas a mano.
  • Escalado por pasos: ajustes distintos según cuánto se supere una alarma.
  • Escalado programado: cambia el mínimo y el máximo a una hora o de forma periódica (horario laboral, campañas).
  • Escalado predictivo: se adelanta a la carga a partir del historial (disponible, por ejemplo, para servicios de ECS).
  • Periodos de enfriamiento (cooldown): tiempo de espera tras escalar hacia fuera o hacia dentro antes de otra actividad del mismo tipo; reducir con cautela protege la disponibilidad.
  • Desactivar la reducción (DisableScaleIn): la política solo añade capacidad y la reducción se hace a mano o con otra política.
  • Suspender y reanudar: se puede pausar el escalado hacia fuera, hacia dentro o el programado (por ejemplo, durante un despliegue) sin borrar las políticas.
  • Recursos personalizados: también escala capacidad de tus propias aplicaciones mediante una API (Application Programming Interface: interfaz para que los programas se comuniquen) que tú expones.

Casos de uso típicos

  • Añadir y quitar tareas de un servicio de ECS (también en Fargate) según la CPU o la profundidad de una cola.
  • Ajustar la capacidad aprovisionada de una tabla de DynamoDB o de sus índices secundarios globales.
  • Añadir réplicas de lectura de Aurora cuando sube la carga de consultas.
  • Subir la concurrencia aprovisionada de una función Lambda en horario laboral para evitar arranques en frío.
  • Escalar flotas de spot, clústeres de EMR (Elastic MapReduce), almacenamiento de brokers de MSK (Managed Streaming for Apache Kafka) o tablas de Keyspaces.

Cuándo NO usarlo

  • Para instancias EC2 en un grupo: EC2 Auto Scaling.
  • Para tablas de DynamoDB con tráfico muy impredecible o con picos repentinos: el modo bajo demanda suele encajar mejor que escalar la capacidad aprovisionada.
  • Para cargas que ya escalan solas por diseño (Lambda sin concurrencia aprovisionada, Aurora Serverless, servicios totalmente gestionados).

Modelo de precios

No tiene coste propio: se paga la capacidad que añade en cada servicio (tareas, unidades de capacidad, réplicas, concurrencia aprovisionada…) y, si las hay, las métricas y alarmas de CloudWatch según su uso.

Seguridad y alta disponibilidad

  • Usa un rol vinculado al servicio para cambiar la capacidad de cada recurso.
  • Permisos de IAM (Identity and Access Management) para registrar objetivos y crear políticas (separar quién puede cambiar mínimos y máximos).
  • Un mínimo adecuado mantiene capacidad en varias zonas aunque baje la carga.
  • Reducir más despacio que se crece (enfriamiento de reducción mayor) evita oscilaciones.

Trampas de examen

  • "Escalar tareas de ECS, réplicas de Aurora o capacidad de DynamoDB": Application Auto Scaling, no EC2 Auto Scaling.
  • "Más concurrencia aprovisionada de Lambda en horario laboral": acción programada (o seguimiento de objetivo) sobre la concurrencia aprovisionada del alias o la versión.
  • "La capacidad sube y baja sin parar": alargar el enfriamiento de reducción o revisar el objetivo.
  • "Solo crecer automáticamente; reducir a mano": DisableScaleIn.
  • "Pausar el escalado durante un despliegue sin borrar nada": suspender el escalado del objetivo.
  • "Cambié el umbral de la alarma y volvió a su valor": las alarmas del seguimiento de objetivo las gestiona el servicio; se cambia el valor objetivo.
