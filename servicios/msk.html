Amazon MSK

Amazon Managed Streaming for Apache Kafka (Amazon MSK)

En una frase: Clústeres gestionados del broker de eventos abierto más usado, con topics y particiones
Categoría: Análisis (Analytics)
Certificaciones: SAA-C03 SAP-C02
Documentación oficial: Documentación de Amazon MSK ↗

Qué es

Amazon Managed Streaming for Apache Kafka (MSK) ejecuta Apache Kafka por ti: crea los brokers, los reparte entre AZ (Availability Zone: zona de disponibilidad), sustituye los que fallan y aplica parches. Tus productores y consumidores usan las API (Application Programming Interface: interfaz para que los programas se comuniquen) y herramientas de Kafka de siempre, sin cambios. Encaja para flujos de eventos de alto volumen, sobre todo si ya usas Kafka o necesitas su ecosistema.

Conceptos clave

  • Temas y particiones: los mensajes se publican en temas divididos en particiones; el orden se garantiza dentro de cada partición.
  • MSK aprovisionado: eliges el número y tipo de brokers. Brokers Standard (más control de la configuración y del almacenamiento) o Express (más rendimiento por broker, escalado más rápido y almacenamiento sin gestionar).
  • MSK Serverless: sin brokers que dimensionar; escala solo y se paga por uso.
  • Almacenamiento por niveles: los datos antiguos pasan a un nivel más barato para retener mucho tiempo.
  • MSK Connect: conectores de Kafka Connect gestionados para llevar datos desde y hacia otros sistemas.
  • MSK Replicator: replica temas entre clústeres, por ejemplo en otra región.
  • Integraciones: Lambda (mapeo de origen de eventos), Data Firehose, Managed Service for Apache Flink y entrega a S3 (Simple Storage Service).

Casos de uso típicos

  • Migrar a AWS un Kafka propio sin cambiar las aplicaciones.
  • Canalizaciones de eventos en tiempo real entre microservicios.
  • Ingesta de registros, clics o telemetría para análisis en streaming.
  • Captura de cambios de bases de datos con conectores de Kafka.

Cuándo NO usarlo

  • Si no necesitas Kafka y quieres lo más sencillo: Kinesis Data Streams.
  • Para colas de mensajes entre componentes: SQS (Simple Queue Service).
  • Para notificaciones a muchos suscriptores: SNS (Simple Notification Service) o EventBridge.
  • Para cargar datos en S3 o Redshift sin gestionar consumidores: Data Firehose.

Modelo de precios

Aprovisionado: por hora de broker (según tipo) y por almacenamiento. Serverless: por hora de clúster, por hora de partición y por datos escritos y leídos. MSK Connect y Replicator se cobran aparte, así como la transferencia de datos entre AZ y regiones cuando aplica.

Seguridad y alta disponibilidad

  • Brokers repartidos en dos o tres AZ, con réplicas de cada partición.
  • Cifrado en reposo con KMS (Key Management Service) y en tránsito con TLS (Transport Layer Security: cifrado de las conexiones).
  • Autenticación con IAM (Identity and Access Management), SASL/SCRAM (credenciales en Secrets Manager) o TLS mutuo; ACL (Access Control List: lista de control de acceso) de Kafka para autorizar.
  • El clúster vive en subredes privadas de tu VPC (Virtual Private Cloud).

Trampas de examen

  • "Ya usan Apache Kafka" o "sin cambiar el código de Kafka": MSK.
  • "Kafka sin gestionar capacidad": MSK Serverless.
  • "Conectores de Kafka Connect gestionados": MSK Connect.
  • "Replicar temas a otra región": MSK Replicator.
  • "Streaming sencillo y nativo de AWS": Kinesis Data Streams.
  • "Procesar los mensajes con funciones": Lambda con MSK como origen de eventos.
