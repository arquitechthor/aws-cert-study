Amazon DocumentDB

En una frase: Base de datos de documentos JSON (JavaScript Object Notation: formato de datos en texto) con consultas ricas e índices, para catálogos y perfiles
Categoría: Base de datos (Database)
Certificaciones: SAA-C03 SAP-C02 AIF-C01 CLF-C02
Documentación oficial: Documentación de Amazon DocumentDB ↗

Qué es

Amazon DocumentDB es una base de datos de documentos totalmente gestionada y compatible con MongoDB: las aplicaciones usan los mismos controladores y herramientas. Guarda documentos JSON con estructura flexible, anidada y distinta de un documento a otro, y permite consultarlos e indexarlos por cualquier campo. Su arquitectura es parecida a la de Aurora: el cómputo y el almacenamiento van separados.

Conceptos clave

  • Clúster basado en instancias: una instancia principal (lecturas y escrituras) y hasta 15 réplicas de solo lectura, todas sobre un mismo volumen de clúster.
  • Volumen de clúster: el almacenamiento crece solo y guarda seis copias de los datos en tres AZ (Availability Zone: zona de disponibilidad). Se paga una vez, no por copia.
  • Puntos de enlace: el del clúster apunta a la principal; el de lectura reparte entre las réplicas.
  • Conmutación por error: si cae la principal, se promociona una réplica automáticamente.
  • Clústeres globales: una región principal y regiones secundarias de solo lectura, para lecturas locales y recuperación ante la caída de una región.
  • Clústeres elásticos: reparten los datos en fragmentos (shards) para escalar las escrituras y el almacenamiento más allá de lo que da una sola instancia principal.
  • Copias: automáticas y continuas en S3 (Simple Storage Service), con recuperación a un momento dado, e instantáneas manuales.
  • Flujos de cambios (change streams): la secuencia de modificaciones, para reaccionar a ellas.
  • Búsqueda vectorial: índices de vectores para aplicaciones de IA (inteligencia artificial) generativa sobre los mismos documentos.
  • Almacenamiento estándar u optimizado para E/S (entrada y salida: lecturas y escrituras): el segundo no cobra por operación y conviene con mucha actividad.

Casos de uso típicos

  • Catálogos de productos, donde cada artículo tiene atributos distintos.
  • Perfiles de usuario y gestión de contenidos.
  • Migrar cargas de MongoDB a un servicio gestionado sin reescribir la aplicación.
  • Aplicaciones móviles y web con modelos de datos que cambian a menudo.

Cuándo NO usarlo

  • Acceso por clave con latencia de milisegundos a cualquier escala y sin instancias: DynamoDB.
  • Datos relacionales con uniones y transacciones complejas: Aurora o RDS (Relational Database Service).
  • Datos muy conectados (relaciones entre entidades): Neptune.
  • Búsqueda de texto completo y análisis de logs: OpenSearch Service.
  • Caché en memoria: ElastiCache.

Modelo de precios

Se pagan las instancias por hora, el almacenamiento por gigabyte y mes, las operaciones de E/S (salvo en la configuración optimizada para E/S) y el almacenamiento de copias que supere el tamaño del clúster. Los clústeres elásticos se cobran por la vCPU de sus fragmentos.

Seguridad y alta disponibilidad

  • Solo es accesible dentro de una VPC (Virtual Private Cloud); no tiene punto de enlace público.
  • Cifrado en reposo con KMS (Key Management Service) (se decide al crear el clúster) y en tránsito con TLS (Transport Layer Security: cifrado de las conexiones).
  • Con réplicas en otras AZ, la conmutación por error es automática; sin réplicas, hay que esperar a que se cree una instancia nueva.
  • Para la caída de una región, clústeres globales.

Trampas de examen

  • "MongoDB" en el enunciado: DocumentDB.
  • "Documentos JSON con consultas flexibles e índices": DocumentDB.
  • "Clave-valor, sin servidor, milisegundos a cualquier escala": DynamoDB.
  • "Escalar las lecturas": réplicas y el punto de enlace de lectura. "Escalar las escrituras": clústeres elásticos.
  • "Relaciones entre entidades, grafos": Neptune, no DocumentDB.
