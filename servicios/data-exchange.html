AWS Data Exchange

En una frase: Catálogo para suscribirse a conjuntos de datos de terceros y usarlos en tu cuenta
Categoría: Análisis (Analytics)
Certificaciones: SAA-C03 SAP-C02 AIF-C01
Documentación oficial: Documentación de AWS Data Exchange ↗

Qué es

AWS Data Exchange es un mercado de datos de terceros. Los proveedores (empresas de datos financieros, sanitarios, meteorológicos, de geolocalización…) publican productos de datos, y los suscriptores los buscan, aceptan sus condiciones y los usan directamente en su cuenta de AWS. Evita el trabajo tradicional de licenciar datos: negociar contratos, recibir ficheros por canales distintos y montar la entrega de cada proveedor.

Conceptos clave

  • Producto de datos: lo que se publica en el catálogo de AWS Marketplace. Incluye uno o varios conjuntos de datos, la oferta (precio y duración) y el acuerdo de suscripción.
  • Conjunto de datos, revisión y activo: un conjunto de datos tiene revisiones (cada actualización que publica el proveedor), y cada revisión contiene activos, que son los datos en sí.
  • Formas de entrega:
    • Ficheros: se exportan a tu bucket de S3 (Simple Storage Service).
    • Acceso a datos en S3: lees directamente del bucket del proveedor, sin copiar.
    • API (Application Programming Interface: interfaz para que los programas se comuniquen): llamas a la API del proveedor, a través de API Gateway.
    • Amazon Redshift: consultas con acceso de solo lectura los datos compartidos, sin ETL (Extract, Transform, Load: extraer, transformar y cargar datos).
    • Permisos de AWS Lake Formation (en versión preliminar): acceso a tablas del lago de datos del proveedor.
  • Ofertas: públicas, o privadas con condiciones negociadas para un suscriptor. Algunos productos exigen que el proveedor verifique la suscripción antes de conceder el acceso.
  • Automatización: al publicarse una revisión nueva se genera un evento en EventBridge, y se puede configurar la exportación automática a S3.
  • Concesiones de datos (data grants): compartir datos con otra cuenta sin publicarlos en el catálogo.
  • Datos abiertos: el catálogo incluye conjuntos de datos gratuitos.

Casos de uso típicos

  • Enriquecer el análisis propio con datos externos: mercados, demografía, clima, movilidad.
  • Alimentar modelos de aprendizaje automático con conjuntos de datos de terceros ya preparados.
  • Recibir cada día las actualizaciones de un proveedor en el lago de datos sin intervención.
  • Vender o distribuir los datos de la propia empresa.

Cuándo NO usarlo

  • Para compartir datos dentro de tu organización: Lake Formation, el uso compartido de datos de Redshift o RAM (Resource Access Manager).
  • Para mover tus datos a AWS: DataSync, Transfer Family o Snow Family.
  • Para comprar software: AWS Marketplace.
  • Para transformar los datos recibidos: Glue.

Modelo de precios

El suscriptor paga el precio que fija cada proveedor (suscripción por un periodo, o por uso en el caso de las API); muchos productos son gratuitos. Aparte se pagan los servicios donde se guardan y analizan los datos (S3, Redshift, Athena). La factura llega integrada en la de AWS.

Seguridad y alta disponibilidad

  • El acceso a los datos suscritos se controla con IAM (Identity and Access Management) en la cuenta del suscriptor.
  • Los datos se cifran en tránsito y en reposo; los exportados heredan la configuración del bucket de destino.
  • Las suscripciones y las exportaciones quedan registradas en CloudTrail.
  • El acuerdo de suscripción de datos fija qué uso se puede hacer de ellos: es responsabilidad del suscriptor respetarlo.

Trampas de examen

  • "Datos de terceros", "suscribirse a conjuntos de datos" o "licenciar datos externos": Data Exchange.
  • "Recibir automáticamente las actualizaciones del proveedor en S3": exportación automática de revisiones o evento de EventBridge.
  • "Consultar los datos del proveedor sin copiarlos ni hacer ETL": conjuntos de datos de Redshift o de acceso a datos en S3.
  • No es para migrar tus datos ni para compartirlos internamente.
