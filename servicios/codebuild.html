AWS CodeBuild

En una frase: Compila el código, ejecuta las pruebas y genera artefactos en entornos efímeros
Categoría: Herramientas para desarrolladores (Developer Tools)
Certificaciones: CLF-C02 DVA-C02 SAP-C02
Documentación oficial: Documentación de AWS CodeBuild ↗

Qué es

AWS CodeBuild es un servicio de integración continua gestionado: cada compilación se ejecuta en un entorno efímero (un contenedor o una instancia que se crea y se destruye) con la imagen que elijas, sigue los pasos de un fichero buildspec y produce artefactos, informes de pruebas o imágenes de contenedor. No hay servidores de compilación que mantener ni colas: escala con las compilaciones simultáneas y se paga por minuto.

Conceptos clave

  • Proyecto de compilación: origen del código, entorno (imagen, tipo de cómputo), rol de servicio, artefactos y registros.
  • buildspec.yml: fases install, pre_build, build y post_build, variables de entorno, artefactos, caché e informes.
  • Variables secretas: se leen de Parameter Store o Secrets Manager desde el buildspec, sin escribirlas en el código.
  • Caché: local o en S3 (Simple Storage Service), para no descargar dependencias en cada compilación.
  • Cómputo: bajo demanda (EC2 (Elastic Compute Cloud) o Lambda) o flotas de capacidad reservada para arranques sin espera.
  • Acceso a la VPC (Virtual Private Cloud): para pruebas que necesitan bases de datos o servicios privados.
  • Informes de pruebas y cobertura, y compilaciones por lotes en paralelo.
  • Se integra como acción de compilación o prueba en CodePipeline, o se lanza con webhooks de GitHub, GitLab o Bitbucket.

Casos de uso típicos

  • Compilar y probar cada commit o solicitud de incorporación.
  • Construir imágenes Docker y subirlas a ECR (Elastic Container Registry).
  • Ejecutar pruebas de integración contra recursos privados de una VPC.
  • Tareas de automatización puntuales (scripts, sincronizaciones) sin mantener servidores.

Cuándo NO usarlo

  • Para orquestar etapas, aprobaciones y despliegues: CodePipeline (que usa CodeBuild dentro).
  • Para desplegar con estrategias canary o azul/verde: CodeDeploy.
  • Para cargas de trabajo largas que no son compilaciones: Batch, ECS (Elastic Container Service) o Step Functions.

Comparativa con servicios parecidos

ServicioPapel en CI/CD (Continuous Integration / Continuous Delivery: integración y entrega continuas)
CodeBuildCompilar, probar y empaquetar
CodePipelineOrquestar el flujo completo
CodeDeployDesplegar con estrategias
CodeArtifactGuardar los paquetes de los que depende la compilación

Modelo de precios

Bajo demanda se paga por minuto de compilación según el tipo de cómputo (o por segundo en cómputo Lambda). Las flotas de capacidad reservada se pagan por el tiempo que están aprovisionadas. Hay una capa gratuita mensual de minutos.

Seguridad y alta disponibilidad

  • Cada compilación corre aislada y el entorno se destruye al terminar.
  • Rol de servicio de IAM (Identity and Access Management) con los permisos mínimos que necesita la compilación.
  • Secretos desde Secrets Manager o Parameter Store, nunca en texto plano en el buildspec.
  • Artefactos cifrados con KMS (Key Management Service) y registros en CloudWatch Logs o S3.

Trampas de examen

  • "Compilar y ejecutar pruebas sin servidores de compilación": CodeBuild.
  • "Las compilaciones tardan por descargar dependencias": caché local o en S3.
  • "Usar una contraseña en la compilación sin exponerla": variables de Secrets Manager o Parameter Store en el buildspec.
  • "Las pruebas necesitan una base de datos privada": configurar la VPC en el proyecto.
  • "Dónde se definen los comandos": buildspec.yml (no AppSpec, que es de CodeDeploy).
