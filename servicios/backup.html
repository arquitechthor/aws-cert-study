AWS Backup

En una frase: Centraliza y programa copias de seguridad de muchos servicios con políticas y bóvedas
Categoría: Almacenamiento (Storage)
Certificaciones: CLF-C02 SAA-C03 SAP-C02
Documentación oficial: Documentación de AWS Backup ↗

Qué es

AWS Backup centraliza y automatiza las copias de seguridad de muchos servicios desde un único lugar: EC2 (Elastic Compute Cloud), EBS (Elastic Block Store), RDS (Relational Database Service), Aurora, DynamoDB, EFS (Elastic File System), FSx, S3 (Simple Storage Service), DocumentDB, Neptune, Redshift, Storage Gateway y máquinas virtuales VMware, entre otros. Defines planes con frecuencia y retención, eliges los recursos (por ejemplo, por etiquetas) y AWS Backup hace, copia, conserva y caduca las copias. También sirve para cumplir normativas y protegerse del ransomware.

Conceptos clave

  • Plan de copias: reglas con frecuencia, ventana, retención, paso a almacenamiento en frío y copias a otras regiones o cuentas.
  • Asignación de recursos: por ID o, mejor, por etiquetas, para que lo nuevo entre solo.
  • Bóveda (vault): contenedor de los puntos de recuperación, cifrado con KMS (Key Management Service) y con su propia política de acceso.
  • Vault Lock: modo gobernanza (solo usuarios con permisos especiales pueden cambiarlo) o cumplimiento (inmutable: nadie, ni siquiera la cuenta raíz o AWS, puede borrar antes de tiempo, tras un periodo de gracia).
  • Bóveda aislada lógicamente (logically air-gapped): bloqueada en modo cumplimiento por defecto y compartible con otras cuentas para restaurar desde ellas.
  • Copias entre regiones y cuentas: para recuperación ante desastres y aislamiento.
  • Políticas de copia de Organizations: aplican planes en todas las cuentas.
  • Audit Manager de AWS Backup (informes de cumplimiento de las copias) y pruebas de restauración automáticas.
  • Recuperación a un momento dado (PITR) en servicios que lo admiten, como RDS, Aurora y S3.

Casos de uso típicos

  • Política de copias única para toda la organización.
  • Cumplir normativas que exigen retención e inmutabilidad.
  • Protección frente a ransomware con copias en otra cuenta bloqueadas.
  • Recuperación ante desastres de tipo copia de seguridad y restauración en otra región.

Cuándo NO usarlo

  • Si necesitas RPO (Recovery Point Objective: cuántos datos puedes permitirte perder) de segundos y RTO (Recovery Time Objective: cuánto tiempo puedes estar sin servicio) de minutos para servidores: Elastic Disaster Recovery.
  • Para replicación continua de bases de datos entre regiones: bases de datos globales de Aurora o tablas globales de DynamoDB.
  • Para versiones de objetos de S3 sin un plan de copias: el control de versiones y la replicación de S3 pueden bastar.

Modelo de precios

Se paga el almacenamiento de las copias por GB y mes (según el tipo de recurso, y más barato en frío), las restauraciones en algunos servicios y la transferencia entre regiones de las copias. No hay cargo por crear planes.

Seguridad y alta disponibilidad

  • Cifrado de las copias con KMS; algunos recursos usan la clave del recurso original.
  • Políticas de acceso a la bóveda para impedir borrados.
  • Vault Lock en modo cumplimiento para copias WORM (Write Once, Read Many: se escribe una vez y no se puede modificar).
  • Copias en otra cuenta y otra región para aislar fallos y ataques.
  • Supervisión con CloudWatch, EventBridge y CloudTrail.

Trampas de examen

  • "Centralizar las copias de varios servicios" o "de toda la organización": AWS Backup con políticas de Organizations.
  • "Que nadie pueda borrar las copias, ni el administrador": Vault Lock en modo cumplimiento.
  • "Proteger las copias del ransomware": copias en otra cuenta, bóveda aislada lógicamente o Vault Lock.
  • "Incluir automáticamente los recursos nuevos": asignación por etiquetas.
  • "Demostrar que las copias cumplen la política": Audit Manager de AWS Backup.
  • "RPO de segundos": no es AWS Backup; piensa en Elastic Disaster Recovery o replicación.
