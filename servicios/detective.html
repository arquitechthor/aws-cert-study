Amazon Detective

En una frase: Investiga el origen de hallazgos de seguridad con gráficos de relaciones entre eventos
Categoría: Seguridad, identidad y cumplimiento (Security, Identity, and Compliance)
Certificaciones: SAA-C03 SAP-C02 CLF-C02
Documentación oficial: Documentación de Amazon Detective ↗

Qué es

Amazon Detective ayuda a investigar un problema de seguridad cuando ya se ha detectado. Recoge automáticamente los registros de tus cuentas y construye con ellos un grafo de comportamiento: quién hizo qué, desde dónde y con qué recursos, a lo largo del tiempo. Así el analista responde con rapidez a lo que importa tras una alerta: ¿es real?, ¿qué más tocó?, ¿desde cuándo? Sin Detective, eso supone cruzar a mano millones de líneas de log.

Conceptos clave

  • Grafo de comportamiento: el conjunto de datos enlazados de una o varias cuentas. La cuenta que activa Detective es su administradora e invita a las cuentas miembro (hasta 1200).
  • Fuentes de datos: eventos de CloudTrail, registros de flujo de la VPC (Virtual Private Cloud), hallazgos de GuardDuty y, de forma opcional, registros de auditoría de EKS (Elastic Kubernetes Service) y hallazgos de Security Hub. Detective los lee directamente: no hay que activarlos ni guardarlos aparte.
  • Entidades y perfiles: cada usuario, rol, dirección IP (Internet Protocol: dirección de red), instancia o clúster tiene un perfil con su actividad y su comportamiento habitual, para ver qué es anómalo.
  • Grupos de hallazgos: agrupa los hallazgos que parecen formar parte del mismo incidente y los muestra de forma visual.
  • Investigaciones: analiza de forma automática un usuario o rol y resume los indicadores de compromiso.
  • Un año de historia: conserva hasta un año de datos agregados para mirar hacia atrás.
  • Integración: desde un hallazgo de GuardDuty, Security Hub o Inspector se salta a Detective para investigarlo; también consulta los registros guardados en Security Lake.

Casos de uso típicos

  • Triaje: decidir si un hallazgo de GuardDuty es un falso positivo.
  • Alcance de un incidente: qué recursos y qué cuentas tocó una credencial comprometida.
  • Causa raíz: reconstruir la cronología de un ataque.
  • Búsqueda proactiva de amenazas a partir de una IP o un usuario sospechoso.

Cuándo NO usarlo

  • Para detectar amenazas: GuardDuty. Detective investiga lo ya detectado.
  • Para una vista agregada de hallazgos y cumplimiento: Security Hub.
  • Para vulnerabilidades de software: Inspector. Para datos sensibles en S3 (Simple Storage Service): Macie.
  • Para consultas libres sobre logs guardados: Athena, CloudWatch Logs Insights o Security Lake.
  • Para responder o contener: EventBridge con Lambda o Systems Manager.

Modelo de precios

Se paga por el volumen de datos ingeridos de cada fuente, por gigabyte y con tramos. No hay que pagar aparte por activar o almacenar las fuentes para Detective. Incluye un periodo de prueba gratuito.

Seguridad y alta disponibilidad

  • Requiere tener GuardDuty activado en la cuenta.
  • Es regional: hay un grafo de comportamiento por región.
  • Con AWS Organizations, un administrador delegado incorpora las cuentas de la organización.
  • Los datos del grafo se cifran y solo los ve la cuenta administradora.
  • Un grafo nuevo necesita unas dos semanas para aprender el comportamiento habitual.

Trampas de examen

  • "Investigar", "causa raíz" o "analizar el alcance de un hallazgo de seguridad": Detective.
  • "Detectar" amenazas: GuardDuty. La pareja habitual es GuardDuty detecta y Detective investiga.
  • "Visualizar las relaciones entre recursos, usuarios e IP tras un incidente": Detective.
  • "Vista única del estado de seguridad": Security Hub, no Detective.
  • No hay que configurar la recogida de logs: Detective la hace por su cuenta.
