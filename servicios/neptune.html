Amazon Neptune

En una frase: Base de datos de grafos para relaciones: redes sociales, fraude y grafos de conocimiento
Categoría: Base de datos (Database)
Certificaciones: SAA-C03 SAP-C02 AIF-C01 CLF-C02
Documentación oficial: Documentación de Amazon Neptune ↗

Qué es

Amazon Neptune es una base de datos de grafos gestionada. Un grafo guarda entidades (nodos) y las relaciones entre ellas (aristas), y está optimizado para recorrerlas: "amigos de mis amigos", "qué cuentas comparten teléfono con esta". Lo que en una base de datos relacional exigiría muchas uniones encadenadas y lentas, aquí es una consulta natural y rápida.

Conceptos clave

  • Dos modelos de grafo:
    • Grafo de propiedades: nodos y aristas con atributos. Se consulta con Gremlin (Apache TinkerPop) o con openCypher.
    • RDF (Resource Description Framework: modelo de datos en tripletas de la web semántica): tripletas sujeto-predicado-objeto, el estándar de la web semántica. Se consulta con SPARQL.
  • Neptune Database: el motor transaccional. Arquitectura como la de Aurora: una instancia principal, hasta 15 réplicas de lectura y un volumen de clúster con seis copias de los datos en tres AZ (Availability Zone: zona de disponibilidad).
  • Neptune Serverless: la capacidad sube y baja sola según la carga.
  • Base de datos global: regiones secundarias de solo lectura para lecturas locales y recuperación ante desastres.
  • Neptune Analytics: motor en memoria para analizar grafos grandes con algoritmos (centralidad, comunidades, caminos) y búsqueda vectorial; es la base de GraphRAG (generación aumentada por recuperación apoyada en un grafo de conocimiento).
  • Neptune ML (Machine Learning: aprendizaje automático): predicciones sobre el grafo con redes neuronales de grafos, apoyado en SageMaker AI.
  • Flujos (Neptune Streams): registro de los cambios del grafo.
  • Carga masiva: el cargador importa ficheros desde S3 (Simple Storage Service).

Casos de uso típicos

  • Redes sociales: contactos, seguidores, recomendaciones de amigos.
  • Motores de recomendación: "quien compró esto también compró".
  • Detección de fraude: anillos de cuentas que comparten dispositivos, direcciones o tarjetas.
  • Grafos de conocimiento: conectar conceptos, productos y documentos.
  • Resolución de identidades y análisis de dependencias de redes y sistemas.
  • IA (inteligencia artificial) generativa: GraphRAG, para que el modelo responda apoyándose en relaciones explícitas entre los datos.

Cuándo NO usarlo

  • Datos tabulares con transacciones clásicas: Aurora o RDS (Relational Database Service).
  • Acceso simple por clave a gran escala: DynamoDB.
  • Documentos JSON (JavaScript Object Notation: formato de datos en texto) con consultas por campos: DocumentDB.
  • Consultas analíticas de agregación sobre grandes tablas: Redshift.
  • Si las relaciones entre los datos son pocas y poco profundas, un grafo no aporta.

Modelo de precios

En Neptune Database se pagan las instancias por hora (o las unidades de capacidad en Serverless), el almacenamiento, las operaciones de E/S (entrada y salida: lecturas y escrituras) y las copias. Neptune Analytics se cobra por la capacidad de memoria aprovisionada para el grafo.

Seguridad y alta disponibilidad

  • Se despliega dentro de una VPC (Virtual Private Cloud); el acceso se controla con grupos de seguridad y, si se activa, con autenticación de IAM (Identity and Access Management).
  • Cifrado en reposo con KMS (Key Management Service) y en tránsito con TLS (Transport Layer Security: cifrado de las conexiones).
  • Conmutación por error automática a una réplica en otra AZ.
  • Copias continuas en S3 con recuperación a un momento dado.

Trampas de examen

  • "Grafo", "relaciones", "red social", "recomendaciones" o "detección de anillos de fraude": Neptune.
  • "Gremlin", "openCypher" o "SPARQL": Neptune.
  • "Grafo de conocimiento" o "GraphRAG": Neptune (Analytics para la parte analítica y vectorial).
  • "Muchas uniones encadenadas que se vuelven lentas en una base de datos relacional": pista de que hace falta un grafo.
  • No confundir con Fraud Detector, que es un servicio de aprendizaje automático, ni con DocumentDB.
