AWS Serverless Application Repository

En una frase: Publica y reutiliza aplicaciones sin servidor ya empaquetadas por ti o por la comunidad
Categoría: Computación (Compute)
Certificaciones: SAA-C03
Documentación oficial: Documentación de AWS Serverless Application Repository ↗

Qué es

AWS Serverless Application Repository es un repositorio gestionado de aplicaciones sin servidor. Quien publica empaqueta una aplicación (funciones Lambda, API (Application Programming Interface: interfaz para que los programas se comuniquen), tablas, colas…) descrita con una plantilla de AWS SAM (Serverless Application Model: extensión de CloudFormation para aplicaciones sin servidores), y quien consume la busca y la despliega en su cuenta en unos clics, sin clonar repositorios ni compilar nada. Sirve tanto para reutilizar aplicaciones de la comunidad y de AWS como para compartir componentes propios dentro de una empresa.

Conceptos clave

  • Aplicación: una plantilla de SAM con su código y metadatos (nombre, autor, descripción, licencia, fichero de ayuda).
  • Versiones semánticas: cada publicación lleva un número de versión (por ejemplo, 1.2.0), y el consumidor elige cuál desplegar.
  • Tres niveles de visibilidad:
    • Privada: solo la cuenta que la publicó. Es el estado inicial.
    • Compartida de forma privada: con cuentas concretas o con una organización de AWS Organizations.
    • Pública: cualquiera puede encontrarla y desplegarla.
  • Ámbito regional: las aplicaciones privadas y las compartidas de forma privada solo existen en la región donde se publicaron; las públicas están disponibles en todas.
  • Política de la aplicación: una política basada en recursos que define quién puede desplegarla.
  • Despliegue: por debajo es una pila de CloudFormation. Si la aplicación crea roles de IAM (Identity and Access Management) o políticas de recursos, el consumidor debe reconocer esas capacidades al desplegar.
  • Aplicaciones anidadas: una plantilla de SAM puede incluir una aplicación del repositorio como componente, con el recurso AWS::Serverless::Application. La aplicación que anida hereda las restricciones de quien la comparte.
  • Publicación: desde la consola, con la CLI (Command Line Interface: línea de comandos) de SAM (sam publish) o desde un pipeline.

Casos de uso típicos

  • Empezar rápido con un patrón ya resuelto: una función que redimensiona imágenes, un conector, una autenticación.
  • Catálogo interno de componentes sin servidor aprobados, compartido con las cuentas de la empresa.
  • Proveedores que distribuyen integraciones para que sus clientes las desplieguen en su cuenta.
  • Componer aplicaciones a partir de piezas mantenidas por otros equipos (aplicaciones anidadas).

Cuándo NO usarlo

  • Para guardar imágenes de contenedor: ECR (Elastic Container Registry). Para paquetes de software (npm, Maven): CodeArtifact.
  • Para un catálogo de productos de cualquier tipo con restricciones de lanzamiento: Service Catalog.
  • Para software comercial de terceros con facturación: AWS Marketplace.
  • Para construir y desplegar tu propia aplicación: SAM o CDK; el repositorio es para compartirla.

Modelo de precios

El repositorio es gratuito. Se pagan los recursos de AWS que crea cada aplicación al desplegarla (invocaciones de Lambda, peticiones de API Gateway, almacenamiento…).

Seguridad y alta disponibilidad

  • Revisa lo que despliegas: una aplicación pública crea recursos y roles en tu cuenta. Mira la plantilla, los permisos que pide y el autor (AWS marca los autores verificados).
  • El reconocimiento de capacidades evita crear roles de IAM sin que el consumidor lo sepa.
  • La política de la aplicación controla quién puede desplegarla; el acceso de quien publica se controla con IAM.
  • Lo desplegado hereda la disponibilidad de los servicios sin servidor que usa.

Trampas de examen

  • "Compartir una aplicación sin servidor con otras cuentas o con toda la organización": Serverless Application Repository.
  • "Reutilizar una aplicación sin servidor ya hecha" o desplegarla sin escribir código: el repositorio.
  • Las aplicaciones se definen con SAM, no con imágenes de contenedor.
  • Por defecto una aplicación publicada es privada; hay que compartirla expresamente.
  • "Incluir una aplicación del repositorio dentro de otra": aplicaciones anidadas.
