AWS Config

En una frase: Guarda el historial de configuración de tus recursos y evalúa si cumplen tus reglas
Categoría: Administración y gobernanza (Management and Governance)
Certificaciones: SAA-C03 SAP-C02 AIF-C01 CLF-C02
Documentación oficial: Documentación de AWS Config ↗

Qué es

AWS Config registra cómo están configurados tus recursos de AWS, cómo se relacionan entre sí y cómo ha cambiado esa configuración con el tiempo. Sobre ese registro evalúa reglas que dicen si cada recurso cumple o no la configuración deseada. Responde a preguntas como "¿qué buckets no están cifrados?", "¿cómo estaba este grupo de seguridad el martes?" o "¿qué cambió antes de la avería?".

Conceptos clave

  • Grabador de configuración (configuration recorder): detecta los cambios de los tipos de recurso que elijas. Hay que activarlo en cada región y cuenta: Config es un servicio regional.
  • Elemento de configuración (configuration item): la foto de un recurso en un momento: atributos, relaciones y, cuando lo hay, el evento de CloudTrail asociado. La sucesión de elementos forma la línea de tiempo del recurso.
  • Frecuencia de grabación: continua (cada cambio, lo adecuado para seguridad y cumplimiento) o diaria (el último estado de las 24 horas si cambió; más barata para entornos que no son de producción).
  • Canal de entrega: un bucket de S3 (Simple Storage Service) para el historial y las instantáneas de configuración y, opcionalmente, un tema de SNS (Simple Notification Service) para avisar de los cambios.
  • Reglas: gestionadas por AWS (por ejemplo, "los volúmenes de EBS (Elastic Block Store) están cifrados") o personalizadas, escritas con una función Lambda o con el lenguaje de políticas Guard. Se evalúan al cambiar un recurso o de forma periódica, y marcan cada recurso como conforme o no conforme.
  • Corrección (remediation): cada regla puede lanzar un documento de automatización de Systems Manager sobre los recursos no conformes, de forma manual o automática.
  • Paquetes de conformidad (conformance packs): un conjunto de reglas y correcciones que se despliega como una unidad en una cuenta o en toda una organización. Las cuentas miembro no pueden modificarlo. AWS publica plantillas para marcos como PCI DSS (Payment Card Industry Data Security Standard: norma de seguridad para datos de tarjetas) o las buenas prácticas de un servicio.
  • Agregador: reúne en una cuenta los datos de configuración y cumplimiento de varias cuentas y regiones (o de toda la organización). Es de solo lectura.
  • Consultas avanzadas: preguntas con sintaxis SQL (Structured Query Language: lenguaje de consultas de bases de datos relacionales) sobre el estado actual de los recursos, también a través de un agregador.

Casos de uso típicos

  • Auditoría y cumplimiento: demostrar que los recursos cumplen una norma y desde cuándo.
  • Detectar y corregir desviaciones: un grupo de seguridad que abre SSH (Secure Shell: acceso remoto cifrado por terminal) a internet se detecta y se cierra solo.
  • Análisis de cambios: ver qué se modificó en un recurso y en los relacionados antes de un incidente.
  • Inventario de recursos de toda la organización.
  • Gobernanza de cargas de IA (inteligencia artificial): comprobar de forma continua que los recursos que usan (buckets con datos de entrenamiento, puntos de enlace de SageMaker AI) mantienen la configuración exigida.

Cuándo NO usarlo

  • Para impedir una acción: Config detecta después de que ocurra. Para prevenir, una SCP (Service Control Policy: límite de permisos para las cuentas de una organización) de Organizations o una política de IAM (Identity and Access Management).
  • Para saber quién hizo una llamada a la API (Application Programming Interface: interfaz para que los programas se comuniquen): CloudTrail. Config cuenta qué cambió y enlaza con el evento.
  • Para métricas de rendimiento y alarmas: CloudWatch.
  • Para buscar vulnerabilidades de software en instancias o imágenes: Inspector.
  • Para gestionar la configuración dentro del sistema operativo: Systems Manager.

Modelo de precios

Se paga por elemento de configuración grabado (con tarifa distinta para la grabación continua y la diaria), por evaluación de regla y por evaluación de paquete de conformidad. Aparte van S3, SNS y las funciones Lambda de las reglas personalizadas. En cuentas con recursos efímeros (muchos cambios) el coste sube: se controla limitando los tipos de recurso grabados o usando la grabación diaria.

Seguridad y alta disponibilidad

  • Config usa un rol de IAM para leer la configuración de los recursos y escribir en el bucket y en el tema.
  • El bucket de entrega se puede cifrar con una clave de KMS (Key Management Service) y conviene que esté en una cuenta de registros separada.
  • Es regional: para una visión global hay que activarlo en todas las regiones en uso y sumar un agregador.
  • Los recursos globales (como los de IAM) basta con grabarlos en una región para no duplicar elementos.

Trampas de examen

  • "Historial de configuración", "cómo estaba configurado", "evaluar el cumplimiento de forma continua": Config.
  • "Quién hizo el cambio": CloudTrail. Muchos enunciados combinan los dos.
  • "Corregir automáticamente los recursos no conformes": regla de Config con corrección automática mediante un documento de automatización de Systems Manager.
  • "Visión del cumplimiento de todas las cuentas y regiones": agregador.
  • "Desplegar el mismo conjunto de reglas en toda la organización": paquete de conformidad.
  • Config no bloquea nada: si piden impedir, la respuesta es una SCP o IAM.
  • "Avisar cuando un recurso deja de cumplir": cambio de cumplimiento de Config hacia EventBridge o SNS.
