AWS RAM

En una frase: Comparte subredes, licencias y otros recursos con otras cuentas sin duplicarlos
Categoría: Seguridad, identidad y cumplimiento (Security, Identity, and Compliance)
Certificaciones: SAA-C03 SAP-C02 CLF-C02
Documentación oficial: Documentación de AWS RAM ↗

Qué es

AWS Resource Access Manager (AWS RAM) permite compartir recursos que tienes en una cuenta con otras cuentas de AWS, de forma segura y centralizada. El recurso se crea una vez y lo usan varias cuentas, en lugar de duplicarlo en cada una. Es una pieza básica de las arquitecturas con muchas cuentas: una red central que usan todos, un Transit Gateway común, las mismas reglas de licencias.

Conceptos clave

  • Recurso compartido (resource share): la unidad de trabajo. Reúne recursos, principales con quienes se comparten y los permisos que reciben.
  • Con quién se comparte: cuentas concretas, OU (Organizational Unit: unidad organizativa de AWS Organizations) o toda la organización de AWS Organizations y, en algunos tipos de recurso, roles y usuarios de IAM (Identity and Access Management).
  • Dentro de la organización: si se activa el uso compartido con AWS Organizations, la compartición es automática, sin invitaciones. Fuera de ella, la otra cuenta debe aceptar una invitación.
  • Permisos gestionados: definen qué acciones pueden hacer los participantes sobre el recurso; también hay permisos gestionados por el cliente para afinar.
  • Propietario y participante: el propietario conserva el control del recurso (lo modifica y lo borra). El participante lo usa dentro de lo permitido, pero no lo administra.
  • Qué se puede compartir (entre otros): subredes de una VPC (Virtual Private Cloud), Transit Gateway, reglas de Route 53 Resolver, configuraciones de License Manager, clústeres de Aurora, reservas de capacidad y hosts dedicados de EC2 (Elastic Compute Cloud), listas de prefijos, recursos de Network Firewall y de Glue.
  • VPC compartida: la cuenta de red crea la VPC y comparte sus subredes; las demás cuentas lanzan sus instancias en ellas. Cada cuenta ve y gestiona solo sus recursos, pero todas comparten la red.
  • Regional: un recurso compartido incluye recursos de su región (salvo los globales).

Casos de uso típicos

  • Red centralizada: una VPC compartida, gestionada por el equipo de redes, para las cuentas de aplicación.
  • Un único Transit Gateway para toda la organización.
  • Reglas de DNS (Domain Name System: traduce nombres de dominio a direcciones IP) comunes (Route 53 Resolver) para todas las VPC.
  • Compartir las reglas de licencias de License Manager.
  • Aprovechar en otras cuentas una reserva de capacidad de EC2.

Cuándo NO usarlo

  • Para recursos que se comparten con políticas basadas en recursos: buckets de S3 (Simple Storage Service), claves de KMS (Key Management Service), colas de SQS (Simple Queue Service), secretos. Se usa la política del propio recurso.
  • Para dar acceso a una cuenta completa o a acciones genéricas: roles de IAM entre cuentas.
  • Para exponer un servicio a otras VPC sin compartir la red: PrivateLink.
  • Para compartir tablas de un lago de datos con permisos finos: Lake Formation (que usa RAM por debajo).
  • Para compartir una AMI (Amazon Machine Image: plantilla con el sistema operativo para arrancar instancias) o una instantánea: sus propios permisos de lanzamiento o de uso compartido.

Modelo de precios

RAM es gratuito. Los recursos compartidos se pagan como siempre: en general los paga su propietario, y cada participante paga lo que crea sobre ellos (por ejemplo, sus instancias en una subred compartida).

Seguridad y alta disponibilidad

  • Se puede restringir la compartición a la propia organización, para que nadie comparta recursos con cuentas externas.
  • Los participantes no pueden modificar ni borrar el recurso compartido, ni volver a compartirlo.
  • En una VPC compartida, los grupos de seguridad y las instancias siguen siendo de cada cuenta; el aislamiento entre cuentas se mantiene a nivel de recursos.
  • Las operaciones quedan registradas en CloudTrail.

Trampas de examen

  • "Compartir recursos entre cuentas sin duplicarlos": RAM.
  • "Varias cuentas deben desplegar en la misma VPC" o "red centralizada": compartir las subredes con RAM (VPC compartida).
  • "Compartir un Transit Gateway con las cuentas de la organización": RAM.
  • "Sin tener que aceptar invitaciones": activar el uso compartido con AWS Organizations.
  • S3, KMS y SQS se comparten con políticas de recurso, no con RAM.
  • No confundir con la memoria RAM de las instancias.
