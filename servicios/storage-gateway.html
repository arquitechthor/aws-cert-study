AWS Storage Gateway

En una frase: Tus servidores locales usan S3 como disco, recurso NFS o cinta virtual, con caché local
Categoría: Almacenamiento (Storage)
Certificaciones: CLF-C02 SAA-C03 SAP-C02
Documentación oficial: Documentación de AWS Storage Gateway ↗

Qué es

AWS Storage Gateway es un servicio de almacenamiento híbrido. Despliegas una puerta de enlace (una máquina virtual en tu centro de datos o una instancia EC2 (Elastic Compute Cloud)) que presenta a tus aplicaciones protocolos de siempre (recursos compartidos NFS o SMB (Server Message Block: protocolo de ficheros compartidos de Windows), volúmenes iSCSI (Internet Small Computer Systems Interface: discos por bloques a través de la red) o una biblioteca de cintas) mientras los datos se guardan en AWS. Una caché local mantiene los datos usados recientemente para que el acceso sea rápido.

Conceptos clave

  • S3 File Gateway: recursos NFS o SMB cuyos ficheros se guardan como objetos en S3, uno por fichero, accesibles también desde servicios de AWS.
  • Volume Gateway: volúmenes iSCSI para servidores locales. Modo en caché: los datos están en S3 y en local solo lo reciente. Modo almacenado: todos los datos están en local y se copian de forma asíncrona a AWS como instantáneas de EBS (Elastic Block Store).
  • Tape Gateway: biblioteca de cintas virtual (VTL) para el software de copias de seguridad de siempre; las cintas se guardan en S3 y se archivan en S3 Glacier Flexible Retrieval o Deep Archive.
  • FSx File Gateway: caché local de FSx for Windows File Server; ya no admite clientes nuevos (desde el 28/10/2024).
  • Despliegue: máquina virtual (VMware, Hyper-V, KVM (Kernel-based Virtual Machine: hipervisor de Linux)) o instancia EC2.

Casos de uso típicos

  • Sustituir cintas físicas por cintas virtuales en AWS sin cambiar el software de copias.
  • Ampliar la capacidad de un servidor de ficheros local con S3, manteniendo NFS o SMB.
  • Llevar datos generados en local a S3 para analizarlos en AWS.
  • Copias de seguridad de volúmenes locales como instantáneas de EBS, recuperables en EC2.

Cuándo NO usarlo

  • Para una migración puntual de datos: DataSync.
  • Si todas las aplicaciones ya están en AWS: usa directamente S3, EFS (Elastic File System) o FSx.
  • Para intercambiar ficheros con terceros por SFTP (SSH File Transfer Protocol: transferencia de ficheros sobre SSH): Transfer Family.

Modelo de precios

Se paga el almacenamiento usado en AWS (por tipo: S3, volúmenes, cintas virtuales y archivadas), las peticiones y la transferencia de datos de salida desde AWS.

Seguridad y alta disponibilidad

  • Cifrado en tránsito con TLS (Transport Layer Security: cifrado de las conexiones) y en reposo con KMS (Key Management Service).
  • Integración con Active Directory para los recursos SMB.
  • Puntos de enlace de VPC (Virtual Private Cloud) para que el tráfico no pase por internet.
  • La caché local no es la copia principal en los modos en caché: si se pierde, los datos siguen en AWS.
  • Alta disponibilidad de la máquina virtual con VMware HA (High Availability: alta disponibilidad).

Trampas de examen

  • "Sustituir cintas sin cambiar el software de copias": Tape Gateway.
  • "NFS o SMB en local, ficheros en S3": S3 File Gateway.
  • "iSCSI con todos los datos en local y copia en AWS": Volume Gateway almacenado.
  • "iSCSI con los datos en AWS y caché local": Volume Gateway en caché.
  • "Acceso de baja latencia desde la oficina a datos en AWS": Storage Gateway, por la caché.
  • "Migración puntual": DataSync, no Storage Gateway.
