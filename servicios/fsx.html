Amazon FSx

Amazon FSx (for all types)

En una frase: Sistemas de ficheros gestionados de Windows, Lustre, NetApp ONTAP u OpenZFS
Categoría: Almacenamiento (Storage)
Certificaciones: CLF-C02 SAA-C03 SAP-C02
Documentación oficial: Documentación de Amazon FSx ↗

Qué es

Amazon FSx ofrece sistemas de ficheros gestionados construidos sobre tecnologías conocidas, para cuando necesitas sus características concretas. Hay cuatro: Windows File Server, Lustre, NetApp ONTAP y OpenZFS. AWS gestiona el hardware, los parches, las copias y la conmutación por error; tú eliges capacidad, rendimiento y despliegue.

Conceptos clave

  • FSx for Windows File Server: recursos compartidos SMB (Server Message Block: protocolo de ficheros compartidos de Windows) nativos de Windows, integrado con Active Directory (permisos NTFS (New Technology File System: sistema de ficheros de Windows, con permisos por usuario)), DFS (Distributed File System: agrupa recursos compartidos de Windows bajo un mismo espacio de nombres), instantáneas que los usuarios pueden restaurar y deduplicación.
  • FSx for Lustre: sistema de ficheros paralelo para HPC (High Performance Computing: cómputo de alto rendimiento), aprendizaje automático y proceso de medios, con cientos de GB/s. Se puede enlazar con un bucket de S3 (Simple Storage Service) para leer y escribir sus objetos como ficheros. Despliegues scratch (temporal, sin replicación, más barato) o persistente.
  • FSx for NetApp ONTAP: NFS (Network File System: protocolo para compartir ficheros en red), SMB e iSCSI (y NVMe (Non-Volatile Memory Express: protocolo de acceso rápido a discos SSD) sobre TCP (Transmission Control Protocol: protocolo de transporte fiable)) a la vez, con las funciones de ONTAP: instantáneas, clones, SnapMirror para replicar y nivel de capacidad automático para datos fríos. Ideal si ya usas NetApp en local.
  • FSx for OpenZFS: NFS con latencias muy bajas, instantáneas y clones; para migrar sistemas ZFS (Zettabyte File System: sistema de ficheros con instantáneas y clones) o Linux.
  • Despliegue Single-AZ o Multi-AZ: Multi-AZ en Windows, ONTAP y OpenZFS (SLA (Service Level Agreement: compromiso de disponibilidad) del 99,99 %); Lustre es solo de una AZ (Availability Zone: zona de disponibilidad).
  • Copias de seguridad: automáticas e incrementales, integradas con AWS Backup.

Casos de uso típicos

  • Recursos compartidos de Windows para aplicaciones .NET, SQL Server o carpetas de usuario (Windows File Server).
  • Entrenamiento de modelos o simulaciones que leen datos de S3 a gran velocidad (Lustre).
  • Migrar cabinas NetApp sin cambiar herramientas ni procesos (ONTAP).
  • Cargas Linux que necesitan NFS de muy baja latencia (OpenZFS).

Cuándo NO usarlo

  • Para un NFS sencillo para Linux que crezca y se pague por uso, sin elegir capacidad: EFS (Elastic File System).
  • Para almacenamiento de objetos: S3.
  • Para un disco de una sola instancia: EBS (Elastic Block Store).

Comparativa con servicios parecidos

NecesidadElige
SMB con Active Directory para WindowsFSx for Windows File Server

Multiprotocolo (NFS + SMB + iSCSI) o venir de NetAppFSx for NetApp ONTAP
NFS de muy baja latencia, venir de ZFSFSx for OpenZFS
NFS elástico sin gestionar capacidad, para LinuxEFS

Modelo de precios

Se paga la capacidad de almacenamiento aprovisionada (o usada, en los niveles elásticos), la capacidad de rendimiento elegida, las IOPS (Input/Output Operations Per Second: operaciones de disco por segundo) aprovisionadas adicionales y las copias de seguridad. Multi-AZ cuesta más que Single-AZ.

Seguridad y alta disponibilidad

  • Cifrado en reposo con KMS (Key Management Service) (siempre activo) y en tránsito según el protocolo.
  • Acceso de red dentro de tu VPC (Virtual Private Cloud) con grupos de seguridad.
  • Permisos de ficheros nativos: ACL (Access Control List: lista de control de acceso) de NTFS con Active Directory, o permisos POSIX (Portable Operating System Interface: estándar de ficheros y permisos tipo Unix).
  • Multi-AZ con conmutación automática a la AZ de reserva.
  • Replicación entre regiones con SnapMirror (ONTAP) o copias de seguridad entre regiones.

Trampas de examen

  • "SMB", "Windows", "Active Directory", "NTFS": FSx for Windows File Server, no EFS.
  • "HPC", "alto rendimiento", "procesar datos de S3": FSx for Lustre.
  • "Datos temporales de un trabajo HPC, lo más barato": Lustre scratch.
  • "NFS y SMB a la vez" o "NetApp": FSx for NetApp ONTAP.
  • "Linux, NFS, elástico, sin gestionar capacidad": EFS.
  • "Alta disponibilidad para un recurso compartido de Windows": FSx for Windows Multi-AZ.
