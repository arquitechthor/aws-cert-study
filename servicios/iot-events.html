AWS IoT Events

En una frase: Detecta patrones en datos de sensores y dispara alertas o acciones al cambiar de estado
Categoría: Internet de las cosas (IoT) (Internet of Things (IoT))
Certificaciones: SAP-C02
Documentación oficial: Documentación de AWS IoT Events ↗
Aviso: AWS IoT Events ya no está disponible. AWS anunció su fin de soporte en mayo de 2025 y el servicio se retiró en 2026: su web redirige a AWS IoT (Internet of Things: internet de las cosas: dispositivos conectados) y su documentación ya no está publicada. Hoy se construye la misma lógica con reglas de IoT Core, Lambda o Step Functions (guardando el estado, por ejemplo, en DynamoDB), con alarmas de IoT SiteWise o con Managed Service for Apache Flink. Esta guía se mantiene porque el servicio aparece en la guía de SAP-C02.

Qué es

AWS IoT Events servía para detectar situaciones a partir de los datos de sensores y aplicaciones y reaccionar a ellas. Se definían modelos de detector: máquinas de estados (por ejemplo, normal → sobrecalentado → avería) con condiciones de transición y acciones como enviar un SNS (Simple Notification Service) o invocar una Lambda. Ya no está disponible.

Conceptos clave

  • Entradas: datos que llegaban de IoT Core, IoT SiteWise u otras fuentes.
  • Modelo de detector: estados, transiciones, temporizadores y variables.
  • Instancias de detector: una por equipo, cada una con su estado.
  • Acciones: SNS, Lambda, SQS (Simple Queue Service), DynamoDB, IoT Core, etc.
  • Alternativas actuales: reglas de IoT Core con Lambda o Step Functions y estado en DynamoDB; alarmas de IoT SiteWise; procesamiento con estado en Managed Service for Apache Flink.

Casos de uso típicos

  • Avisar cuando una máquina supera una temperatura durante más de cinco minutos.
  • Detectar secuencias de eventos (por ejemplo, una puerta abierta sin alarma desactivada).

Cuándo NO usarlo

  • Ya no se puede usar: elige una de las alternativas actuales.
  • Para alarmas sencillas sobre métricas: CloudWatch.

Modelo de precios

Se cobraba por mensaje evaluado por los detectores.

Seguridad y alta disponibilidad

  • Era un servicio gestionado con acceso por IAM (Identity and Access Management); las alternativas mantienen ese modelo.

Trampas de examen

  • "Máquina de estados sobre datos de sensores" o "detectar un patrón y avisar": en la guía, IoT Events.
  • "Hoy": alarmas de SiteWise, reglas de IoT Core con Lambda o Step Functions, o Flink.
