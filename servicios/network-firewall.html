AWS Network Firewall

En una frase: Cortafuegos gestionado con inspección de paquetes e IPS (Intrusion Prevention System: sistema que detecta y bloquea intrusiones en la red) para el tráfico de tu VPC (Virtual Private Cloud)
Categoría: Seguridad, identidad y cumplimiento (Security, Identity, and Compliance)
Certificaciones: SAA-C03 SAP-C02
Documentación oficial: Documentación de AWS Network Firewall ↗

Qué es

AWS Network Firewall es un cortafuegos de red gestionado para tus VPC. Inspecciona el tráfico que entra, sale o circula entre redes, y lo permite, lo bloquea o avisa según tus reglas. Va más allá de los grupos de seguridad y las ACL (Access Control List: lista de control de acceso) de red: hace inspección profunda de paquetes, filtra por nombre de dominio y actúa como sistema de prevención de intrusiones. AWS gestiona la infraestructura, que escala sola con el tráfico.

Conceptos clave

  • Cortafuegos y punto de enlace: el cortafuegos se despliega en una subred dedicada por cada AZ (Availability Zone: zona de disponibilidad). Para que inspeccione, hay que dirigir el tráfico hacia su punto de enlace con las tablas de rutas de la VPC.
  • Política de cortafuegos: el conjunto de grupos de reglas y acciones por defecto; se puede compartir entre varios cortafuegos.
  • Reglas sin estado: evalúan cada paquete por separado (IP (Internet Protocol: dirección de red), puerto, protocolo), como una ACL de red, con prioridad numérica.
  • Reglas con estado: evalúan el paquete dentro de su conexión. Usan el motor de Suricata, de código abierto. Tres formas de escribirlas: reglas estándar sencillas, listas de dominios y reglas en sintaxis de Suricata.
  • Filtrado por dominio: permite o bloquea el tráfico saliente por nombre de dominio, tanto HTTP (HyperText Transfer Protocol: protocolo de la web) como HTTPS (lee el nombre en la negociación de TLS (Transport Layer Security: cifrado de las conexiones), sin descifrar).
  • Inspección de TLS: opcionalmente descifra el tráfico para inspeccionar su contenido y lo vuelve a cifrar.
  • Grupos de reglas gestionados: mantenidos por AWS (dominios e IP maliciosos, firmas de amenazas) o por socios, para no escribirlo todo a mano.
  • Registros: de alertas y de flujos, hacia S3 (Simple Storage Service), CloudWatch Logs o Data Firehose.
  • Modelos de despliegue: distribuido (un cortafuegos en cada VPC) o centralizado, con una VPC de inspección por la que pasa todo el tráfico a través de Transit Gateway.

Casos de uso típicos

  • Filtrar la salida a internet: las cargas solo pueden llegar a una lista de dominios aprobados.
  • Inspeccionar el tráfico entre VPC o hacia el centro de datos (Direct Connect, VPN (Virtual Private Network: red privada virtual)).
  • Prevención de intrusiones con firmas conocidas.
  • Cumplir requisitos normativos de inspección y segmentación de red.

Cuándo NO usarlo

  • Para control básico por IP y puerto: grupos de seguridad (por recurso) y ACL de red (por subred), que son gratuitos.
  • Para ataques a aplicaciones web (inyección SQL (Structured Query Language: lenguaje de consultas de bases de datos relacionales), cross-site scripting): WAF (Web Application Firewall).
  • Para DDoS (Distributed Denial of Service: ataque que satura un servicio desde muchos orígenes): Shield.
  • Para filtrar solo las consultas de DNS (Domain Name System: traduce nombres de dominio a direcciones IP): DNS Firewall de Route 53 Resolver.
  • Para detectar amenazas a partir de los registros, sin estar en el camino del tráfico: GuardDuty.

Modelo de precios

Se paga por hora de cada punto de enlace del cortafuegos y por gigabyte de tráfico procesado. La inspección de TLS y algunos grupos de reglas gestionados tienen cargos adicionales.

Seguridad y alta disponibilidad

  • Un punto de enlace por AZ: para alta disponibilidad, despliega el cortafuegos en todas las AZ que uses y mantén el tráfico de cada AZ en su propio punto de enlace.
  • El enrutamiento debe ser simétrico: la ida y la vuelta de una conexión tienen que pasar por el mismo cortafuegos.
  • Con Firewall Manager se despliega y se mantiene de forma uniforme en toda la organización.
  • Escala automáticamente con el tráfico.

Trampas de examen

  • "Permitir la salida solo a determinados dominios": Network Firewall con una lista de dominios.
  • "Inspección profunda de paquetes", "prevención de intrusiones" o "reglas de Suricata": Network Firewall.
  • "Inspeccionar de forma centralizada el tráfico entre VPC": VPC de inspección con Network Firewall y Transit Gateway.
  • "Inyección SQL en una aplicación web": WAF, no Network Firewall.
  • "Usar un cortafuegos de un proveedor externo": Gateway Load Balancer.
  • El tráfico no se inspecciona solo: hay que modificar las tablas de rutas.
