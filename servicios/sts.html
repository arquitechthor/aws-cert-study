AWS STS

En una frase: Emite credenciales temporales para asumir roles o federar identidades externas
Categoría: Seguridad, identidad y cumplimiento (Security, Identity, and Compliance)
Certificaciones: SAP-C02 DVA-C02
Documentación oficial: Documentación de AWS STS ↗

Qué es

AWS Security Token Service (AWS STS) es el servicio que emite credenciales temporales de seguridad. Cada vez que algo o alguien asume un rol de IAM (Identity and Access Management), es STS quien entrega las credenciales: un identificador de clave de acceso, una clave secreta y un token de sesión, con fecha de caducidad. Es la base de casi todo el acceso moderno a AWS: roles de servicio, acceso entre cuentas, federación e inicio de sesión único. No tiene consola propia: se usa a través de IAM, la CLI (Command Line Interface: línea de comandos) o los SDK (Software Development Kit: bibliotecas para programar contra AWS).

Conceptos clave

  • Por qué temporales: caducan solas, no se guardan con el usuario y no hay que rotarlas ni revocarlas a mano.
  • Operaciones principales:
    • AssumeRole: asumir un rol en la misma cuenta o en otra. Es la base del acceso entre cuentas.
    • AssumeRoleWithWebIdentity: federación con un proveedor OIDC (Google, GitHub Actions, roles de IAM para cuentas de servicio de EKS (Elastic Kubernetes Service)).
    • AssumeRoleWithSAML: federación con un proveedor SAML (Security Assertion Markup Language: estándar de inicio de sesión federado) 2.0 corporativo.
    • GetSessionToken: credenciales temporales para un usuario de IAM, normalmente para cumplir una condición de MFA (Multi-Factor Authentication: inicio de sesión con un segundo factor).
    • GetFederationToken: credenciales para un usuario federado mediante un intermediario propio.
    • GetCallerIdentity: devuelve quién eres (cuenta, ARN (Amazon Resource Name: identificador único de un recurso de AWS)); útil para comprobar qué identidad se está usando.
    • DecodeAuthorizationMessage: descifra el mensaje codificado de un error de autorización.
  • Política de confianza del rol: indica quién puede asumirlo. Hacen falta las dos partes: que la política de confianza lo permita y que quien llama tenga permiso para sts:AssumeRole.
  • Duración de la sesión: por defecto una hora; configurable desde 15 minutos hasta el máximo del rol (12 horas como mucho). Al encadenar roles, el máximo es una hora.
  • Identificador externo (external ID): valor que un tercero debe presentar al asumir un rol en tu cuenta; evita el problema del suplente confundido.
  • Políticas de sesión: restringen aún más los permisos de una sesión concreta; nunca los amplían.
  • Etiquetas de sesión e identidad de origen: atributos que acompañan a la sesión, para control de acceso por atributos y para auditar quién actuó.
  • Puntos de enlace regionales: recomendados frente al global por latencia y resiliencia.

Casos de uso típicos

  • Acceso entre cuentas: un rol en la cuenta de destino que asumen identidades de otra cuenta.
  • Roles de servicio: EC2 (Elastic Compute Cloud), Lambda y ECS (Elastic Container Service) obtienen sus credenciales así, sin que lo veas.
  • Federación: empleados con el directorio corporativo, pipelines de CI/CD (Continuous Integration / Continuous Delivery: integración y entrega continuas) con OIDC, usuarios de aplicaciones a través de Cognito.
  • Acceso de terceros (proveedores de software) a tu cuenta, con identificador externo.
  • Elevar permisos de forma temporal, con MFA.

Cuándo NO usarlo

  • Para el acceso de la plantilla a muchas cuentas, no montes la federación a mano: IAM Identity Center, que usa STS por debajo.
  • Para los usuarios de una aplicación móvil o web: Cognito, que canjea sus tokens por credenciales temporales.
  • Para guardar contraseñas o claves de API (Application Programming Interface: interfaz para que los programas se comuniquen) de terceros: Secrets Manager.
  • STS no define permisos: los permisos son los del rol asumido.

Modelo de precios

STS es gratuito. Solo se pagan los servicios a los que se accede con las credenciales.

Seguridad y alta disponibilidad

  • Las credenciales temporales no se pueden revocar una a una, pero sí invalidar todas las sesiones de un rol anteriores a un momento, con una política de denegación.
  • Los permisos efectivos son la intersección de la política del rol, la política de sesión, el límite de permisos y las SCP (Service Control Policy: límite de permisos para las cuentas de una organización).
  • Cada llamada queda en CloudTrail, con el nombre de la sesión: ponle uno que identifique a quien actúa.
  • Las credenciales se pueden reutilizar mientras sean válidas, lo que evita llamadas innecesarias a STS.
  • Usar los puntos de enlace regionales reduce la dependencia de una sola región.

Trampas de examen

  • "Credenciales temporales": STS.
  • "Acceso entre cuentas": rol en la cuenta de destino y sts:AssumeRole.
  • "Un tercero accede a nuestra cuenta": rol con identificador externo.
  • "Federar con un proveedor OIDC": AssumeRoleWithWebIdentity. "Con SAML": AssumeRoleWithSAML.
  • "La CLI con MFA": GetSessionToken.
  • "Error de acceso denegado al asumir un rol": revisa la política de confianza del rol y el permiso sts:AssumeRole de quien llama.
  • "Mensaje de error de autorización codificado": DecodeAuthorizationMessage.
