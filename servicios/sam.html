AWS SAM

AWS Serverless Application Model (AWS SAM)

En una frase: Plantillas abreviadas para definir, probar en local y desplegar aplicaciones sin servidor
Categoría: Herramientas para desarrolladores (Developer Tools)
Certificaciones: DVA-C03
Documentación oficial: Documentación de AWS SAM ↗

Qué es

AWS SAM (Serverless Application Model: extensión de CloudFormation para aplicaciones sin servidores) es un marco de código abierto para construir aplicaciones sin servidor como infraestructura como código. Tiene dos partes: las plantillas SAM, una extensión de CloudFormation con una sintaxis abreviada para funciones Lambda, APIs, tablas y máquinas de estado, y la herramienta de línea de comandos sam, que compila, prueba en local, sincroniza y despliega. Al desplegar, SAM transforma la plantilla en recursos normales de CloudFormation.

Conceptos clave

  • Transformación: la línea Transform: AWS::Serverless-2016-10-31 convierte una plantilla de CloudFormation en una plantilla SAM. En la misma plantilla pueden convivir recursos SAM y recursos normales de CloudFormation.
  • Tipos de recurso SAM: AWS::Serverless::Function, Api, HttpApi, SimpleTable, LayerVersion, StateMachine o Application, entre otros. Una función con su evento Api genera la función, su rol, la API (Application Programming Interface: interfaz para que los programas se comuniquen) y los permisos entre ellas.
  • Sección Globals: propiedades comunes (entorno de ejecución, tiempo de espera, memoria, variables) para todas las funciones o APIs.
  • Permisos: Policies con plantillas de políticas como DynamoDBCrudPolicy o S3ReadPolicy acotadas a un recurso, o un Role propio (no los dos a la vez). Los conectores describen la relación entre recursos y SAM genera los permisos de IAM (Identity and Access Management).
  • Comandos de sam: sam init (proyecto), sam build (dependencias y artefactos), sam local invoke, start-api, start-lambda y generate-event (pruebas en local con contenedores de Docker), sam deploy (con --guided guarda las respuestas en samconfig.toml), sam sync (sincroniza cambios con la nube mientras desarrollas), sam logs y sam pipeline.
  • Despliegues graduales: AutoPublishAlias publica una versión nueva y mueve un alias; DeploymentPreference usa CodeDeploy para desviar el tráfico de forma canaria, lineal o de golpe, con alarmas que revierten y funciones de comprobación antes y después (PreTraffic y PostTraffic). Sin AutoPublishAlias, DeploymentPreference da error.

Casos de uso típicos

  • Definir con pocas líneas una API con API Gateway, funciones Lambda y una tabla de DynamoDB.
  • Probar y depurar funciones en el portátil antes de desplegar, con eventos de prueba generados.
  • Canalizaciones de CI/CD (Continuous Integration / Continuous Delivery: integración y entrega continuas) para aplicaciones sin servidor con despliegues canarios y reversión automática.
  • Pasar a código funciones y APIs creadas a mano en la consola.
  • Usar las pruebas locales de SAM con proyectos de CDK o Terraform.

Cuándo NO usarlo

  • Si prefieres definir la infraestructura con un lenguaje de programación (bucles, clases, abstracciones): CDK.
  • Para infraestructura que no es sin servidor (redes, flotas de EC2 (Elastic Compute Cloud)): CloudFormation o CDK directamente (SAM no aporta sus atajos ahí).
  • Para desplegar una aplicación web o móvil de frontend con su alojamiento: Amplify.

Modelo de precios

SAM es gratuito: se pagan los recursos que despliega (Lambda, API Gateway, DynamoDB…) y el depósito de S3 (Simple Storage Service) o el repositorio de ECR (Elastic Container Registry) donde sube los artefactos.

Seguridad y alta disponibilidad

  • Plantillas de políticas y conectores para dar a cada función solo los permisos que necesita.
  • PermissionsBoundary para limitar los roles que crea la plantilla.
  • Secretos fuera del código: referencias dinámicas a Secrets Manager o Parameter Store de Systems Manager.
  • Despliegues graduales con reversión automática por alarmas de CloudWatch.
  • sam sync es para entornos de desarrollo: se salta los conjuntos de cambios, así que no se usa en producción.

Trampas de examen

  • "Probar en local la función detrás de un punto de enlace HTTP (HyperText Transfer Protocol: protocolo de la web)": sam local start-api.
  • "Enviar el 10 % del tráfico a la versión nueva y revertir si salta una alarma": AutoPublishAlias + DeploymentPreference (Canary10Percent10Minutes) con Alarms.
  • "Qué identifica una plantilla SAM": la línea Transform.
  • "Permisos mínimos sobre una tabla con poco código": plantilla de política DynamoDBCrudPolicy con el nombre de la tabla.
  • "La misma configuración para todas las funciones": sección Globals.
  • "Ver los cambios en la nube en segundos mientras desarrollo": sam sync --watch.
